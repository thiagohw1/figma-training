Fundação visual e tokens do produto

Antes de desenhar a primeira tela, construímos a linguagem visual do produto: um conjunto coerente de cores, tipografia, espaçamentos e efeitos que garante consistência de ponta a ponta — e que escala sem caos.

⏱️ Leitura: ~25 min 🎯 Nível: Projeto prático 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Criar uma paleta de cores completa usando Variables do Figma com dois modos (Light e Dark);
  • Definir uma escala tipográfica para web com Text Styles bem nomeadas;
  • Estabelecer tokens de espaçamento em múltiplos de 4 px com Variables numéricas;
  • Criar Border Radius, Shadow e Opacity como tokens reutilizáveis;
  • Montar a página de fundação visual como documentação viva do Design System do TaskFlow.

O que são design tokens?

Design tokens são as unidades atômicas de um Design System: valores nomeados (cores, tamanhos, espaçamentos) que encapsulam as decisões de design e podem ser referenciados em qualquer lugar do sistema. Em vez de usar #6c4cf1 diretamente em 200 componentes, você define uma variável chamada color/brand/primary e usa essa referência em todo o lugar. Quando a cor mudar, muda em um lugar só.

Variables vs. Styles no Figma

Variables (novo desde 2023) armazenam valores primitivos (cores, números, strings, booleans) com suporte a múltiplos modos. Styles armazenam propriedades compostas (texto com fonte + tamanho + peso, sombra, grid). Use Variables para tokens de cor e espaçamento; use Styles para tipografia e sombras compostas.

Paleta de cores do TaskFlow

O TaskFlow é um produto profissional para times. A paleta precisa transmitir confiança, clareza e eficiência — com um acento de cor vibrante que diferencia a marca, mas sem cansar os olhos em longas sessões de trabalho.

Passo a passo: criando as Variables de cor

  1. Abra o painel de Variables. Na página Fundação Visual, vá em Assets (painel esquerdo) → Variables, ou use o menu Edit → Variables. Clique em + Collection e nomeie Primitives.
  2. Adicione dois modos. Na collection Primitives, clique em + Mode. Crie Light e Dark. Renomeie o modo padrão para "Light".
  3. Crie o grupo Brand. Clique em + Variable → Color. Nomeie a variável brand/primary. Defina o valor Light como #6c4cf1 e o valor Dark como #9b81ff (mais claro para contraste no fundo escuro). Repita para brand/secondary (#b0367a / #e06bab).
  4. Crie os neutrals. Crie variáveis neutral/50 até neutral/900. No modo Light, use tons claros; no modo Dark, inverta a escala (o que era 50 vira 900 e vice-versa, pois backgrounds claros viram escuros).
  5. Crie uma segunda collection: Tokens. Esta collection vai usar os primitivos como referência — são as variáveis semânticas que os componentes usam. Crie color/text/default e aponte para neutral/900 no Light e neutral/50 no Dark. Isso é o aliasing de variáveis.
  6. Aplique as variáveis a um retângulo de teste. Desenhe um retângulo (R), selecione o fill e clique no ícone de biblioteca para usar uma variable. Troque o modo no painel de Variables e observe a cor mudar instantaneamente — isso é o Dark Mode funcional.

Passo a passo: criando Text Styles

  1. Crie um frame de tipografia. Na página Fundação Visual, crie um frame (F) chamado "Tipografia". Adicione textos de exemplo para cada nível da escala com o texto real de um produto ("Projetos ativos", "Dashboard de métricas", etc.).
  2. Configure e salve o primeiro estilo. Selecione o texto do display (32 px / 800). No painel direito, em Text, defina fonte: Inter, tamanho 32, weight Extra Bold (800), line-height 120%. Clique nos 4 pontos ao lado de Text e escolha Create style. Nomeie Display/32 ExtraBold.
  3. Repita para todos os níveis. Crie um Text Style para cada linha da tabela acima. Use a nomenclatura Categoria/Tamanho Peso — ex.: Body/14 Regular, Heading/24 Bold.

Border Radius, Sombras e Ícones

Border Radius

Crie Variables numéricas para raio de borda:

  • radius/sm → 4 px (chips, badges, separadores)
  • radius/md → 8 px (botões, inputs, cards pequenos)
  • radius/lg → 12 px (cards padrão, dropdowns)
  • radius/xl → 16 px (modais, painéis)
  • radius/pill → 999 px (tags arredondadas, avatars com pill)

Sombras (Effect Styles)

Crie três Effect Styles de sombra para diferentes níveis de elevação:

  • Shadow/sm: 0 1px 3px rgba(0,0,0,.08) — cards, inputs no estado default
  • Shadow/md: 0 4px 12px rgba(0,0,0,.10) — dropdowns, popovers
  • Shadow/lg: 0 12px 32px rgba(0,0,0,.14) — modais, drawers

Ícones

Para o TaskFlow, use ícones do conjunto Lucide Icons (disponível como plugin no Figma: Icons8 – Icons & Illustrations ou importe o arquivo de ícones Lucide da comunidade). São ícones de linha com traço de 1.5 px, ideais para interfaces de produto — leves, legíveis e consistentes.

Densiddade adequada para web/desktop

Diferente de mobile (onde tapping targets precisam de no mínimo 44 px), em desktop os alvos de clique podem ser menores: 32–36 px para ações secundárias, 40 px para botões principais. Isso permite mais informação na tela sem a interface parecer espaçosa demais para o contexto de trabalho.

Nunca use cores brutas nos componentes

A regra de ouro: componentes sempre referenciam tokens semânticos (color/text/default), nunca valores primitivos diretos (#1a1d23). Se você usar o valor bruto, quando o Dark Mode for ativado, o componente não vai responder. Tokens são a camada de abstração que torna o tema possível.

Exemplo de uso real

O Figma usa exatamente esse sistema de tokens internamente (é como eles constroem o próprio Figma). Empresas como Airbnb (DLS), IBM (Carbon), Atlassian (Atlaskit) e Shopify (Polaris) publicaram seus sistemas de tokens publicamente — todos seguem a mesma arquitetura de primitivos + tokens semânticos que você está aprendendo aqui.

Resumo

  • Design tokens são os valores nomeados que compõem o Visual Foundation — quando um valor muda, muda em todo o sistema.
  • Use Variables para cores (com Light e Dark mode) e espaçamentos numéricos; use Styles para tipografia e sombras.
  • A paleta do TaskFlow tem 4 camadas: Brand, Neutral, Semantic e Surface.
  • A escala tipográfica para web vai de 32 px (display) a 11 px (overline), com Inter como fonte base.
  • Espaçamentos em múltiplos de 4 px garantem alinhamento preciso e consistência com grids de 8 px.
  • Componentes sempre referenciam tokens semânticos, nunca valores primitivos diretamente.

Monte a página de fundação visual

  2. Defina todas as variáveis de cor Brand (primary, secondary, soft) com valores para os dois modos.

🏆 Desafio

Tokens semânticos com aliasing

Crie uma segunda collection chamada Tokens com variáveis semânticas que fazem referência (aliasing) às variáveis primitivas — por exemplo, color/background/default aponta para neutral/50 no Light e neutral/900 no Dark. Crie pelo menos 12 tokens semânticos cobrindo: background, surface, border, text default, text muted, brand, success, warning, danger e info. Depois aplique esses tokens a um card de KPI simples e teste trocando os modos.

QuizTeste seu conhecimento

1. Qual é a diferença principal entre Variables e Styles no Figma?

  • Variables são para cores e Styles são para espaçamentos — não há outra diferença
  • Variables suportam múltiplos modos (Light/Dark) e armazenam valores primitivos; Styles armazenam propriedades compostas como tipografia e sombras
  • Styles são mais modernos e substituíram as Variables completamente
  • Variables só funcionam em Components; Styles funcionam em qualquer layer
Variables têm suporte a modos (fundamental para temas), enquanto Styles armazenam composições de propriedades (fonte + tamanho + peso, por exemplo). Use os dois juntos.

2. Por que usamos múltiplos de 4 px no sistema de espaçamento?

  • Porque o Figma só aceita valores divisíveis por 4
  • Porque 4 px é o menor espaço visível em tela
  • Porque 4 divide bem em diferentes densidades e alinha ao grid de 8 px — padrão de iOS, Material e Tailwind
  • Porque o CSS Box Model usa 4 px como unidade base
A base de 4 px é ubíqua no design de UI porque se alinha ao grid de 8 px e divide consistentemente em resoluções e densidades de pixel variadas. Não é uma limitação técnica, é uma convenção de design.

3. Por que componentes devem referenciar tokens semânticos em vez de valores primitivos?

  • Para que o Dark Mode e temas funcionem: ao trocar o modo, os tokens semânticos mudam de valor e todos os componentes se atualizam automaticamente
  • Porque tokens semânticos carregam mais rápido no handoff com desenvolvedores
  • É apenas uma preferência organizacional — não tem impacto técnico
  • Porque o Figma bloqueia valores primitivos em componentes publicados
A função dos tokens semânticos é desacoplar o componente do valor concreto. color/text/default pode valer #1a1d23 no Light e #e8eaee no Dark — o componente não precisa saber qual é qual, só precisa da referência semântica.
