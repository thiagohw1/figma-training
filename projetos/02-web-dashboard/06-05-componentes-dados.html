Componentes de dados

Um dashboard SaaS vive e morre pela qualidade dos seus componentes de dados. Tabelas bem construídas, cards de KPI elegantes, gráficos compreensíveis e um Kanban fluido — nesta lição você vai construir cada um deles como Components profissionais com Variants.

⏱️ Leitura: ~30 min 🎯 Nível: Projeto prático 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Construir uma data table com header, linhas, estados de hover e seleção, e indicadores de sort;
  • Criar cards de KPI/métrica com variações de tendência (alta, baixa, neutro);
  • Desenhar mocks realistas de gráficos de barra e linha para o dashboard;
  • Montar o board Kanban com colunas e cards arrastáveis (interativos no protótipo);
  • Criar Components de apoio: filtros, badges, avatars e tags com Variants.

Card de KPI / Métrica

O card de KPI é o componente mais visto pelos gestores — ele precisa comunicar um número e sua tendência em menos de 2 segundos. A estrutura é simples mas precisa ser flexível: título, valor principal, delta (variação percentual) e sparkline opcional.

Estrutura do KPI Card

  1. Crie o frame base do card. Frame de 240×120 px, Auto Layout vertical, padding 20, gap 8, border-radius 12, fill color/surface/card, Shadow/sm.
  2. Adicione o header do card. Auto Layout horizontal, gap Auto: label à esquerda (Body/13 Regular, color/text/muted) e ícone de contexto à direita (16×16 px, cor muted).
  3. Adicione o valor principal. Texto com estilo Display/32 ExtraBold, cor color/text/default. Este é o número em destaque.
  4. Adicione o delta. Auto Layout horizontal, gap 4: ícone de seta (12×12 px) + texto percentual (Caption/12). Crie 3 Variants de Trend: up (ícone ↑, cor success), down (ícone ↓, cor danger), neutral (ícone →, cor muted).
  5. Salve como Component com Variants. Propriedades: Trend (up/down/neutral) e Has sparkline (true/false). Nomeie KPICard.

Data Table

A tabela de dados é o componente mais complexo de um dashboard — ela precisa lidar com ordenação, seleção, overflow e muitos estados diferentes. A chave é decompô-la em sub-componentes.

Componentes da tabela

  • TableCell: célula base com Auto Layout, padding 12×14, alinhamento configurável. Variants: text, number, badge, avatar+text, actions.
  • TableHeaderCell: como o TableCell mas com fundo surface-2, texto Bold, e ícone de sort (↕ / ↑ / ↓). Variants de Sort: none, asc, desc.
  • TableRow: linha com Auto Layout horizontal, usando instâncias de TableCell. Variants de State: default, hover, selected.
  • Table: container com header row + N linhas de dados.
  1. Crie o TableHeaderCell. Frame 160×44 px, Auto Layout horizontal, padding 12, gap Auto. Texto "Projeto" (Body/13 Bold) à esquerda + ícone sort (16×16) à direita. Fundo: color/surface/2. Variants: sort-none, sort-asc, sort-desc.
  2. Crie o TableCell base. Frame 160×48 px, Auto Layout horizontal, padding 12, align center. Conteúdo: Text instance property para editar o texto na instância. Fundo: transparente (vem do row).
  3. Crie o TableRow. Frame Auto Layout horizontal, sem gap (as células se tocam), borda inferior 1 px. Instancie 4 TableCells. Variants de State: default (fundo transparent), hover (fundo surface-2), selected (fundo primary-soft).
  4. Monte a Table. Frame Auto Layout vertical, gap 0. Primeiro, um TableHeaderRow (com TableHeaderCells). Depois, 5 instâncias de TableRow com dados reais do TaskFlow: nome do projeto, responsável (avatar), prazo, status (badge), ações.
  5. Adicione checkbox de seleção. No TableHeaderCell à esquerda, adicione um checkbox (16×16, border 1.5 px) com estado "marcar todos". Nas TableRows, o primeiro TableCell é uma célula de checkbox.
Variável de instância: Instance Swap

Use a propriedade Instance Swap em TableCell para que o conteúdo de cada célula seja trocável. Isso permite ter uma célula com avatar+texto em uma coluna e uma célula com badge em outra — tudo com o mesmo componente base e sem criar variantes para cada combinação.

Gráficos: mock realista sem bibliotecas

No Figma, gráficos são desenhados como mocks visuais — não são dados reais. O objetivo é comunicar o tipo de visualização, as proporções e a estética, para que o desenvolvedor saiba qual biblioteca de gráficos usar (Chart.js, Recharts, etc.).

Gráfico de barras

  1. Crie o frame do gráfico. Frame 760×260 px, Auto Layout vertical, gap 16, padding 20. Inclua um título e o gráfico em si.
  2. Desenhe as barras. Crie 7 retângulos representando os dias da semana. Use largura fixa (60 px) e alturas variáveis para representar os dados (ex.: 80, 130, 100, 170, 120, 160, 90 px). Fill: color/brand/primary com 80% de opacidade.
  3. Organize em Auto Layout. Agrupe as barras em um frame com Auto Layout horizontal, gap 12, align bottom. Isso alinha todas as barras pela base.
  4. Adicione eixos e labels. Adicione uma linha horizontal de 1 px na base (eixo X) e labels de dias abaixo de cada barra. Use estilo Caption/12 com cor muted.

Gráfico de linha

Para o gráfico de linha, use a ferramenta Vetor (P) para desenhar a linha de dados como um caminho com curvas suaves (segmentos bezier). Adicione um fill de gradiente da linha até o eixo X para criar o efeito de área preenchida.

Board Kanban

O board Kanban é a visualização mais amada pelos times operacionais. Cada coluna representa um status e cada card é uma tarefa. No Figma, o desafio é construir os cards de forma que sejam fáceis de reordenar no protótipo.

Estrutura do Kanban

  1. Crie o KanbanCard. Frame 280×auto, Auto Layout vertical, padding 14, gap 10, border-radius 10, fill surface, sombra Shadow/sm. Conteúdo: tag de projeto (badge), título da tarefa (Body/14 Medium), linha de footer com avatar atribuído + data de prazo. Salve como Component.
  2. Crie a KanbanColumn. Frame de largura fixa 300 px, Auto Layout vertical, padding 14, gap 10, border-radius 12, fill surface-2. Header: nome do status (h3) + contagem de cards + botão "+". Abaixo: N instâncias de KanbanCard.
  3. Monte o board completo. Frame com Auto Layout horizontal, gap 16. Instancie 3 KanbanColumns: "A fazer" (cor neutral), "Em progresso" (cor info), "Concluído" (cor success). A cor é aplicada à bolinha no header da coluna e ao top-border da coluna.
  4. Adicione o drag state. Crie uma Variant do KanbanCard chamada State: dragging — o card tem sombra maior (Shadow/lg), leve rotação (2°) e borda tracejada no lugar de onde saiu. No protótipo, conecte o card a uma animação drag-and-drop entre colunas.

Componentes de apoio

Badge / Status

Crie um Component Badge com Auto Layout horizontal, padding 3×10, border-radius 999 px. Variants de Type: default, success, warning, danger, info, primary. Cada variant muda fill e cor do texto baseado nos tokens semânticos.

Avatar

Component Avatar com Variants de Size (sm: 24, md: 32, lg: 40, xl: 48) e Type (image, initials). Para o tipo initials, use uma letra maiúscula centralizada em fundo colorido. Suporte a avatar grupo (sobreposição): use border branca de 2 px e margin negativa no layout.

Tag / Chip

Component Tag com texto + ícone de fechar opcional. Variants de Color (mapeando para os tokens semânticos) e Closeable (true/false). O ícone X aparece apenas quando Closeable é true — use uma nested Component com visibilidade controlada por propriedade booleana.

Dica: nomeie os components com /

Ao nomear components com barras (Data/Table/Cell, Data/Kanban/Card), o Figma organiza automaticamente uma estrutura hierárquica no painel Assets e no menu de swap de instâncias. Isso facilita enormemente navegar em uma biblioteca com dezenas de componentes.

Mock de gráfico vs. gráfico real

O gráfico que você desenha no Figma é apenas uma representação visual — o desenvolvedor vai implementar com uma biblioteca real (Chart.js, D3, Recharts). Na hora do handoff, documente no Dev Mode quais dados alimentam o gráfico, a biblioteca recomendada e os parâmetros de cor e estilo. O Figma comunica o visual; a lógica de dados vai no código.

Exemplo de uso real

A Atlassian (criadora do Jira e do Trello) mantém o Atlaskit, um design system com centenas de componentes de dados. O princípio que eles usam é o mesmo desta lição: cada componente de dados (tabela, badge, avatar) é um Component com Variants bem definidas e propriedades expostas — nada de copiar e colar e editar na mão.

Resumo

  • KPI Cards devem ter 3 variants de trend (up/down/neutral) usando tokens semânticos de cor.
  • Data Tables são construídas de baixo para cima: Cell → HeaderCell → Row → Table.
  • Use Instance Swap e propriedades de componente para evitar criar uma Variant para cada combinação de conteúdo.
  • Gráficos no Figma são mocks visuais — comunicam o tipo e a estética, mas os dados vêm do código.
  • O board Kanban usa um KanbanCard Component com state:dragging para o protótipo interativo.
  • Nomeie components com Categoria/Subcategoria/Nome para organização automática no Assets.

QuizTeste seu conhecimento

1. Por que gráficos no Figma são considerados "mocks" e não gráficos reais?

  • Porque o Figma não suporta SVG para gráficos
  • Porque gráficos precisam de dados em tempo real, impossíveis no Figma
  • Porque gráficos no Figma são representações visuais estáticas — os dados reais e a lógica de renderização vêm de bibliotecas de código como Chart.js
  • Porque gráficos em Figma são baixa fidelidade por padrão
Gráficos no Figma comunicam o visual e a intenção, mas são estáticos. O desenvolvedor usa bibliotecas como Recharts, Victory, Chart.js ou D3 para renderizar os dados reais com o mesmo estilo definido no mock.

2. Qual propriedade de componente deve ser usada para tornar o conteúdo de uma TableCell trocável sem criar variantes para cada tipo?

  • Instance Swap — permite substituir o componente interno por qualquer outro da biblioteca
  • Boolean property — controla a visibilidade de elementos
  • Text property — edita o texto de qualquer nível do componente
  • Variant property — cria novas versões do componente
Instance Swap é a propriedade certa para conteúdo intercambiável (uma célula pode ter um badge, um avatar ou texto puro). Boolean é para mostrar/ocultar, Text para editar strings, Variant para mudar o "estado" do componente.

3. Qual benefício a nomenclatura hierárquica de componentes (com /) traz no Figma?

  • Melhora a performance de renderização do arquivo
  • Permite que o desenvolvedor gere o código automaticamente
  • É necessária para o Dev Mode funcionar
  • Organiza os componentes em grupos no painel Assets e no menu de Instance Swap, facilitando a navegação em bibliotecas grandes
A barra / cria grupos no painel Assets do Figma — Data/Table/Cell, Data/Table/Row e Data/Table/Header ficam todos dentro do grupo "Data/Table". Em bibliotecas com centenas de componentes, essa organização é essencial.
