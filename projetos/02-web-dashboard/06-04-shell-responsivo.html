Shell responsivo: sidebar e topbar

O app shell é o esqueleto permanente do produto — a estrutura que permanece em toda navegação enquanto o conteúdo central muda. Construir um shell sólido com Auto Layout e Constraints é o que separa um design de dashboard amador de um profissional.

⏱️ Leitura: ~28 min 🎯 Nível: Projeto prático 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Construir a sidebar de navegação com itens, ícones e estado ativo usando Auto Layout;
  • Criar o comportamento colapsável da sidebar com Variables booleanas e Variants;
  • Montar a topbar com busca, notificações e avatar de usuário;
  • Usar Constraints para que o shell se estique corretamente quando o frame é redimensionado;
  • Organizar o app shell em um Component reutilizável na página Components.

O que é o app shell?

Em arquitetura de aplicações web, o app shell é a camada mínima de HTML, CSS e JS que sempre está carregada — o esqueleto que "segura" o conteúdo dinâmico. No design, o app shell é o conjunto de elementos fixos: a sidebar (navegação lateral), a topbar (barra superior) e a área de conteúdo (onde cada tela renderiza).

Por que o shell merece uma lição inteira?

O shell é usado em todas as telas do produto. Se ele estiver errado — com Constraints incorretos, sem Auto Layout, com tamanhos fixos que não respondem — você vai precisar consertar em dezenas de frames. Investir 2 horas para montar um shell perfeito poupa 20 horas de retrabalho.

Anatomia do shell do TaskFlow

App shell do TaskFlow: topbar fixa no topo (constraint Top + Left&Right), sidebar fixa na esquerda (240 px), e área de conteúdo que preenche o espaço restante.

Passo a passo: construindo a sidebar

  1. Crie o frame base da sidebar. No frame Desktop 1440, crie um frame (F) de 240×900 px posicionado em X: 0, Y: 48 (abaixo da topbar). Nomeie-o Sidebar. Defina o fill com a variable color/surface/default e adicione uma borda direita (Stroke → Inside, 1 px, color/border/default).
  2. Adicione Auto Layout à sidebar. Com o frame Sidebar selecionado, pressione Shift + A. Configure:
    • Direção: Vertical
    • Gap: 4
    • Padding: 12 em todos os lados
    • Align: Top center
    • Height: Fill container (para que a sidebar ocupe a altura do frame pai)
  3. Crie um item de navegação. Dentro da sidebar, crie um frame de Nav Item com Auto Layout horizontal: ícone (20×20 px) + texto "Dashboard", gap 10, padding horizontal 12, padding vertical 10, border-radius 8. Aplique o fill color/surface/default. Adicione uma variant State com valores: default, hover, active.
  4. Configure o estado ativo. Na variant active: fill do frame com color/brand/primary-soft, cor do texto com color/brand/primary, cor do ícone com color/brand/primary. Salve como Component (⌥/Alt + ⌘/Ctrl + K).
  5. Adicione todos os items de navegação. Instancie o componente Nav Item 5 vezes dentro da sidebar. Mude os textos: Dashboard, Projetos, Minhas Tarefas, Membros, Configurações. Defina "Dashboard" como active.
  6. Adicione separador e rodapé da sidebar. Após os items de menu, adicione um Spacer (frame de 1 px de altura com Fill height) para empurrar o rodapé para baixo. No rodapé, coloque o avatar do usuário + nome + botão de logout com Auto Layout horizontal.
  7. Configure Constraints da sidebar. Selecione o frame Sidebar. No painel Constraints, defina:
    • Horizontal: Left
    • Vertical: Top and Bottom
    Isso faz a sidebar grudar na esquerda e esticar na vertical quando o frame da tela for redimensionado.
Spacer com Fill height

Um truque poderoso: dentro de um Auto Layout vertical, crie um frame vazio (sem fill, sem stroke) e defina sua altura como Fill container. Ele age como um "mola" que empurra os elementos abaixo para o fundo do container — exatamente como margin-top: auto no Flexbox CSS.

Passo a passo: construindo a topbar

  1. Crie o frame da topbar. Crie um frame de 1440×48 px no topo do frame de tela. Nomeie Topbar. Fill: color/surface/default, borda inferior de 1 px.
  2. Adicione Auto Layout. Pressione Shift + A. Configure: direção horizontal, align center, padding horizontal 20, gap: Auto (space between).
  3. Adicione o logotipo e nome. Crie um grupo com o logo (quadrado de 28×28 px com gradiente brand) + texto "TaskFlow" (24 px, Bold). Agrupe com Ctrl/⌘ + G e aplique Auto Layout ao grupo (horizontal, gap 8, align center).
  4. Adicione o campo de busca. Crie um frame de input de busca: ícone de lupa + placeholder "Buscar projetos e tarefas…" com Auto Layout horizontal. Largura: 280 px, altura: 36 px, border-radius 8, borda 1 px.
  5. Adicione ações da direita. Crie um grupo com: ícone de notificações (36×36 px, border-radius 8) + separador vertical (1×24 px) + avatar de usuário (32×32 px, border-radius 50%) + chevron-down. Use Auto Layout horizontal, gap 8.
  6. Configure Constraints da topbar. Constraints: Left and Right + Top. A topbar ficará fixa no topo e se estenderá horizontalmente quando o frame for redimensionado.

Montando o app shell completo

  1. Crie o frame-pai (tela completa). O frame raiz é 1440×900 px. Dentro dele, posicione: Topbar (Y:0), Sidebar (Y:48, X:0), e um frame de Conteúdo (X:240, Y:48, Width: 1200, Height: 852).
  2. Configure o frame de Conteúdo. Fill: color/background/subtle. Constraints: Left and Right + Top and Bottom. Isso faz o conteúdo se estender em ambas as direções quando a janela cresce.
  3. Teste redimensionando o frame. Selecione o frame raiz e arraste a borda direita. Observe: topbar se estica horizontalmente, sidebar mantém a largura e o conteúdo absorve o espaço.
  4. Salve como Component. Selecione o frame raiz do shell. Use Alt/⌥ + Ctrl/⌘ + K para criar um Component chamado AppShell/Desktop. Mova-o para a página Components.
Dica: sidebar colapsável com Variants

Para criar o comportamento de colapsar a sidebar, adicione uma segunda Variant ao Component AppShell: Sidebar: expanded (240 px) e Sidebar: collapsed (60 px, mostrando apenas ícones). Use uma Variable booleana sidebar/collapsed para controlar qual variante exibir. No protótipo, conecte o botão "Colapsar" a uma ação de Set variable que alterna o estado.

Resumo

  • O app shell (topbar + sidebar + área de conteúdo) é a fundação de toda interface de dashboard.
  • A sidebar usa Auto Layout vertical com um Spacer de Fill height para empurrar o rodapé para baixo.
  • A topbar usa Auto Layout horizontal com gap Auto (space between) para separar logo e ações.
  • Constraints corretos: topbar (Left&Right + Top), sidebar (Left + Top&Bottom), conteúdo (Left&Right + Top&Bottom).
  • O Nav Item é um Component com variants de estado (default, hover, active) para manter consistência.
  • O shell inteiro deve ser salvo como Component na página de Components e instanciado em cada tela.
✍️ Exercício

Construa o app shell completo

  1. Crie um frame Desktop 1440×900 px e monte dentro dele: topbar (48 px), sidebar (240 px) e área de conteúdo.
  2. Aplique Auto Layout à sidebar com padding 12 e gap 4.
  3. Crie o Nav Item como Component com 3 variants de estado (default, hover, active).
  4. Adicione 5 itens de menu na sidebar e defina "Dashboard" como active.
  5. Configure todos os Constraints corretamente e teste redimensionando o frame raiz.
Critério de sucesso: ao arrastar a borda direita do frame raiz para 1280 px, a topbar se estica, a sidebar permanece com 240 px e o conteúdo preenche o espaço restante — sem nenhum elemento se deslocando incorretamente.
🏆 Desafio

Sidebar colapsável com protótipo

Adicione uma segunda Variant ao Component AppShell: a versão colapsada, onde a sidebar tem 60 px de largura e exibe apenas ícones (sem texto). Crie um botão de toggle na sidebar (ícone de seta apontando para a esquerda/direita conforme o estado). No modo Protótipo, conecte o botão a uma interação de Set variable que alterna entre expanded e collapsed. Teste a animação Smart Animate para suavizar a transição de 240 → 60 px.

QuizTeste seu conhecimento

1. Quais Constraints devem ser aplicados à topbar para que ela fique fixa no topo e se estenda horizontalmente?

  • Left + Top
  • Left and Right + Bottom
  • Left and Right + Top
  • Scale + Top
Left and Right + Top: "Left and Right" faz a topbar se esticar horizontalmente; "Top" a mantém ancorada ao topo quando o frame é redimensionado verticalmente.

2. Como empurrar o rodapé de uma sidebar para o fundo usando Auto Layout vertical?

  • Definir o padding-bottom como 999 px para criar espaço manual
  • Adicionar um frame vazio com Height: Fill container entre o menu e o rodapé — ele age como uma mola
  • Usar position absolute no rodapé
  • Desativar o Auto Layout e usar coordenadas Y manuais
Um frame de altura Fill container dentro de um Auto Layout vertical consome todo o espaço disponível — exatamente como flex: 1 ou margin-top: auto no CSS Flexbox. Isso empurra os elementos subsequentes para o fundo.

3. Por que o Nav Item deve ser criado como Component com Variants em vez de frames comuns?

  • Para garantir que todos os estados (default, hover, active) sejam consistentes em todas as instâncias e que mudanças no master se propaguem para todas as telas
  • Porque frames comuns não suportam ícones SVG
  • Porque Variants são mais rápidas de renderizar no Figma
  • Apenas por convenção — não há diferença funcional
Components com Variants garantem que todos os estados são gerenciados em um lugar só. Quando você atualiza o estilo do estado ativo no master Component, todas as 5 instâncias na sidebar (e em todas as telas do projeto) se atualizam automaticamente.
