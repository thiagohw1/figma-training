Responsividade: desktop → tablet → mobile

Um dashboard que só funciona em 1440 px é um produto incompleto. Nesta lição, você vai aprender a adaptar cada parte do TaskFlow — sidebar, tabela, Kanban — para os três breakpoints, usando Auto Layout e Constraints como sua principal ferramenta de responsividade.

⏱️ Leitura: ~28 min 🎯 Nível: Projeto prático 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Adaptar a sidebar de fixa (desktop) para drawer deslizante (tablet/mobile);
  • Converter a data table em lista de cards para mobile usando o mesmo componente base;
  • Usar Auto Layout com wrap e fill para que grids de cards se adaptem automaticamente;
  • Criar frames de 768 e 375 px com layouts adaptados para cada breakpoint;
  • Aplicar Constraints para que os elementos do shell se comportem corretamente ao redimensionar.

A filosofia da responsividade no design

Responsividade não é "fazer a tela menor". É rearranjar a informação para que ela seja igualmente acessível em qualquer tela. Um table de dados em desktop vira uma lista de cards no mobile — não uma tabela com scroll horizontal que o usuário precisa arrastar infinitamente.

No Figma, responsividade se implementa em três camadas:

  • Constraints: definem como os elementos se movem e redimensionam quando o frame pai muda de tamanho.
  • Auto Layout (Fill + Wrap): os containers redistributem automaticamente os filhos quando o espaço muda.
  • Variantes de breakpoint: para mudanças estruturais (sidebar vira drawer), criamos Variants separadas do componente.

Passo a passo: adaptando para tablet (768 px)

  1. Duplique o frame de desktop e redimensione para 768 px. Selecione o frame 01 — Dashboard (Desktop), pressione Ctrl/⌘ + D para duplicar. Renomeie para 01 — Dashboard (Tablet). Selecione-o e no painel de propriedades mude a largura para 768 px.
  2. Oculte a sidebar e ajuste a topbar. No frame de tablet, oculte o frame da Sidebar clicando no ícone de olho no painel de layers. Na Topbar, troque o componente AppShell pela Variant breakpoint: tablet (que você criará com hamburguer menu à esquerda).
  3. Ajuste o layout dos KPI Cards. O frame pai dos cards usa Auto Layout horizontal com wrap ativo. No desktop eram 4 cards por linha. Ao reduzir para 768 px, o wrap os reorganiza para 2 por linha automaticamente — desde que cada card esteja com Width: Fill container e o gap seja 16.
  4. Empilhe o gráfico e o painel lateral. No layout desktop, o gráfico e o painel lateral estão em Auto Layout horizontal. No tablet, mude a direção para vertical. O gráfico ocupa 100% da largura e o painel lateral aparece abaixo.
  5. Adicione o Drawer de sidebar. Crie um novo frame de 320×768 px sobreposto ao conteúdo (posição X:0), com a sidebar dentro. Adicione um backdrop semitransparente atrás. Este é o estado "sidebar aberta" no tablet. Conecte ao botão hamburguer no protótipo.
Auto Layout Wrap: o segredo do layout responsivo

No Figma, ao ativar Wrap em um Auto Layout horizontal, os filhos quebram para a próxima linha quando não há espaço. Se cada filho está em Fixed width (ex.: 300 px), eles sempre terão o mesmo tamanho. Se estão em Fill container, cada filho cresce para ocupar o espaço disponível. A combinação de Wrap + Fixed mínimo é o equivalente ao CSS grid-template-columns: repeat(auto-fill, minmax(300px, 1fr)).

Passo a passo: adaptando para mobile (375 px)

  1. Duplique o frame de tablet e redimensione para 375 px. Renomeie para 01 — Dashboard (Mobile). Mude a largura para 375 px.
  2. Substitua a topbar pela versão mobile. A topbar mobile tem apenas: hamburguer (à esquerda) + logo (centro) + avatar (à direita). A busca migrou para um ícone que abre a busca em tela cheia.
  3. Substitua a sidebar pela bottom navigation. No mobile, a navegação vai para o fundo da tela (bottom navigation bar): um frame de 375×56 px fixo no bottom, com 5 ícones com labels. No Figma, posicione-o com Constraint Left and Right + Bottom.
  4. Ajuste os KPI Cards para 1 coluna. Com o wrap ativo, ao chegar em 375 px e os cards em Fixed 343 px (375 - 32 de margem), cada card ocupa automaticamente uma linha inteira. Verifique que o padding lateral do container é 16 px.
  5. Substitua a tabela pela lista de cards mobile. Oculte o componente Table. No lugar, crie uma lista de ProjectCardMobile — um card vertical com nome, status (badge), responsável (avatar) e prazo. Isso substitui as linhas da tabela por cards tocáveis, com padding adequado para touch (mínimo 44 px de altura de hit area).
  6. Ajuste os espaçamentos de toque. Revise todos os elementos interativos: botões, links, ícones. No mobile, o mínimo para área de toque é 44×44 px (guideline da Apple) / 48×48 dp (guideline do Material). Qualquer coisa menor é difícil de tocar com precisão.

Técnicas avançadas de Auto Layout para responsividade

Fill container vs. Fixed

A combinação mais poderosa para responsividade no Figma:

  • Elementos com Fill container crescem para preencher o espaço disponível no container pai.
  • Elementos com Fixed mantêm tamanho absoluto, independente do pai.
  • Use Fill + min-width para definir o mínimo antes do wrap acontecer.

Wrap com espaçamento dinâmico

Em Auto Layout horizontal com Wrap, configure:

  • Horizontal gap: 16 px (entre colunas)
  • Vertical gap: 16 px (entre linhas quando há wrap)
  • Cada filho: Width: Fill container com valor mínimo (ex.: 260 px)

O resultado é equivalente ao CSS grid-template-columns: repeat(auto-fill, minmax(260px, 1fr)); gap: 16px — adaptação automática sem criar frames separados para cada breakpoint.

Atenção: Constraints só funcionam dentro de frames não-Auto Layout

Dentro de um frame com Auto Layout ativo, as Constraints são ignoradas — o Auto Layout controla o posicionamento. Constraints só se aplicam a filhos de frames sem Auto Layout. Use Auto Layout para layouts que precisam de lógica de distribuição; use Constraints para elementos que precisam de ancoragem específica (ex.: botão flutuante no canto inferior direito).

Exemplo de uso real

O Notion — uma das ferramentas de produtividade mais complexas do mercado — usa exatamente essa estratégia: no desktop tem uma sidebar permanente, no tablet o conteúdo ocupa tela cheia e a sidebar aparece como overlay, e no mobile há uma interface completamente repensada com navegação por drawer. O design file oficial da Notion no Figma tem frames nomeados por breakpoint para cada tela principal.

Resumo

  • Responsividade no Figma usa Constraints, Auto Layout Fill/Wrap e Variants de breakpoint em combinação.
  • A sidebar vira drawer (tablet) e bottom navigation (mobile) — mudanças estruturais exigem Variants de componente.
  • Auto Layout Wrap + filhos com Fill container é o equivalente visual do CSS auto-fill minmax.
  • No mobile, tabelas viram listas de cards e os alvos de toque precisam de no mínimo 44×44 px.
  • Constraints funcionam apenas em frames sem Auto Layout — dentro de Auto Layout, o posicionamento é controlado pela direção e alinhamento.
  • Duplique e adapte, não refaça do zero — o design desktop é a base, as adaptações são camadas sobre ela.
✍️ Exercício

Adapte o Dashboard para os 3 breakpoints

  1. Duplique o frame do Dashboard desktop e crie as versões 768 e 375 px.
  2. Na versão tablet: oculte a sidebar, adicione o hamburguer na topbar e crie o frame do Drawer sobre o conteúdo.
  3. Na versão mobile: substitua a sidebar pela bottom navigation bar e os KPI cards por 1 coluna.
  4. Certifique-se de que os KPI cards em todos os frames usam Auto Layout Wrap para redistribuição automática.
Critério de sucesso: os 3 frames do Dashboard estão na página correspondente, a sidebar desaparece corretamente no tablet e mobile, e os KPI cards se redistribuem em 2 colunas no tablet e 1 coluna no mobile sem retrabalho manual.

QuizTeste seu conhecimento

1. Como o Auto Layout Wrap com filhos em Fill container se traduz no CSS?

  • display: flex; flex-wrap: wrap; justify-content: flex-start com filhos de largura fixa
  • display: grid; grid-template-columns: repeat(auto-fill, minmax(Xpx, 1fr)) — redistribuição automática com largura mínima
  • display: flex; flex-direction: column
  • display: grid; grid-template-columns: repeat(12, 1fr)
Auto Layout Wrap + Fill container é equivalente ao auto-fill minmax do CSS Grid — os itens ocupam o espaço disponível e quebram para a próxima linha quando atingem o mínimo. É a técnica mais poderosa para layouts de cards responsivos.

2. Por que Constraints são ignorados dentro de um Auto Layout?

  • É um bug conhecido do Figma que ainda não foi corrigido
  • Constraints só funcionam em frames raiz (top-level), não em filhos
  • Constraints precisam ser ativados manualmente no modo de Auto Layout
  • Porque o Auto Layout controla o posicionamento dos filhos — Constraints e Auto Layout são dois sistemas mutuamente exclusivos de posicionamento
Auto Layout e Constraints são sistemas concorrentes: o Auto Layout toma o controle do posicionamento dos filhos. Constraints só entram em jogo em frames onde o Auto Layout não está ativo. Dentro de um Auto Layout, você controla a posição via direção, alinhamento e gap.

3. Qual é o tamanho mínimo de área de toque recomendado para mobile?

  • 44×44 px (Apple HIG) / 48×48 dp (Material Design)
  • 24×24 px — mesma que o ícone visual
  • 32×32 px — padrão de cursor para desktop
  • Não há recomendação oficial — depende do contexto
A Apple recomenda 44×44 pt e o Material Design recomenda 48×48 dp como mínimo de área de toque. Elementos menores são difíceis de acionar com precisão — especialmente para usuários com mobilidade reduzida ou dedos maiores.
