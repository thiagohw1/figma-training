Prototipagem e microinterações

Um design estático não convence. Um protótipo clicável que navega suavemente entre telas, abre bottom sheets com animação e responde ao toque — isso convence. Nesta lição você vai conectar todas as telas do FinView, configurar transições e criar microinterações com Smart Animate.

⏱️ Leitura: ~24 min 🎯 Nível: Projeto prático 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Conectar todas as telas do FinView em um fluxo de protótipo coeso;
  • Configurar a navegação da Tab Bar com transições adequadas;
  • Criar o bottom sheet de "Adicionar Transação" com animação de subida;
  • Usar Smart Animate para a transição de abertura de detalhe de transação;
  • Simular o loading skeleton com transição automática;
  • Testar o protótipo em um dispositivo real via Figma Mirror.

O modo Prototype no Figma

O Figma tem dois modos de trabalho: Design (onde você constrói) e Prototype (onde você conecta). Para entrar no modo Prototype, clique na aba Prototype no painel direito. Você verá setas azuis nos frames e elementos quando passar o mouse — essas são as conexões de navegação.

Cada conexão tem três partes:

  • Trigger: o que aciona a transição (tap, hover, drag, after delay, on key press)
  • Action: o que acontece (navigate to, open overlay, back, scroll to)
  • Animation: como a transição visual ocorre (Instant, Dissolve, Smart Animate, Move In, Move Out, Slide In, Slide Out, Push)
Smart Animate: o motor das animações suaves

Smart Animate é o recurso mais poderoso de prototipagem do Figma. Quando você conecta dois frames e usa Smart Animate, o Figma detecta automaticamente elementos com o mesmo nome de layer nos dois frames e interpola a posição, tamanho, opacidade e outros atributos entre eles — criando uma animação fluida sem você precisar definir cada keyframe. É como ter um sistema de interpolação automática.

Conectando o fluxo principal

  1. Ative o modo Prototype. Clique na aba Prototype no painel direito. Mude a view para Flow para ver todas as conexões existentes (se houver). Defina o frame de Starting Point clicando no ícone de play no frame do Onboarding.
  2. Conecte Onboarding → Home. Selecione o botão "Próximo →" no frame Onboarding Card 3 (o último). No modo Prototype, um ponto azul aparece na borda direita do botão ao passar o mouse. Arraste esse ponto até o frame da Home. Configure: Trigger = On tap, Action = Navigate to, Animation = Push →, Duration = 350ms, Easing = Spring.
  3. Configure a navegação entre os 3 cards de onboarding. No card 1, conecte o botão "Próximo" ao card 2 com Push → (350ms). No card 2, conecte ao card 3. No card 3, ao frame Home. Também conecte os dots de indicação: o dot 2 no card 1 navega para o card 2, etc.
  4. Configure a Tab Bar. Selecione a instância da Tab Bar na Home. Você precisa tornar cada item da tab um hotspot de navegação. Selecione o Tab Item "Metas" e conecte ao frame de Metas. Repita para "Cartões" → frame Cartões, "Perfil" → frame Perfil. Para o botão "+" central, navegue para o bottom sheet. Use Trigger = On tap, Animation = Instant para trocas de tab (troca instantânea é o padrão iOS/Android).
  5. Conecte a lista de transações → Detalhe. Selecione um item de transação na Home. Conecte ao frame de Detalhe. Use Smart Animate com duration 400ms, easing Ease In Out. Para que o Smart Animate funcione corretamente, certifique-se de que o card do item tem o mesmo nome de layer na Home e no Detalhe (ex.: ambos se chamam "Transaction Card").
  6. Configure o botão Voltar no Detalhe. O botão "← Voltar" no frame Detalhe deve conectar de volta à Home. Use Action = Navigate back (não "Navigate to" — "back" mantém o histórico correto). Animation = Push ← (sentido oposto ao de entrada).

Criando o Bottom Sheet de Adicionar Transação

O Bottom Sheet é um padrão mobile onde um painel sobe de baixo para cima sobre a tela atual. No Figma, isso é feito com a Action Open overlay.

  1. Construa o frame do Bottom Sheet. Crie um frame 390×600 (mais alto que a tela) com fundo color/surface, corner radius top 20×20. Dentro: drag handle (linha 32×4 px centrada no topo), título "Nova Transação", toggle Entrada/Saída, campo de valor grande, grid de categorias (4×2), campo de nota e botão Salvar.
  2. Configure o backdrop escuro. O backdrop (sobreposição escura atrás do bottom sheet) é criado colocando o frame do bottom sheet em cima de um retângulo 390×844 fill preto 50% de opacidade, dentro do mesmo frame-container.
  3. Conecte o botão "+" ao Bottom Sheet. No frame da Home, selecione o botão "+" da Tab Bar. Conecte ao frame do Bottom Sheet. Trigger = On tap, Action = Open overlay, Overlay position = Bottom, Animation = Move in from bottom, Duration = 400ms, Easing = Spring (0.5).
  4. Conecte o botão Fechar do Bottom Sheet. No bottom sheet, selecione o botão "X" ou "Cancelar". Action = Close overlay, Animation = Move out to bottom.
  5. Conecte o backdrop para fechar ao tap. O retângulo de backdrop deve fechar o overlay quando tocado. Selecione-o, conecte com Action = Close overlay.

Smart Animate: a transição de detalhe de transação

O padrão mais sofisticado do FinView é a transição da lista para o detalhe: o card da transação na lista "expande" para ocupar a tela de detalhe — efeito similar ao App Store no iOS. Com Smart Animate, você faz isso no Figma:

Como funciona o Smart Animate

O Figma compara os layers de dois frames consecutivos. Layers com exatamente o mesmo nome são animados automaticamente entre suas posições/tamanhos/estilos. Por isso, a nomenclatura dos layers é fundamental:

  • Na Home: o item de transação deve ter um layer chamado Transaction Card
  • No Detalhe: o card de informações no topo deve ter o layer Transaction Card
  • O valor monetário em ambos deve ter o mesmo nome de layer: Amount Text
  • O ícone de categoria: Category Icon

Com esses nomes iguais, ao usar Smart Animate, o card "crescerá" da sua posição na lista até ocupar o topo do Detalhe — e o valor e ícone se moverão suavemente para suas novas posições.

  1. Nomeie os layers corretamente na Home. Clique duas vezes no item de transação para entrar nele. Renomeie o container principal para Transaction Card, o texto do nome para Merchant Name, o valor para Amount Text, o ícone para Category Icon.
  2. Nomeie os layers correspondentes no Detalhe. No frame Detalhe, nomeie o card de resumo no topo como Transaction Card. O valor grande como Amount Text. O ícone como Category Icon. O nome da empresa como Merchant Name.
  3. Conecte os frames com Smart Animate. No modo Prototype, selecione o item de transação na Home. Arraste a conexão para o frame Detalhe. Configure: Trigger = On tap, Animation = Smart Animate, Duration = 450ms, Easing = Spring.
  4. Teste no Preview. Pressione Ctrl/⌘ + P para abrir o protótipo. Clique em um item de transação. Observe o card transitando suavemente do tamanho de lista para o detalhe. Ajuste a duração se necessário (400-500ms costuma funcionar bem).
Dica para Smart Animate mais fluido

Para animações mais suaves, use Spring como easing (configuração: stiffness 300, damping 25). O Spring cria a sensação de "bounce" natural que aplicativos nativos têm. Evite Linear e Ease puro para animações de UI mobile — elas parecem mecânicas. A maioria dos apps iOS usa algo equivalente ao Spring para modais e sheets.

Microinterações: feedback ao toque

Microinterações são as pequenas respostas visuais que confirmam que o toque do usuário foi registrado. No FinView, planejamos 4 microinterações:

ElementoMicrointeraçãoComo fazer no Figma
Botão primário Scale down (98%) ao pressionar, escurece fill Variante State=Pressed, Smart Animate na volta
Item de transação Highlight sutil (fundo ligeiramente mais claro) ao hover/press Variante hover com fill diferente + After delay para voltar
Tab Bar item Ícone sobe e desce (bounce) ao ativar Dois frames intermediários + Smart Animate encadeado
Toggle Entrada/Saída Slide do pill de seleção Dois frames do toggle + Smart Animate (o pill muda de posição)

Implementando o toggle com Smart Animate

O toggle de Entrada/Saída no bottom sheet é uma microinteração elegante. Para implementar:

  1. Crie duas variantes do Toggle component: State=Expense (pill na esquerda, texto Gasto ativo) e State=Income (pill na direita, texto Receita ativo).
  2. Nomeie o pill de seleção com o mesmo nome em ambas as variantes: Toggle Pill.
  3. No protótipo, o tap no label "Receita" muda a variante para State=Income via Smart Animate — o pill desliza suavemente para a direita.

Simulando o loading com transição automática

Para simular o skeleton loading → conteúdo carregado, use a opção After delay como trigger:

  1. Defina o frame 01 — Home (Loading) como ponto inicial do fluxo de app.
  2. Conecte esse frame ao frame 01 — Home com Trigger = After delay, Delay = 2000ms, Animation = Dissolve, Duration = 500ms.
  3. No preview, o app começa com o skeleton e, após 2 segundos, dissolve suavemente para a Home com dados. Parece real.
Prototype flow: organize por cenário

Nos arquivos Figma profissionais, o fluxo de protótipo é organizado em Flows separados (clique em "+ Flow" no painel Prototype quando nenhuma conexão está selecionada). Crie flows como "Flow 1: Adicionar Transação", "Flow 2: Consultar Meta", "Flow 3: Onboarding". Isso permite que você apresente cenários específicos sem começar do zero, e o Figma cria links de preview separados para cada flow — perfeito para apresentar para stakeholders diferentes.

Testando em dispositivo real com Figma Mirror

Nenhum preview no computador substitui o teste no dispositivo. O Figma Mirror (app mobile disponível para iOS e Android) espelha o protótipo em tempo real no seu celular:

  1. Baixe o app Figma Mirror no seu celular.
  2. No Figma desktop, abra o protótipo com Ctrl/⌘ + P ou clique no botão "Play" no topo.
  3. No app mobile, escaneie o QR code ou faça login — o protótipo aparece no tamanho real da tela do seu celular.
  4. Navegue pelas telas com os toques reais. Observe: os toques parecem confortáveis? O conteúdo cabe bem? A tab bar fica na posição certa?
Área de toque mínima: 44×44 pt

O Apple HIG especifica que toda área interativa deve ter pelo menos 44×44 pt de área de toque, mesmo que o elemento visual seja menor. Se um ícone de 24×24 pt é clicável, envolva-o em um frame de 44×44 pt invisível. No Figma, você pode criar uma camada "Tap Target" transparente de 44×44 que é o hotspot real do protótipo. Teste no Figma Mirror: se você precisar mirar muito para clicar, a área está pequena.

Resumo

  • O modo Prototype conecta frames com triggers, actions e animações — três componentes de cada conexão.
  • A Tab Bar usa Action = Navigate to com Animation = Instant (troca de tab sem animação é o padrão nativo).
  • O Bottom Sheet de Adicionar usa Open overlay com Move in from bottom e Spring easing.
  • Smart Animate interpola automaticamente elementos com o mesmo nome de layer entre dois frames, criando transições fluidas.
  • Microinterações são criadas com variantes (State=Pressed) e Smart Animate entre elas.
  • Figma Mirror permite testar o protótipo no dispositivo físico em tempo real.
✍️ Exercício

Protótipo completo do FinView

No seu arquivo, na page 🔗 Protótipo (ou usando as telas da page iOS):

  1. Defina o frame de Onboarding como Starting Point.
  2. Conecte o fluxo completo: Onboarding → Home → Detalhe (Smart Animate) → Voltar.
  3. Configure a Tab Bar para navegar para Metas e Perfil.
  4. Crie e conecte o Bottom Sheet de Adicionar Transação com Open overlay + Spring.
  5. Implemente a simulação de loading com After delay (2s) → Home.
  6. Teste o protótipo no Figma Mirror no seu celular.
Critério de sucesso: é possível percorrer o fluxo completo (Onboarding → Home → Adicionar transação → fechar sheet → abrir detalhe → voltar) sem encontrar nenhuma conexão quebrada. As transições parecem suaves e nativas no teste pelo Figma Mirror.
🏆 Desafio

Microinteração de celebração ao completar meta

Construa uma microinteração para quando uma meta é concluída (100% atingido). Ao clicar em uma meta completa, o app deve: (1) expandir o card da meta com Smart Animate, (2) mostrar um estado de "Conquista!" com um ícone de troféu animado (escala de 0 a 1 via Smart Animate), (3) exibir confetti simulado com formas coloridas espalhadas, e (4) um botão "Criar nova meta" aparece deslizando de baixo. Use encadeamento de frames (cada frame é um "keyframe" da animação) conectados com Smart Animate e After delay curto (100-200ms entre cada etapa). Esse tipo de animação comemorativa é o que diferencia apps mediocres de apps que os usuários adoram.

QuizTeste seu conhecimento

1. Para que o Smart Animate funcione corretamente entre dois frames, qual é o requisito fundamental?

  • Os dois frames devem estar na mesma page do Figma
  • Os dois frames devem ter exatamente as mesmas dimensões
  • Os layers que serão animados devem ter exatamente o mesmo nome nos dois frames
  • Os elementos devem ser components — frames comuns não funcionam com Smart Animate
O Smart Animate funciona comparando nomes de layers entre dois frames. Layers com o mesmo nome são interpolados automaticamente em posição, tamanho, rotação e opacidade. Se os nomes forem diferentes, o Figma fará um dissolve simples em vez da animação "matched" desejada.

2. Qual Action no Figma Prototype é a correta para criar um Bottom Sheet que aparece sobre a tela atual?

  • Open overlay
  • Navigate to
  • Swap with
  • Scroll to
Open overlay é a action correta para sheets, modais e dialogs — ela exibe o frame de destino sobre a tela atual, sem substituí-la. Quando o overlay é fechado, o usuário volta à tela original. "Navigate to" seria para navegação de tela completa (substituição).

3. Qual trigger do Figma Prototype permite simular carregamento automático (skeleton → conteúdo)?

  • On hover
  • After delay
  • On scroll
  • On key press
After delay dispara automaticamente a transição após um tempo definido (em ms), sem precisar de interação do usuário. É perfeito para simular carregamento: o frame de skeleton transita para o frame com dados após 2000ms, imitando o comportamento real de uma request de API.
