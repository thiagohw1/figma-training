Fundação visual: cores, tipografia e Variables

Uma interface coesa começa com tokens bem definidos. Nesta lição você vai construir o sistema de design do FinView do zero — criando Variables para cores, tipografia, espaçamentos e raios, com suporte a light e dark mode de verdade.

⏱️ Leitura: ~24 min 🎯 Nível: Projeto prático 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Criar uma coleção de Variables de cor com dois modos (Light e Dark) no Figma;
  • Organizar os tokens em grupos semânticos (surface, text, brand, semantic);
  • Definir variables de número para spacing, border-radius e font-size;
  • Configurar a grade de 4 colunas para mobile no Figma;
  • Aplicar as variables nos elementos da tela e alternar modos com um clique.

Por que Variables e não Styles?

O Figma tinha apenas Color Styles por anos, e eles ainda existem — mas Variables (lançadas em 2023, aprimoradas em 2024/2025) são uma camada mais poderosa. A diferença fundamental:

CaracterísticaColor StylesVariables
Múltiplos modos (light/dark)Não — você cria styles separadosSim — um único nome, N valores por modo
Tipos de dadoApenas corCor, número, string, booleano
Referência a outras variablesNãoSim — token aliases (semantic sobre primitive)
Uso em Auto Layout (spacing)NãoSim — espaçamentos com variável numérica
Handoff para Dev ModeParcialTotal — nome do token aparece no Dev Mode

Para o FinView, usaremos Variables em todas as camadas — o resultado será um design system que troca de tema com um único clique e que, quando entregue ao desenvolvedor, já vem com os nomes de tokens corretos.

Arquitetura de dois níveis: Primitive → Semantic

A prática profissional usa dois níveis de tokens: Primitive (os valores brutos, ex.: purple/500: #6C4CF1) e Semantic (significado, ex.: color/brand/primary: {purple/500}). Os semantic tokens apontam para os primitivos. Com isso, trocar a cor primária de todo o produto é alterar um único primitive — todos os semantic tokens que o referenciam se atualizam automaticamente.

Passo a passo: criando as Variables no Figma

  1. Abra o painel de Variables. Na page 🎨 Design Tokens, pressione Ctrl/⌘ + Alt/⌥ + V ou clique no ícone de grade no canto superior esquerdo do Figma e selecione Local variables. Um painel flutuante se abrirá.
  2. Crie a coleção "Primitive/Colors". Clique em + New collection e nomeie como Primitive/Colors. Esta coleção terá apenas um modo (sem light/dark — primitivos são valores absolutos). Mantenha o modo padrão como "Mode 1" ou renomeie para "Base".
  3. Adicione os grupos de cores primitivas. Clique em + New variable → Color. Nomeie com a barra como separador de grupo: violet/100, violet/300, violet/500, violet/700. O Figma agrupa automaticamente por prefixo. Repita para green, red, neutral (escala de cinzas de 100 a 950).
  4. Crie a coleção "Semantic/Colors" com dois modos. Nova coleção: Semantic/Colors. Clique em + Add mode e crie dois modos: Light e Dark. Agora você terá duas colunas para cada variável.
  5. Adicione os tokens semânticos e referencie os primitivos. Crie variável color/bg. No modo Light, clique no campo de cor e, em vez de digitar um hex, clique em Library e escolha Primitive/Colors/neutral/50. No modo Dark, referencie Primitive/Colors/neutral/950. Repita para todos os tokens semânticos da tabela abaixo.
  6. Crie a coleção "Semantic/Spacing" com number variables. Nova coleção: Semantic/Spacing. Adicione variáveis do tipo Number: spacing/xs: 4, spacing/sm: 8, spacing/md: 16, spacing/lg: 24, spacing/xl: 32, spacing/2xl: 48. Essas serão usadas como padding e gap nos Auto Layouts.
  7. Crie a coleção "Semantic/Radius". Mesma lógica, tipo Number: radius/sm: 8, radius/md: 12, radius/lg: 16, radius/xl: 20, radius/pill: 999. Use radius/pill para badges e tags.
  8. Aplique uma variable a um elemento. Selecione um retângulo na canvas. No painel direito, clique no campo de Fill e veja o ícone de biblioteca (losango) ao lado do seletor de cor. Clique nele e escolha a variable color/bg. Pronto — o elemento agora usa o token semântico e vai mudar automaticamente quando você trocar o modo.
  9. Troque o modo de um frame inteiro. Selecione o frame iPhone. No painel direito, em Layer, aparece um seletor de variable mode. Clique e escolha entre Light e Dark. Todos os elementos que usam variables semânticas trocam de cor instantaneamente.
Nome de variável com "/" cria agrupamento automático

A barra (/) no nome da variável cria hierarquia visual no painel: color/bg e color/surface aparecem agrupados sob color. Use até 3 níveis: color/brand/primary. Isso é fundamental para variáveis de cor — você terá dezenas delas e o agrupamento mantém o painel organizado.

Por que não criar variables de string para tipografia?

No Figma 2025/2026, as variables de tipo String ainda não se conectam diretamente aos estilos de texto de forma nativa (font family, size, weight juntos). Por isso, tipografia segue usando Text Styles tradicionais. Variables numéricas podem ser usadas para font-size individual se necessário. Acompanhe o roadmap do Figma — isso pode mudar.

Grid mobile no Figma

O grid de um app mobile iOS usa 4 colunas com gutters de 16 px e margens de 16 px em cada lado. Para configurar no Figma:

  1. Selecione o frame iPhone 16. Clique no frame (não em um elemento dentro dele).
  2. Adicione o grid de colunas. No painel direito, em Layout grid, clique em +. Clique no ícone de grade e mude de Grid para Columns.
  3. Configure as colunas. Count: 4, Margin: 16, Gutter: 16, Type: Stretch. Ative a visibilidade do grid com Ctrl/⌘ + G (ou o ícone de olho no painel).
  4. Adicione a row guide (opcional mas recomendado). Adicione um segundo grid do tipo Rows com height 8 px e color com 10% de opacidade. Isso cria uma grade de 8 px para alinhar elementos verticalmente — o famoso "grid de 8 pt".
O sistema de 8 pt: o padrão da indústria mobile

Basicamente todo app mobile sério (iOS, Android) usa múltiplos de 8 para todos os espaçamentos: 8, 16, 24, 32, 48... Isso garante que os elementos sempre caem em pixels inteiros (em telas 2x/3x retina), mantém consistência e facilita o handoff — o desenvolvedor já sabe que padding é sempre múltiplo de 8. No FinView, nossos spacing tokens já seguem isso: xs=4, sm=8, md=16, lg=24, xl=32, 2xl=48.

Resumo

  • Variables superam Color Styles por suportarem múltiplos modos, tipos de dado variados e referências entre tokens.
  • A arquitetura de dois níveis (Primitive → Semantic) permite trocar a identidade visual do produto alterando apenas os primitivos.
  • Criamos 4 coleções: Primitive/Colors, Semantic/Colors (com modos Light e Dark), Semantic/Spacing e Semantic/Radius.
  • Tipografia usa Text Styles tradicionais (7 estilos), seguindo o sistema de 8 pt.
  • O grid mobile usa 4 colunas, margem 16 px, gutter 16 px — grid de 8 pt na vertical.

🏆 Desafio

Sistema de cores para categorias

O FinView precisa de cores para cada categoria de transação: Alimentação, Transporte, Lazer, Saúde, Moradia, Assinaturas, Salário. Crie uma coleção Category/Colors com um token para cada categoria (fill + soft background), nos dois modos Light e Dark. Use a psicologia das cores: vermelho/laranja para gastos pesados, verde para receita, azul para lazer, etc. Ao final, construa um grid de categorias no Figma mostrando o ícone placeholder com o fundo colorido de cada categoria — como seria no seletor de categorias ao adicionar uma transação.

QuizTeste seu conhecimento

1. Qual é a diferença principal entre um token "primitive" e um token "semantic" no sistema de design?

  • Primitivos são para tipografia; semânticos são para cores
  • Primitivos têm suporte a dark mode; semânticos são fixos
  • Primitivos são valores brutos (ex.: violet/500 = #6C4CF1); semânticos têm significado contextual (ex.: color/brand/primary) e apontam para primitivos
  • Primitivos são criados pelos desenvolvedores; semânticos pelos designers
Primitivos são os valores brutos da paleta (a cor em si, sem contexto). Semânticos têm significado de uso e apontam para primitivos como aliases — isso permite trocar todo o sistema de cores alterando apenas os primitivos, sem tocar em nenhum elemento da tela.

2. Por que usamos múltiplos de 8 para espaçamentos em design mobile?

  • Porque telas retina (2x/3x) renderizam múltiplos de 8 sem frações de pixel, garantindo nitidez
  • Porque o Figma só aceita valores múltiplos de 8 em suas variáveis numéricas
  • Porque 8 pt é o tamanho mínimo de fonte legível em dispositivos iOS
  • É apenas uma convenção estética sem razão técnica
Em telas de alta densidade (Retina 2x, 3x), cada ponto virtual corresponde a 2 ou 3 pixels físicos. Múltiplos de 8 sempre resultam em números inteiros ao multiplicar por 2 ou 3, evitando anti-aliasing e garantindo bordas nítidas. Também cria um ritmo visual consistente.

3. No Figma 2025, qual recurso permite que um mesmo elemento mude todas as suas cores ao alternar entre Light e Dark com um único clique no frame pai?

  • Color Styles com suffixo "/dark"
  • Conditional logic em componentes
  • Múltiplas páginas com os mesmos frames
  • Variable Modes aplicados ao frame — todos os elementos usando semantic variables trocam de valor
Variable Modes é o mecanismo correto: quando você aplica um modo (Light ou Dark) em um frame, todos os elementos dentro dele que usam variables semânticas da coleção configurada trocam seus valores automaticamente. É o coração do dark mode dinâmico no Figma.
