Diretrizes iOS vs Android

Um app que parece nativo transmite qualidade e confiança. Nesta lição final do projeto você vai entender as diferenças fundamentais entre o Apple Human Interface Guidelines e o Material Design 3, e adaptar o FinView para que se sinta em casa em ambas as plataformas.

⏱️ Leitura: ~26 min 🎯 Nível: Projeto prático 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Identificar as principais diferenças de padrões de UX entre iOS (HIG) e Android (Material Design 3);
  • Adaptar a navegação, componentes e tipografia do FinView para cada plataforma;
  • Respeitar as safe areas, notches e Dynamic Island no iOS e a barra de status/gesto no Android;
  • Aplicar as áreas de toque mínimas (44 pt iOS / 48 dp Android) no design;
  • Organizar a page Android do arquivo Figma com os frames adaptados.

Por que as plataformas importam?

Usuários de iOS e Android passaram anos aprendendo padrões específicos de cada plataforma. Um usuário iOS espera tocar no canto superior esquerdo para voltar; um usuário Android usa um swipe a partir da borda. Ignorar esses padrões não é apenas uma questão estética — é uma questão de expectativa quebrada, o que gera confusão e abandono.

Apps de sucesso como o Nubank, Spotify e WhatsApp têm versões levemente diferentes para iOS e Android, respeitando as convenções nativas de cada plataforma enquanto mantêm a identidade visual da marca.

As bíblias de design mobile

Human Interface Guidelines (HIG) é o documento da Apple que define os padrões de design para iOS, macOS, watchOS e tvOS — disponível em developer.apple.com/design. Material Design 3 (M3) é o sistema da Google para Android e web — em m3.material.io. Ambos estão em constante evolução e são referências obrigatórias para qualquer designer mobile.

O Dynamic Island não é apenas decoração

O Dynamic Island no iPhone 14 Pro+ é uma área interativa que expande para mostrar notificações ao vivo (timer, música, Uber, etc.). No design, isso significa: (1) nunca coloque botões críticos diretamente sob o Dynamic Island; (2) considere como seu app se integra com Live Activities se relevante; (3) a ilha pode expandir durante o uso do app, deslocando levemente o conteúdo abaixo. No FinView, o header da Home está a 8 pt abaixo da ilha por segurança.

Áreas de toque mínimas

Telas touchscreen têm uma limitação física: o dedo humano tem uma área de contato de 10–14 mm. Elementos muito pequenos são difíceis de tocar com precisão. Por isso, ambas as plataformas definem tamanhos mínimos:

PlataformaTamanho mínimo de toqueRecomendado
iOS (HIG)44×44 pt44×44 pt a 60×60 pt para ações críticas
Android (Material)48×48 dp48×48 dp, com 4 dp de espaçamento entre elementos tocáveis
Web (WCAG)24×24 px (mínimo), 44×44 px (recomendado)48×48 px para WCAG 2.5.5 AAA

No FinView, isso significa:

  • O ícone de 24 pt da Tab Bar fica dentro de um "tap target" invisível de 44×44 pt.
  • Os botões de ação sempre têm pelo menos 44 pt de altura (usamos 48 pt como padrão).
  • Os itens da lista têm 64 pt de altura — bem acima do mínimo.
  • O botão de fechar (X) em sheets tem 44×44 pt mesmo que o X visual seja apenas 20 pt.
Como verificar tap targets no Figma

Use o plugin Accessibility Checker ou A11y - Color Contrast Checker para auditar tap targets automaticamente. Para verificar manualmente: no frame, use o plugin Measure ou o Inspect mode para medir elementos. Outra técnica: crie um frame de 44×44 pt como guia e sobreponha sobre o elemento para verificar visualmente se a área de toque é suficiente.

Adaptando o FinView para Android

Com base em tudo que vimos, aqui está o checklist de adaptações para a page Android do FinView:

  1. Crie frames Android na page 🤖 Android — Telas. Use o preset Android Small (360×800 dp) ou Pixel 8 (393×851 dp). Duplique os frames iOS como base e redimensione.
  2. Adapte o Header: centralizado → alinhado à esquerda. Na versão Android, o título do header (ex.: "Transações") fica alinhado à esquerda com padding 16 dp. O botão voltar fica à esquerda também, mas sem o texto "← Voltar" — apenas a seta. As ações ficam empilhadas em um menu de 3 pontos (⋮) à direita.
  3. Adapte a Tab Bar para Navigation Bar Material. O item ativo no Android M3 usa um pill highlight (oval colorido) em torno do ícone, sem label em alguns casos. Ajuste o componente Tab Bar Item para ter a variante Android com o pill.
  4. Substitua o botão "+" central por um FAB. No Android, o padrão para a ação principal de adicionar é o FAB (Extended ou padrão). Adicione um FAB no canto inferior direito da Home Android: 56×56 dp, corner radius 16 dp, ícone + (ou Extended FAB com ícone + "Nova transação").
  5. Adapte os botões para o formato Material. Botão primário: corner radius 100 dp (pill). Botão secundário: Outlined Button com borda e radius 100 dp. Todos os botões têm height 40 dp (mais compacto que os 48 pt do iOS).
  6. Ajuste a status bar. No Android, a barra de status tem 24 dp de altura (sem Dynamic Island). Remova o componente de Dynamic Island e substitua por uma status bar simples com hora, rede e bateria.
  7. Verifique o home indicator bottom padding. Adicione 16 dp de padding na base da Tab Bar para respeitar a gesture bar do Android.
  8. Adicione a variante ripple ao botão. O ripple effect (onda que se expande do ponto de toque) é o feedback visual padrão do Android. No Figma, crie uma variante State=Pressed do botão com um círculo de raio expandido em branco 20% de opacidade centralizado no centro — simula visualmente o ripple.
Trabalhe com Design Tokens para facilitar a adaptação

O motivo pelo qual o FinView usa Variables semânticas desde a Lição 3 é exatamente este: ao criar a página Android, você reutiliza os mesmos tokens de cor, espaçamento e tipografia. A adaptação se resume às diferenças de padrão de componente (radius, alinhamento), não aos valores de cor. Em times grandes, a versão Android e iOS de um app compartilham o mesmo design token package — apenas as "receitas" de como montar os componentes diferem.

Resumo

  • iOS e Android têm padrões de UX distintos: tab bar vs. navigation bar, título centralizado vs. alinhado à esquerda, botão pill (Android) vs. retangular arredondado (iOS).
  • A adaptação do FinView para Android envolve: header à esquerda, NAV bar com pill indicator, FAB em vez de "+" central, botões pill e ripple feedback.
  • Áreas de toque mínimas: 44×44 pt (iOS) e 48×48 dp (Android) — sempre respeite, mesmo quando o elemento visual é menor.
  • Safe areas variam por plataforma e modelo: Dynamic Island (54–62 pt) no iOS mais recente vs. status bar simples (24 dp) no Android.
  • O uso de Design Tokens (variables) desde o início facilita a adaptação entre plataformas — apenas os padrões de componente mudam, não as cores e espaçamentos.

Adaptar a Home para Android

Na page 🤖 Android — Telas do seu arquivo:

  1. Crie um frame Android (360×800 dp ou 393×851 dp).
  2. Adapte a Home do FinView com: status bar de 24 dp, title à esquerda, Navigation Bar com pill indicator, FAB no canto inferior direito e botão de nova transação no formato pill (radius 100).
  3. Crie as variantes Android dos components Button e Header com as specs do Material Design 3.
  4. Coloque as versões iOS e Android lado a lado na canvas para comparação visual.
Critério de sucesso: ao olhar as versões iOS e Android lado a lado, as diferenças de plataforma são claras (título, botão, FAB, nav indicator) enquanto a identidade visual do FinView (paleta, tipografia Inter, tokens) é mantida consistente nos dois.
🏆 Desafio

Auditoria completa de acessibilidade

Faça uma auditoria de acessibilidade do seu arquivo FinView com foco em três áreas: (1) Contraste de cor — verifique que todos os textos têm ratio mínimo 4.5:1 (AA) em ambos os modos com uma ferramenta de contraste; (2) Tap targets — audite todos os elementos interativos e confirme que nenhum tem área de toque abaixo de 44×44 pt; (3) Acessibilidade para leitores de tela — no Dev Mode do Figma, adicione labels de acessibilidade (accessibility annotations) em todos os elementos interativos e imagens decorativas. Documente as falhas encontradas e as correções aplicadas em um frame na page de Handoff Notes. Esse tipo de auditoria é o que separa um design "bonito" de um design profissional e inclusivo.

QuizTeste seu conhecimento

1. Qual é a principal diferença visual entre um botão primário iOS e um botão primário Android (Material Design 3)?

  • iOS usa fundo sólido; Android usa borda sem fundo
  • iOS usa fonte SemiBold; Android usa fonte Bold
  • iOS tem cantos levemente arredondados (10–14 pt); Android usa pill (radius 100 dp)
  • iOS tem sombra; Android não tem nenhum tratamento de elevação
O botão primário iOS tem cantos moderadamente arredondados (8–14 pt de radius), enquanto o Material Design 3 usa o formato pill (radius tão alto que resulta em cápsulas arredondadas). Essa diferença de forma é um dos sinais mais imediatos de que um app "parece nativo" ou "parece genérico" em cada plataforma.

2. Qual é a área de toque mínima recomendada pela Apple Human Interface Guidelines?

  • 44×44 pt
  • 24×24 pt
  • 48×48 pt
  • 36×36 pt
A Apple HIG especifica 44×44 pt como a área de toque mínima para elementos interativos. O Android Material Design usa 48×48 dp. Ambos estão alinhados com as diretrizes de acessibilidade WCAG para interfaces touch. Um elemento visual menor pode ter um tap target maior (frame transparente) para cumprir esse requisito.

3. Qual é o padrão Android equivalente ao botão "+" centralizado na Tab Bar do iOS do FinView?

  • Um item especial com ícone diferente no centro da Navigation Bar
  • Um Action Sheet acessível pelo menu ⋮
  • Um item de menu no Top App Bar
  • Um FAB (Floating Action Button) posicionado fora da Navigation Bar, no canto inferior direito
No Material Design, a ação principal de uma tela é representada pelo FAB — um botão circular (56×56 dp) ou estendido que fica sobre o conteúdo, no canto inferior direito. Colocar uma ação de "adicionar" como item central da Navigation Bar não é um padrão Android e parecerá "fora do lugar" para usuários Android. O FAB é o componente correto para essa finalidade.
