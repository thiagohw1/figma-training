Componentização do app

Um design system real não é uma coleção de telas — é uma biblioteca de peças reutilizáveis. Nesta lição você vai transformar os elementos das telas do FinView em Components com Variants e Properties, criando uma base que escala sem retrabalho.

⏱️ Leitura: ~26 min 🎯 Nível: Projeto prático 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Criar componentes com Variants e Component Properties no Figma;
  • Construir a Tab Bar, o Card de Saldo, o List Item de Transação, o Botão e o Header como components;
  • Usar as propriedades Text, Boolean (visible) e Instance Swap para flexibilizar components;
  • Reaproveitar os components nas telas da page iOS;
  • Organizar a page de Components com a hierarquia Atomic Design.

Por que componentizar?

Imagine que o FinView tem 40 itens de transação espalhados por 5 telas. Se você precisar alterar a altura de cada item de 64 para 72 px, sem componentes você editaria 40 instâncias manualmente. Com um componente, você muda o master uma vez e todas as 40 instâncias se atualizam instantaneamente.

Mas a vantagem vai além da velocidade. Components com Variants permitem que um único "Item de Transação" seja: receita ou despesa, com ou sem nota, compacto ou expandido. E Component Properties tornam cada instância configurável sem entrar na edição interna.

Component Properties vs. Variants — quando usar cada um

Variants são melhores para variações discretas que mudam a estrutura visual do componente (ex.: Size=Small/Medium/Large, State=Default/Active/Disabled). Component Properties (Text, Boolean, Instance Swap) são melhores para personalizar o conteúdo sem mudar a estrutura: trocar o label, mostrar/ocultar um elemento, trocar um ícone. Para o FinView, usaremos ambos em conjunto.

Passo a passo: criando o Transaction List Item

O List Item de Transação é o component mais usado no FinView — aparece na Home, na tela de Metas e em buscas. Vamos criá-lo com todas as properties:

  1. Vá para a page de Components. Na page 🧩 Components, crie uma Section (Shift + S) chamada "Transaction / List Item". Esta será nossa área de trabalho.
  2. Construa o layout base do item. Crie um Auto Layout horizontal (Shift + A): width 390, height hug, padding 16×12, gap 12, align center. Dentro:
    • Frame de ícone: 44×44, corner radius radius/md (12), fill color/brand/soft. Dentro, um emoji ou ícone centralizado.
    • Auto Layout vertical (flex-1): texto "iFood" (text/body bold, color/text/primary) + texto "Alimentação · Hoje" (text/caption, color/text/secondary).
    • Auto Layout vertical (align end): texto "- R$ 54,90" (text/body-lg bold, color/expense) + texto "13:42" (text/caption, color/text/secondary).
  3. Crie o componente master. Selecione o Auto Layout inteiro e pressione Ctrl/⌘ + Alt/⌥ + K para criar o componente. Renomeie para Transaction/List Item.
  4. Adicione as Component Properties. Com o componente master selecionado, clique em Add property no painel direito. Adicione:
    • Name (Text) — vinculado ao texto "iFood"
    • Category (Text) — vinculado a "Alimentação · Hoje"
    • Amount (Text) — vinculado a "- R$ 54,90"
    • Show Time (Boolean) — controla a visibilidade do texto "13:42"
    Para vincular, selecione o layer de texto dentro do component e, no painel, clique em "Apply property" para conectar a propriedade de texto.
  5. Crie as Variants. Selecione o componente master e clique em Add variant (ícone de losango roxo no painel). Isso cria um Component Set. Agora você tem dois items: modifique o segundo para ser uma receita (Income): mude o ícone para 💰, o texto do valor para "+ R$ 5.000,00" e a cor do valor para color/income. Selecione os dois no Component Set, clique no campo de Variant e nomeie: Type=Expense e Type=Income.
  6. Adicione a variante Compact. Duplique a variante Expense e reduza o padding vertical para 8 px, removendo o texto de horário. Nomeie como Type=Expense, Size=Compact. Repita para Income. Você terá 4 variantes no total.
  7. Teste o component em uma tela. Vá para a page 📱 iOS — Telas, abra a Home e selecione um dos itens de transação que você construiu na Lição 4. Delete-o e, no painel de Assets (Alt/⌥ + 2), arraste uma instância do Transaction/List Item para o lugar. Altere as properties Name, Amount e Type no painel direito — sem entrar no componente.
  8. Substitua todos os itens da lista. Repita o processo para os outros 4 itens da lista na Home. Agora você tem uma lista real de components — se alterar o master, todas as instâncias se atualizam.
Atalho para criar componente

Ctrl/⌘ + Alt/⌥ + K transforma a seleção em componente. Para criar uma cópia do componente como instância (não editar o master), use Ctrl/⌘ + D ou arraste do painel Assets. Para voltar ao master a partir de uma instância, clique com o botão direito → Go to main component.

Construindo a Tab Bar

A Tab Bar é o elemento de navegação principal do FinView. Cada item da tab é um sub-component com variant State=Default/Active. A tab bar em si é um component que agrupa 5 instâncias do Tab Item:

  1. Crie o componente Tab Bar Item. Auto Layout vertical, gap 4, padding 8×10: ícone (frame 24×24 com SVG ou emoji) + texto label (text/caption). Variante Default: ícone e texto em color/text/secondary. Variante Active: ícone e texto em color/brand/primary, com um indicador de bolinha acima do ícone (frame 4×4, fill primary, opacity 100%).
  2. Crie o component Tab Bar. Auto Layout horizontal, width 390, height 83, padding bottom 16 (safe area do iOS), gap Auto. Arraste 5 instâncias de Tab Bar Item. Defina uma propriedade de Instance Swap chamada Active Tab para controlar qual item está ativo.
  3. Adicione Instance Swap Properties para os ícones. Cada Tab Item pode ter seu ícone trocado via Instance Swap. Isso permite usar o mesmo component em contextos diferentes (ex.: uma tab bar de admin com ícones diferentes).
Nested components: componente dentro de componente

Componentes podem conter outras instâncias de componentes — isso é chamado de nested components. A Tab Bar contém 5 Tab Items; o Tab Item contém um ícone. Quando você altera o Tab Item master, todos os Tab Bars que usam instâncias dele se atualizam. Essa hierarquia espelha exatamente como o desenvolvimento funciona (React: componente-pai usa filhos), tornando o handoff muito mais fácil.

Construindo o Header

O Header aparece em quase todas as telas secundárias do FinView. Ele precisa ser flexível: às vezes tem botão de voltar, às vezes apenas um título, às vezes com ação secundária (ícone de configurações, etc.).

Organizando a page de Components

Na page 🧩 Components, use Sections para organizar os components por tipo. Uma convenção comum inspirada no Atomic Design:

  • Atoms: Icon, Avatar, Badge, Chip — elementos indivisíveis
  • Molecules: Button, Input, Tab Bar Item, List Item — combinações simples
  • Organisms: Tab Bar, Header, Balance Card, Transaction List — combinações complexas

Dentro de cada Section, organize os Component Sets lado a lado com espaço de 40 px entre eles. Adicione labels (text frames) acima de cada set identificando o nome e o número de variantes.

Não componentize tudo de imediato

Um erro comum é passar horas criando componentes de coisas que aparecem uma única vez. A regra prática: se um elemento aparece 3 ou mais vezes no projeto ou é provável que mude frequentemente, crie um componente. Caso contrário, deixe como frame comum por ora. Componentização excessiva aumenta a complexidade sem benefício real.

Reaproveitando na page iOS

Com a biblioteca montada, volte para a page 📱 iOS — Telas e substitua os elementos "soltos" pelos components criados:

  1. Abra o painel de Assets (Alt/⌥ + 2) e busque os components pelo nome.
  2. Arraste instâncias para as posições corretas nos frames de tela.
  3. Configure as properties de cada instância (label, variante, booleans) no painel direito — sem entrar dentro do componente.
  4. Confira que todas as telas usam a mesma Tab Bar component — ao alterar o master, todas as telas se atualizam.

Resumo

  • Components com Variants e Properties tornam o design system escalável — uma mudança no master propaga para todas as instâncias.
  • O Transaction List Item foi construído com 4 variantes (Expense/Income × Default/Compact) e 5 properties (Name, Category, Amount, Date, Show Time).
  • O Botão tem 3 tipos (Primary, Secondary, Ghost), 3 tamanhos e 3 estados, com properties de Label, Icon Left e Icon Right.
  • A Tab Bar usa nested components: 5 instâncias de Tab Bar Item dentro de um Tab Bar master.
  • Organizar a page de Components com Atomic Design (Atoms → Molecules → Organisms) mantém a biblioteca navegável.

QuizTeste seu conhecimento

1. Qual é a diferença prática entre Variants e Component Properties no Figma?

  • Variants são para mobile; Component Properties são para web
  • Variants mudam o conteúdo de texto; Component Properties mudam a estrutura visual
  • Variants mudam a estrutura/layout do componente; Component Properties personalizam conteúdo sem alterar estrutura
  • São a mesma coisa com nomes diferentes
Variants existem para variações que afetam a estrutura visual (tamanho, layout, estado visual). Component Properties (Text, Boolean, Instance Swap) permitem personalizar o conteúdo de uma instância específica sem criar uma variante nova — ex.: mudar o label de um botão sem criar um variant separado para cada texto possível.

2. Quando você altera o componente master (principal), o que acontece com as instâncias usadas nas telas?

  • Todas as instâncias que não tiveram substituições locais se atualizam automaticamente
  • Apenas instâncias na mesma page do master se atualizam
  • Nenhuma instância se atualiza — é preciso substituir manualmente
  • Todas as instâncias se atualizam, incluindo as que tiveram substituições locais
Quando o master muda, todas as instâncias que não têm sobrescritas (overrides) locais naquela propriedade se atualizam. Se uma instância já tem um texto diferente do master (override), essa propriedade específica não é sobrescrita — o Figma preserva customizações locais.

3. O que são "nested components" (componentes aninhados)?

  • Componentes que estão dentro de outros frames, não de components
  • Componentes que contêm instâncias de outros componentes em sua estrutura interna
  • Componentes que só funcionam em uma única tela do projeto
  • Componentes duplicados dentro do mesmo arquivo
Nested components são componentes que usam instâncias de outros componentes internamente — como a Tab Bar que contém 5 Tab Items. Essa hierarquia espelha o desenvolvimento (React com componentes filhos) e permite que mudanças no componente filho se propaguem para todos os pais que o usam.
