Aliases, scoping e organização

Aliases constroem a ponte entre tokens primitivos e semânticos diretamente no Figma. Scoping garante que cada variable apareça somente nos seletores onde faz sentido — mantendo o painel limpo e a equipe produtiva.

⏱️ Leitura: ~20 min 🎯 Nível: Avançado 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Criar aliases — variables que apontam para outras variables — para montar tokens semânticos;
  • Configurar o Scoping de uma variable para limitar onde ela aparece nos seletores do painel;
  • Configurar Code Syntax para web (CSS), iOS e Android;
  • Conhecer as novidades de composite/array variables (2025);
  • Aplicar boas práticas de organização de Collections em um arquivo de Design System.

O que são Aliases?

Um alias é uma variable cujo valor aponta para outra variable ao invés de armazenar um valor bruto. É exatamente assim que o Tier 2 (semântico) e o Tier 3 (componente) da hierarquia de tokens são implementados no Figma.

Ao clicar no campo de valor de uma variable e usar o ícone de grid para selecionar outra variable (ao invés de digitar um valor direto), você está criando um alias.

Alias = referência, não cópia

Quando color/bg/brand aponta para color/blue/500, o Figma não copia o valor — ele cria uma referência. Se color/blue/500 mudar de #6C4CF1 para #1D6FD1, o color/bg/brand atualiza automaticamente sem nenhuma ação manual.

Criando aliases na prática

  1. Abra a Collection semântica. No painel de Variables, selecione a Collection Semantic/Color. Se ela não existir, crie-a conforme a lição anterior.
  2. Crie uma nova variable. Adicione uma variable Color chamada color/bg/brand. Por padrão, ela pede um valor de cor.
  3. Ative o modo de seleção de variable. Em vez de clicar no swatch de cor para digitar um hex, clique no ícone de grid (4 quadradinhos) que aparece à direita do campo de valor. O painel troca para o seletor de variables existentes.
  4. Selecione a variable primitiva. Navegue até Primitives/Color → blue → 500. Clique para confirmar o alias.
  5. Verifique o resultado. A variable color/bg/brand agora mostra um ícone de seta indicando que ela é um alias — e herda o valor atual de color/blue/500. Se você alterar o primitivo, o semântico atualiza junto.
  6. Repita para o Mode Dark. No Mode Dark de color/bg/brand, selecione o alias para color/blue/400 (um tom mais claro, pois no dark mode cores primárias costumam ser mais claras para manter contraste). Agora o semântico tem aliases diferentes por Mode.
Aliases entre Collections diferentes

No Figma, aliases podem cruzar Collections. Uma variable em Semantic/Color pode apontar para uma variável em Primitives/Color. Esta é exatamente a forma de montar a arquitetura de tiers — Collections separadas por nível de abstração com aliases conectando-as.

Scoping — controlando onde a variable aparece

Scoping define em quais propriedades e seletores do painel uma variable aparece quando o designer a procura. Sem scoping, uma variable de cor de fundo apareceria nos campos de stroke, de texto e de todos os outros seletores de cor — criando ruído e confusão.

Para configurar o scoping de uma variable, clique com o botão direito nela e escolha Edit Variable. Na janela que abre, há uma seção Scoping com checkboxes:

Scoping reduz erros

Se um designer aplicar por engano um token de color/text/default no fundo de um botão, ele terá aplicado o token errado — e pode ser que ninguém perceba no tema claro, mas vai criar um bug no dark mode. Com scoping correto, color/text/default só aparece nos seletores de texto, tornando o erro impossível de acontecer.

Code Syntax — conectando tokens ao código

O Figma permite configurar o Code Syntax de cada variable — ou seja, como o nome do token aparece nas diferentes plataformas de código. Isso facilita o handoff para desenvolvedores que trabalham com CSS, Swift (iOS) ou Kotlin (Android).

Para acessar, clique com o botão direito → Edit Variable → seção Code Syntax:

PlataformaConvençãoExemplo para color/bg/brand
Web (CSS) kebab-case com -- prefix --color-bg-brand
iOS (Swift) camelCase colorBgBrand
Android (Kotlin/XML) snake_case com prefixo color_bg_brand

No Dev Mode, quando um desenvolvedor inspecionar um elemento que usa uma variable com Code Syntax configurado, ele verá o nome no formato correto para a plataforma selecionada — sem precisar fazer a conversão manualmente.

Plugins de exportação de tokens

Ferramentas como Tokens Studio for Figma (antigo Figma Tokens), Style Dictionary e Theo exportam tokens como arquivos JSON, CSS, Swift ou Kotlin. O Code Syntax configurado no Figma alimenta diretamente esses exports, garantindo naming consistente no código.

Composite e Array variables (novidade 2025)

Em 2025, o Figma introduziu suporte experimental a composite variables — variables que agregam múltiplos valores em uma única entidade, similar a como um Text Style combina família, tamanho, peso e entrelinha.

Um exemplo de composite seria um token de sombra que agrega blur, spread, offset X/Y e cor — todos controláveis como uma unidade. Outro seria um token de tipografia que combina font-size, line-height e font-weight.

Na data de escrita (2025/2026), composite variables estão em beta e disponíveis apenas para alguns planos. Verifique o changelog oficial do Figma para o estado atual desse recurso.

Boas práticas de organização de Collections

Estrutura recomendada

Use Collections separadas por nível de abstração e tipo de valor. Uma estrutura sólida para um DS de médio porte:

CollectionConteúdoModes
Primitives/ColorPaleta completa de cores brutas (azul 50–900, verde, vermelho, neutros)Apenas 1 (sem Mode)
Primitives/NumberEscala de espaçamento (4, 8, 12, 16…) e scale de font-sizeApenas 1
Semantic/ColorTokens semânticos de cor (bg/surface, text/default, border/default, feedback/…)Light, Dark (+ High Contrast opcional)
Semantic/SpacingSpacing semântico (component/sm, component/md, layout/section)Comfortable, Compact
Semantic/RadiusRadius semântico (button, input, card, chip)Mobile, Desktop (opcional)
BrandCores de marca de cada cliente (somente para white label)Brand A, Brand B…
ContentStrings de conteúdo (somente se multilíngue)pt-BR, en-US…

Dicas de organização dentro de Collections

  • Use grupos (/) para criar hierarquias claras: color/bg/brand, não colorBgBrand.
  • Mantenha primitivos e semânticos em Collections separadas — nunca misture os dois níveis na mesma Collection.
  • Nomeie Modes com nomes descritivos e consistentes ("Light"/"Dark", não "Mode 1"/"Mode 2").
  • Adicione descrições nas variables (campo Description na janela Edit Variable) para documentar o propósito de cada token.
  • Revise e limpe Collections periodicamente — tokens obsoletos criam confusão.
Evite a proliferação de Collections

É tentador criar uma Collection para cada micro-categoria, mas isso fragmenta demais e torna o painel difícil de navegar. Comece com 3–5 Collections e só crie novas quando o motivo for claro (ex: multi-brand realmente justifica uma Collection separada).

Exemplo de uso real

O Design System do produto de fintech "Paggo" tem a seguinte estrutura de Collections:

  • Primitives/Color — 120 tokens de cor (4 famílias × 10 tons + neutros);
  • Semantic/Color com Modes Light e Dark — 32 tokens semânticos, todos aliases para primitivos;
  • Semantic/Spacing com Modes Comfortable e Compact — 12 tokens;
  • Semantic/Radius — 6 tokens (button, input, card, chip, modal, avatar);

Total: menos de 200 tokens bem organizados cobrem 100% das necessidades visuais do produto. O Code Syntax está configurado para web e iOS. Ao exportar com Tokens Studio, o output é um JSON com os tokens completos que alimenta o repositório de código.

Resumo

  • Aliases são variables que apontam para outras variables — a forma de criar tokens semânticos que referenciam primitivos.
  • Ao mudar um primitivo, todos os semânticos (aliases) que apontam para ele atualizam automaticamente.
  • Scoping limita onde uma variable aparece nos seletores, evitando erros de aplicação incorreta.
  • Code Syntax configura como o token aparece no Dev Mode para CSS, iOS e Android.
  • Composite variables (2025) permitem agregar múltiplos valores em um único token.
  • Separe primitivos e semânticos em Collections diferentes; use grupos com (/) para hierarquia.
✍️ Exercício

Monte a cadeia de aliases

  1. Com a Collection Primitives/Color já criada (lição anterior), crie a Collection Semantic/Color com Modes Light e Dark;
  2. Crie 8 tokens semânticos usando aliases para os primitivos: color/bg/surface, color/bg/subtle, color/bg/brand, color/text/default, color/text/muted, color/border/default, color/feedback/danger, color/feedback/success;
  3. Configure o Scoping de color/text/default para aparecer apenas em "Text fill";
  4. Configure o Code Syntax de pelo menos 3 tokens para web CSS.
Critério de sucesso: ao tentar aplicar color/text/default a um fill de retângulo, ela não aparece na lista. Ao inspecionar um texto no Dev Mode com essa variable, o nome CSS configurado aparece corretamente.
🏆 Desafio

Auditoria de tokens em um arquivo real

Abra um arquivo Figma de um projeto existente (seu ou da comunidade). Identifique todos os valores de cor "hardcoded" (sem variable aplicada) em componentes e frames. Calcule quantos valores únicos existem. Proponha uma arquitetura de tokens com primitivos e semânticos para substituir todos esses valores — e estime quantos tokens primitivos e semânticos você precisaria criar. Documente a proposta em uma página dedicada do arquivo.

QuizTeste seu conhecimento

1. O que é um alias no contexto de Variables do Figma?

  • Um segundo nome para uma variable dentro de uma Collection
  • Um Mode alternativo de uma variable
  • Uma variable cujo valor aponta para outra variable ao invés de armazenar um valor bruto
  • Um atalho de teclado personalizado para variáveis frequentes
Um alias é uma referência: uma variable que aponta para outra. Quando o primitivo muda, o alias atualiza automaticamente — essa cadeia de referências é o que torna a hierarquia de tokens eficiente.

2. Para que serve o Scoping de uma variable?

  • Para esconder a variable de outros designers do time
  • Para limitar em quais propriedades (Fill, Stroke, Text, etc.) a variable aparece quando o designer está escolhendo um valor
  • Para definir em quais arquivos a variable é visível
  • Para proteger a variable contra alterações acidentais
O Scoping filtra onde a variable aparece nos seletores do painel. Uma variable de color/text/default com scope "Text fill" não aparecerá ao tentar aplicar uma cor a um retângulo — prevenindo erros de uso.

3. Qual é a convenção de nomenclatura recomendada para Code Syntax de tokens em CSS?

  • kebab-case com prefixo --, ex: --color-bg-brand
  • camelCase sem prefixo, ex: colorBgBrand
  • UPPER_SNAKE_CASE, ex: COLOR_BG_BRAND
  • PascalCase, ex: ColorBgBrand
CSS Custom Properties (variáveis CSS) usam kebab-case com o prefixo --. Essa é a convenção padrão adotada por Material, Carbon, Polaris e a maioria dos Design Systems modernos.
