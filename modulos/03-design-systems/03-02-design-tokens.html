Design Tokens — teoria e tiers

Design tokens são a camada que transforma valores brutos de design em variáveis nomeadas e reutilizáveis — a cola que une o Figma ao código e garante que uma decisão de design se propague por toda a plataforma com um único clique.

⏱️ Leitura: ~20 min 🎯 Nível: Avançado 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Explicar o que são design tokens e por que eles existem;
  • Diferenciar os três tiers: primitivo/global, semântico/alias e específico de componente;
  • Criar uma nomenclatura coerente e escalável para tokens;
  • Traçar o caminho de um token do valor bruto até a propriedade de um componente;
  • Justificar por que a hierarquia em tiers evita retrabalho em atualizações de tema.

O que são design tokens?

Um design token é uma variável nomeada que armazena um valor de design — uma cor, um tamanho de fonte, um espaçamento, um raio de borda, uma sombra. Em vez de usar o valor bruto #6C4CF1 ou 16px diretamente em toda parte, você usa o nome color.brand.primary ou spacing.md.

Parece uma distinção sutil, mas a diferença é enorme. Quando você precisa mudar a cor primária da marca, não precisa caçar todos os lugares onde usou #6C4CF1: basta atualizar o token color.brand.primary uma única vez e tudo se propaga.

Tokens são a língua franca do Design System

Um token tem o mesmo nome no Figma (Variables), no CSS (var(--color-brand-primary)), no iOS (Color.brandPrimary) e no Android (@color/brand_primary). Essa consistência entre plataformas é o superpoder dos tokens.

Por que a hierarquia de tiers?

O maior erro de quem começa com tokens é tentar fazer tudo em uma camada só. "Vou chamar de button-background-color e pronto." Isso parece simples, mas gera um problema: você tem centenas de tokens de componente que não se conversam entre si, e quando a paleta muda, você ainda precisa atualizar dezenas deles.

A solução é a arquitetura em três tiers (camadas/níveis), onde cada token de nível superior aponta para o de nível inferior:

Cada tier aponta para o anterior. Para mudar a cor da marca inteira, basta alterar o Tier 1.

Tier 1 — Tokens Primitivos (Global Tokens)

Os tokens primitivos são os valores brutos nomeados. Eles não carregam nenhum contexto de uso — apenas dizem "esta cor existe com este valor". Exemplos:

  • color.blue.50 → #EEF2FF
  • color.blue.500 → #6C4CF1
  • color.blue.900 → #1E0A5A
  • color.neutral.0 → #FFFFFF
  • color.neutral.1000 → #000000
  • size.4 → 4px
  • size.8 → 8px
  • size.16 → 16px

Pense nos primitivos como a paleta de tinta completa do pintor. Todas as cores existem, mas ainda não sabemos para quê cada uma vai ser usada.

Nomenclatura de primitivos

Para cores, use escalas numéricas (50, 100, 200 … 900) como o Tailwind ou o Material. Para espaçamento, use os valores em px diretamente (size.4, size.8, size.16…). Consistência na nomenclatura facilita muito a vida do time.

Tier 2 — Tokens Semânticos (Alias Tokens)

Os tokens semânticos apontam para primitivos e carregam intenção de uso. Em vez de dizer "azul 500", dizem "cor de fundo de elementos de marca" ou "cor de texto em superfícies de destaque". Exemplos:

O segredo dos tokens semânticos é a troca de tema. Para um tema escuro, basta fazer color.bg.surface apontar para color.neutral.900 ao invés de color.neutral.0. Todos os componentes que usam color.bg.surface mudam automaticamente — sem tocar em nenhum componente.

A regra de ouro dos tokens semânticos

Um token semântico deve ser nomeado pelo seu propósito, não pela sua aparência. color.bg.brand é correto. color.purple-for-buttons é errado — acopla o nome ao visual e impede reutilização.

Tier 3 — Tokens de Componente

Os tokens de componente são específicos de um componente e apontam para semânticos (ou, em casos raros, direto para primitivos). Eles permitem que um componente individual customize seu visual sem quebrar o sistema.

Os tokens de componente podem parecer excessivos no início, mas eles permitem um nível de customização muito mais limpo. Se um cliente enterprise quiser que o botão primário dele seja verde ao invés do roxo padrão, você muda apenas button.bg.primary para apontar para color.green.600 — sem tocar na estrutura de componente.

Nomenclatura de tokens — boas práticas

A convenção mais adotada é o ponto como separador com hierarquia de categoria → grupo → variante → estado:

categoria.grupo.variante.estado
color.bg.brand.hover
spacing.layout.section.top
typography.body.md.lineHeight
ParteO que representaExemplos
CategoriaO tipo do tokencolor, spacing, typography, radius, shadow
GrupoO contexto/subfamíliabg, text, border, component, layout
VarianteA variante específicabrand, muted, danger, sm, md, lg
EstadoO estado interativo (opcional)hover, active, focus, disabled
Evite nomes ambíguos ou ligados ao visual

Tokens como bluePrimary, darkGray ou bigPadding criam problemas no futuro. bluePrimary não pode mais ser renomeado quando a marca mudar para verde. Prefira sempre nomes semânticos: color.bg.brand, color.text.muted, spacing.layout.section.

Por que essa hierarquia evita retrabalho

Considere este cenário: o rebranding da empresa muda a cor primária de roxo (#6C4CF1) para azul (#1D6FD1). Veja o trabalho necessário em cada arquitetura:

ArquiteturaO que precisa mudarRisco
Sem tokens (valores diretos) Caçar e substituir #6C4CF1 em todos os componentes, protótipos e exportações CSS Altíssimo — é fácil esquecer instâncias
Apenas tokens de componente (sem hierarquia) Atualizar button.bg.primary, badge.bg.default, tab.bg.active, chip.bg.selected… Alto — dezenas de tokens de componente
Hierarquia de tiers (primitivo → semântico → componente) Atualizar um único primitivo: color.blue.500 de #6C4CF1 para #1D6FD1 Mínimo — tudo se propaga em cascata

Exemplo de uso real

O IBM Carbon Design System publica seus tokens abertamente. O token $interactive-01 (semântico) aponta para $blue-60 (primitivo) no tema White, mas aponta para $blue-50 no tema Dark — permitindo múltiplos temas sem alterar nenhum componente.

O Shopify Polaris segue a mesma lógica: --p-color-bg-primary (semântico) → --p-color-green-700 (primitivo), e para o tema Partner (rosa), apenas o primitivo de destaque muda.

Resumo

  • Tokens são variáveis nomeadas que armazenam valores de design e têm o mesmo nome no Figma e no código.
  • Tier 1 — Primitivos: valores brutos nomeados (color.blue.500 = #6C4CF1).
  • Tier 2 — Semânticos: apontam para primitivos e carregam intenção (color.bg.brand → color.blue.500).
  • Tier 3 — Componente: específicos de um componente, apontam para semânticos (button.bg.primary → color.bg.brand).
  • A hierarquia em tiers significa que para trocar a paleta inteira, muda-se apenas o Tier 1.
  • Nomes semânticos (pelo propósito) são muito mais escaláveis do que nomes visuais.
✍️ Exercício

Projete tokens para um produto real

Escolha um produto com pelo menos duas cores de destaque (primária e feedback de sucesso/erro). Crie uma tabela no Figma (ou no papel) com:

  1. Pelo menos 6 tokens primitivos de cor (escala do azul/verde/vermelho que você escolheu);
  2. Pelo menos 4 tokens semânticos que apontem para os primitivos, cobrindo: fundo de marca, texto padrão, borda default, feedback de erro;
  3. Pelo menos 3 tokens de componente para um botão primário (bg, text, border).
Critério de sucesso: se a cor primária da marca mudar, você consegue identificar exatamente um token primitivo para atualizar — e todos os semânticos e de componente se propagam sem mais alterações.

QuizTeste seu conhecimento

1. Qual é a principal vantagem de usar tokens semânticos ao invés de tokens primitivos diretamente nos componentes?

  • Tokens semânticos têm nomes mais curtos e são mais rápidos de digitar
  • Permitem trocar o tema inteiro (ex: light→dark) mudando apenas o mapeamento dos semânticos para primitivos, sem tocar em componentes
  • Tokens semânticos suportam valores animados, os primitivos não
  • São obrigatórios para exportar tokens para o código
Tokens semânticos carregam intenção (color.bg.brand), não aparência. Ao trocar de tema, basta remapear o semântico para outro primitivo — todos os componentes que usam esse semântico atualizam automaticamente.

2. No exemplo color.blue.500 → color.bg.brand → button.bg.primary, o que representa color.blue.500?

  • Um token semântico de fundo
  • Um token de componente
  • Um token primitivo com o valor bruto da cor
  • Um alias de outro token semântico
color.blue.500 é um token primitivo — armazena o valor bruto (#6C4CF1) sem nenhuma intenção de uso. Ele é a base da hierarquia.

3. Por que o token color.purple-brand é considerado uma má prática de nomenclatura?

  • É muito longo para ser digitado no código
  • O Figma não suporta hifens em nomes de tokens
  • Mistura a categoria (color) com o nível de variante de forma confusa
  • Acopla o nome do token ao visual (roxo), tornando-o incorreto quando a cor da marca mudar
Nomes baseados em aparência (purple) se tornam mentirosos e confusos quando o visual muda. O nome correto descreve o propósito: color.bg.brand continua fazendo sentido mesmo se a marca mudar para azul.
