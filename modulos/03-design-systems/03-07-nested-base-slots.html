Nested components, base components e slots

O poder máximo de um DS no Figma vem de compor componentes dentro de componentes — com padrões claros de base, aninhamento e slots que tornam cada componente flexível sem sacrificar consistência.

⏱️ Leitura: ~24 min 🎯 Nível: Avançado 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Implementar o padrão Base Component para criar variantes de forma eficiente;
  • Aninhar instâncias de componentes dentro de outros componentes;
  • Criar Slots usando Instance Swap para conteúdo flexível;
  • Compor componentes complexos (Card, List Item) a partir de componentes simples;
  • Evitar as armadilhas mais comuns de estrutura de componentes.

O padrão Base Component

O Base Component (ou componente âncora) é um padrão de design de componentes onde você cria uma versão interna "mestre" que carrega toda a lógica estrutural, e as variantes públicas são derivadas dela.

Sem esse padrão, cada variante é independente — mudança na estrutura exige alterar todas as variantes manualmente. Com ele, uma mudança no Base Component se propaga para todas as variantes automaticamente.

Quando usar Base Components

  • Componentes com muitas variantes que compartilham a mesma estrutura (Button, Badge, Tag, Chip);
  • Componentes com estados complexos (Input com Default, Focused, Error, Disabled);
  • Qualquer componente onde você prevê que a estrutura vai evoluir com o tempo.

Como implementar

  1. Crie o Base Component. Crie um componente com todas as Component Properties necessárias — variantes (Type, Size, State), booleans (hasIcon, hasLabel), instance swaps (icon). Prefixe o nome com underscore para indicar que é interno: _Button/Base.
  2. Configure todas as props no Base. Adicione todas as variações como propriedades, não como variantes separadas. Use Variant properties para Type (Primary, Secondary, Danger, Ghost), Size (sm, md, lg) e State (Default, Hover, Focus, Disabled, Loading).
  3. Crie as variantes "públicas" como wrappers. Para cada variante principal (ex: Button/Primary), crie um componente que contém uma instância do _Button/Base com as props configuradas. Exponha somente as props relevantes para aquela variante usando Expose nested instance ou Component Properties expostas.
  4. Publique apenas as variantes públicas. Quando publicar na Library, marque os componentes _ como "Not for publishing" ou coloque-os em uma página oculta. Os consumidores da Library só veem as variantes limpas.
Prefixo underscore como convenção

A convenção _ComponentName indica "componente interno, não use diretamente". É amplamente adotada no ecossistema Figma. O Figma Community tem diversos DS open source que seguem essa convenção — estudá-los é uma ótima forma de aprender.

Nested Instances — componentes dentro de componentes

Nested instances são instâncias de componentes colocadas dentro de outros componentes. É o principal mecanismo de composição do Figma.

Exemplo: o componente ListItem contém uma instância de Icon, uma instância de Text/Body e uma instância de Badge. Cada uma dessas instâncias pode ser trocada ou configurada individualmente dentro do ListItem.

Instance vs. Detach

Nunca use Detach Instance (Ctrl/⌘ + Alt + B) dentro de um componente. Isso quebra a hierarquia e o componente detachado não recebe mais atualizações da biblioteca. Prefira sempre Instance Swap para trocar o conteúdo, e Component Properties para customizar.

Slots com Instance Swap

Um Slot é um "buraco" em um componente que pode ser preenchido com qualquer outro componente usando Instance Swap. No Figma, isso é implementado através da Component Property do tipo Instance Swap.

Como criar um Slot

  1. Defina o componente placeholder do Slot. Crie um componente chamado, por exemplo, Slot/Icon/Default — pode ser um ícone genérico ou um frame vazio com as dimensões corretas.
  2. Coloque o placeholder no componente pai. Dentro do seu componente Card, insira uma instância de Slot/Icon/Default na posição onde o ícone vai ficar.
  3. Crie a Component Property de Instance Swap. Selecione a instância do Slot no componente. No painel direito, em Component Properties, clique em + e escolha Instance Swap. Nomeie como "Leading Icon". Defina o valor padrão como Slot/Icon/Default.
  4. Teste no consumer. Coloque uma instância do Card no canvas. No painel de propriedades da instância, você verá o campo "Leading Icon" com um seletor de componente. Selecione qualquer ícone da sua biblioteca para trocar o conteúdo do slot.

Um Card com três Slots: imagem (pode ser um ícone, uma foto ou nada), área de conteúdo (flexível) e ação (botão ou ícone). Cada slot aceita qualquer componente.

Composição: Card com List Item e Slot

Vamos ver um exemplo completo de composição. Você vai criar um Card/Product usando um ListItem como base, com Slots para imagem, título, descrição e ação:

  1. Crie o componente Icon/Star e Icon/Heart. Dois ícones simples (podem ser Auto Layout com vetores). Esses serão as opções de slot de ação.
  2. Crie o componente Button/IconOnly. Um botão com apenas um ícone, com Instance Swap property "Icon" (default: Icon/Star).
  3. Crie o componente ListItem/Base. Um Auto Layout horizontal com: Slot "Leading" (Instance Swap, default: Icon/Star), uma coluna central de texto (título + descrição) com Auto Layout vertical, Slot "Trailing" (Instance Swap, default: Button/IconOnly).
  4. Crie o componente Card/Product. Um Auto Layout vertical com: uma área de imagem (Slot Image), um separador, uma instância de ListItem/Base (com as props de Leading/Trailing expostas como Component Properties no Card).
  5. Teste a composição. No canvas, instancie vários Card/Product. Em cada um, troque o Leading por um ícone diferente, o Trailing por um botão diferente, e confirme que a estrutura se mantém.
Expor propriedades de nested instances

Quando você tem uma instância aninhada dentro de um componente e quer que o consumidor possa configurar as props dessa instância de fora, use Expose nested instance. Selecione a instância aninhada, clique em Expose properties from [ComponentName] no painel. As props do nested component ficam acessíveis diretamente no painel do componente pai.

Evitando armadilhas comuns

Armadilha 1: Variantes demais no mesmo componente

Um componente com 6 propriedades de 4 valores cada gera 4.096 variantes combinadas — o Figma fica lento e o painel confuso. A solução é usar Component Properties ao invés de variantes explícitas para dimensões ortogonais (size e state podem ser props; type pode ser um componente separado).

Armadilha 2: Frames normais dentro de componentes

Se você colocar um frame (não componente) no slot de um componente, ele não será trocável via Instance Swap. Todo conteúdo que precisa ser slot deve ser um componente. Verifique se há ícones ou elementos internos que ainda são frames simples.

Armadilha 3: Usar grupos onde deveria usar frames

Grupos não têm layout, não respeitam constraints e não aceitam Variables. Converta grupos em frames (Ctrl/⌘ + G cria grupo, mas você pode converter para frame depois) sempre que um elemento for parte de um componente.

Cuidado com a profundidade de aninhamento

Componentes aninhados demais (5+ níveis) dificultam a navegação e a edição. A regra geral: se você precisa de mais de 3 cliques para chegar ao elemento que quer editar dentro de um componente, a estrutura provavelmente precisa de refatoração.

Exemplo de uso real

O DS de um app de e-commerce usa este padrão de composição:

  • Icon/[Name] — 80 ícones como componentes independentes;
  • _Button/Base — base component com Type (Primary, Secondary, Danger, Ghost, Link), Size (sm, md, lg), State (Default, Hover, Loading, Disabled), Boolean (hasLeadingIcon, hasTrailingIcon) e dois Instance Swap slots para ícones;
  • Button/Primary/MD, Button/Primary/LG etc. — wrappers públicos com props pré-configuradas;
  • ProductCard — composto por Image/Placeholder, um Badge/Promo (Boolean hasPromo), Text/Body (Slot de título), Text/Caption (descrição), PriceDisplay e Button/Primary.

Para criar a versão "out of stock" do card, basta mudar o State do Button/Primary para Disabled e adicionar um Badge/OutOfStock no slot de badge — sem duplicar o componente.

Resumo

  • Base Component (_ComponentName) concentra a lógica estrutural; variantes públicas são wrappers que expõem props selecionadas.
  • Nested instances permitem composição: componentes dentro de componentes, trocáveis via Instance Swap.
  • Slots são Instance Swap properties que criam "buracos" no componente para conteúdo flexível.
  • Use Expose nested instance para surfacear props de componentes internos no componente pai.
  • Evite: variantes demais, frames simples onde deveria ter componentes, grupos em vez de frames, aninhamento excessivo.
✍️ Exercício

Componha um List Item com slots

  1. Crie 4 componentes de ícone simples (pode ser apenas frames com texto de emoji): Icon/Star, Icon/Heart, Icon/Share, Icon/Bookmark;
  2. Crie um componente ListItem com Auto Layout horizontal, com 3 zonas: Leading Slot (Instance Swap, default: Icon/Star), Text Area (título obrigatório + descrição Boolean), Trailing Slot (Instance Swap, default: Icon/Heart);
  3. No canvas, instancie 5 ListItem diferentes trocando os ícones dos Slots e alternando a visibilidade da descrição;
  4. Crie um componente List que contém 3 instâncias de ListItem com Auto Layout vertical.
Critério de sucesso: cada ListItem aceita qualquer ícone nos dois Slots sem quebrar o layout, e o componente List atualiza automaticamente quando você edita o componente ListItem.
🏆 Desafio

Refatore um componente existente para o padrão Base

Pegue um componente com pelo menos 4 variantes do seu arquivo (ou crie um Button com Primary/Secondary/Danger/Ghost × sm/md/lg). Refatore-o para o padrão Base Component: crie o _Button/Base com todas as props, e 4 componentes públicos wrapper. Confirme que uma mudança no Base (ex: aumentar o font-size) se propaga para todas as variantes públicas.

QuizTeste seu conhecimento

1. O que é um "Slot" em componentes Figma e como ele é implementado tecnicamente?

  • Uma "área vazia" em um componente que aceita qualquer outro componente, implementada via Instance Swap Component Property
  • Uma variante especial com o nome "Slot" que serve como placeholder
  • Um frame vazio dentro de um componente, usado para posicionar conteúdo livre
  • Uma propriedade de visibilidade que oculta ou mostra partes do componente
Slots são implementados como Instance Swap Component Properties. Você define um placeholder padrão e permite que o consumidor troque esse placeholder por qualquer componente compatível.

2. Por que usar o padrão Base Component com prefixo underscore (_Button/Base)?

  • Para que o Figma processe esse componente mais rapidamente
  • Para ocultar o componente dos desenvolvedores no Dev Mode
  • Para criar uma cópia de backup automática do componente
  • Para indicar que é um componente interno não destinado ao uso direto pelos consumidores da Library
O prefixo _ é uma convenção da comunidade que sinaliza "componente interno". O Base Component centraliza a estrutura; as variantes públicas (sem underscore) são os wrappers que os designers consomem.

3. O que acontece se você usar Detach Instance (Ctrl+Alt+B) em uma instância dentro de um componente?

  • O componente pai é automaticamente atualizado para refletir o estado detachado
  • O elemento detachado vira um frame normal e não recebe mais atualizações da biblioteca ou do componente pai
  • O Figma cria uma nova variante do componente com as modificações feitas
  • O Detach Instance não funciona dentro de componentes — só em instâncias no canvas
Detach Instance transforma a instância em um frame comum (ou grupo), quebrando definitivamente a conexão com o componente original. As atualizações da library deixam de se propagar para aquele elemento.
