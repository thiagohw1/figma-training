Libraries: publicar, consumir, versionar

Uma Library transforma seu DS de um arquivo privado em uma fonte de verdade compartilhada — qualquer arquivo do time pode consumir os mesmos componentes, styles e variables, e receber atualizações automaticamente quando o DS evolui.

⏱️ Leitura: ~22 min 🎯 Nível: Avançado 🛠️ Pratique no Figma

Ao final desta lição você será capaz de

  • Publicar um arquivo como Library, incluindo Components, Styles e Variables;
  • Habilitar uma Library em arquivos de produto e usar seus recursos;
  • Revisar e aceitar updates quando a Library for atualizada;
  • Entender o modelo de versionamento do Figma para Libraries;
  • Gerenciar Team Libraries e adotar boas práticas de governança.

O que é uma Library no Figma?

Uma Library (biblioteca) é um arquivo Figma publicado que disponibiliza seus componentes, Text Styles, Color Styles, Effect Styles e Variables para outros arquivos dentro do mesmo time (Team) ou organização.

Sem Libraries, cada arquivo de produto precisa ter suas próprias cópias dos componentes — quando o botão muda, você precisa atualizar em cada arquivo separadamente. Com uma Library, a mudança acontece no arquivo do DS e todos os arquivos consumidores podem aceitar a atualização com um clique.

Library vs. cópia local

Uma instância de componente vinda de uma Library mantém uma conexão permanente com o componente original. Uma cópia local (componente criado diretamente no arquivo de produto) não recebe updates automáticos. Sempre prefira instâncias de Library para componentes compartilhados.

O que pode ser publicado em uma Library

  • Components: todos os componentes marcados como publicáveis (não-ocultos);
  • Color Styles: estilos de cor criados no arquivo;
  • Text Styles: estilos de tipografia;
  • Effect Styles: sombras e blurs;
  • Grid Styles: grades e layouts;
  • Variables: todas as Collections de Variables do arquivo.

Passo a passo: publicando sua Library

  1. Prepare o arquivo do DS. Certifique-se de que todos os componentes têm nomes claros, as Variables estão organizadas em Collections, e os Styles estão nomeados corretamente. Componentes com nome começando em _ podem ser marcados como "Private" para não aparecerem na Library.
  2. Abra o menu de Library. No arquivo do DS, clique no menu hamburger (≡) no canto superior esquerdo → Libraries. O painel de Libraries abre.
  3. Publique o arquivo. No painel de Libraries, clique em Publish (ou "Publish all changes" se já foi publicado antes). Uma caixa de diálogo mostra o que será publicado — revise a lista.
  4. Adicione uma descrição da atualização. No campo de mensagem, descreva o que mudou: "Adicionados componentes de Input; corrigido padding do Button/MD; adicionado Mode Dark em Semantic/Color". Essa mensagem aparece para os consumidores quando eles recebem o update.
  5. Confirme a publicação. Clique em Publish. O arquivo agora está disponível como Library para os arquivos do team.
Publish seletivo

O painel de publicação mostra quais itens têm mudanças pendentes. Você pode desselecionar itens que ainda não estão prontos para publicação — útil quando está trabalhando em novos componentes em WIP que não devem ser consumidos ainda.

Habilitando uma Library em outros arquivos

  1. Abra o arquivo de produto onde você quer usar a Library.
  2. Acesse o painel de Libraries. Menu hamburger (≡) → Libraries. O painel mostra todas as Libraries disponíveis no seu Team.
  3. Ative a Library. Encontre o arquivo do DS na lista e ative o toggle. A partir deste momento, os componentes, Styles e Variables da Library estão disponíveis neste arquivo.
  4. Use os componentes. No painel de Assets (Alt/⌥ + 2), você verá os componentes da Library na seção "Libraries". Arraste para o canvas ou use a busca para encontrar componentes específicos.
  5. Use os Styles e Variables. Ao selecionar um Fill, os Color Styles da Library aparecem no seletor. No painel de Variables, as Collections da Library ficam disponíveis para aplicação.
Atalho para Assets

Pressione Alt + 2 (Windows) ou ⌥ + 2 (Mac) para abrir o painel de Assets. Use a busca do painel para encontrar componentes da Library por nome — muito mais rápido do que navegar pela hierarquia.

Recebendo e aceitando updates

Quando o arquivo de DS é publicado com alterações, os arquivos consumidores recebem uma notificação. O fluxo para aceitar:

  1. Veja a notificação. Uma bandeirinha azul aparece no canto inferior da tela — "Updates available from [nome da Library]".
  2. Revise as mudanças. Clique na notificação → View changes. O Figma mostra um diff visual de cada componente/style alterado, com antes e depois.
  3. Aceite ou ignore. Clique em Update all para aceitar todos os updates de uma vez, ou selecione individualmente quais deseja aceitar. Há também a opção de ignorar um update específico para não quebrar trabalho em andamento.
  4. Verifique depois. Após aceitar, percorra as telas para garantir que nada quebrou visivelmente. Se uma mudança de estrutura no componente causou problemas visuais, você precisará ajustar as instâncias afetadas.
Updates que podem quebrar layouts

Mudanças de estrutura em componentes (adicionar ou remover layers, mudar o Auto Layout direction) podem afetar como as instâncias se comportam nos arquivos consumidores. Sempre comunique o time antes de publicar mudanças estruturais grandes, e dê tempo para as equipes revisarem antes de aceitar o update.

Versionamento de Libraries

O Figma mantém um histórico de versões de cada arquivo. Para Libraries, isso significa que você pode voltar a uma versão anterior se um update causar problemas:

  • Version history: Menu hamburger → Show version history. Mostra todas as versões salvas com timestamps.
  • Named versions: Você pode criar versões nomeadas manualmente (ctrl/⌘ + alt + S) para marcar releases significativos: "v1.0 — Lançamento inicial", "v1.1 — Adicionados componentes de Form".
  • Restaurar versão: Clique em uma versão no histórico e selecione "Restore" para voltar a esse estado. Atenção: isso afeta o arquivo de DS, e a próxima publicação refletirá o estado restaurado.
Versionamento semântico

Adote versionamento semântico para as versões nomeadas da Library: v1.0.0 (maior.menor.patch). Mudanças quebradoras aumentam o major; novas features aumentam o minor; correções aumentam o patch. Documente o changelog nas descriptions ou em uma página dedicada do arquivo.

Team Libraries e governança

Em times maiores, pode existir mais de uma Library — por exemplo, uma Library de foundations e uma por produto. As responsabilidades ficam claras quando você define quem pode editar e publicar cada Library:

TipoConteúdoQuem publica
Foundation Library Tokens, Primitives, Text Styles, grids Lead Designer ou DS team
Component Library Todos os componentes do DS DS team
Product Library Componentes específicos de produto que estendem o DS Lead do produto
Icon Library Todos os ícones como componentes DS team ou design lead

Processo de governança recomendado

  • RFC (Request for Change): qualquer designer pode propor uma mudança ao DS; a proposta é revisada pelo DS team antes de ser implementada;
  • Branch para features: use Figma Branches para trabalhar em novas features da Library em isolamento, sem afetar a versão publicada atual;
  • Review antes de publicar: pelo menos uma segunda pessoa revisa as mudanças antes de publicar;
  • Changelog documentado: toda publicação tem uma mensagem de mudança clara, idealmente com uma página de changelog no arquivo;
  • Comunicação: avisar o time antes de publicar mudanças significativas, especialmente as que mudam estrutura de componentes.
Figma Branches para o DS

O recurso Branches (disponível no plano Professional+) permite criar uma cópia temporária do arquivo de Library para trabalhar em mudanças sem afetar a versão publicada. Ao terminar, você faz o merge de volta para o arquivo principal — como um git branch para design. Ideal para refatorações grandes ou adição de novos conjuntos de componentes.

Exemplo de uso real

O DS do sistema de e-commerce "Shopper" tem a seguinte estrutura de Libraries:

  • Shopper DS — Foundations: tokens primitivos, semânticos, Text Styles, sombras, ícones;
  • Shopper DS — Components: 80+ componentes baseados nas foundations;
  • Shopper DS — Icons: 500 ícones como componentes separados (Library própria pelo volume);

Os arquivos de produto (App Mobile, Web, Admin Dashboard, Seller Portal) habilitam as três Libraries. Quando o botão primário recebe um update de radius (de 8 para 10 px), o DS team publica a mudança nos Components. Os 4 arquivos de produto recebem a notificação e aceitam com um clique — 4 produtos atualizados em segundos, sem nenhum trabalho manual.

Resumo

  • Libraries compartilham Components, Styles e Variables entre arquivos de um Team ou organização.
  • Para publicar: menu hamburger → Libraries → Publish. Adicione uma descrição da mudança.
  • Para consumir: no arquivo de produto, menu hamburger → Libraries → ative a Library desejada.
  • Updates aparecem como notificação; revise o diff e aceite (all ou seletivo).
  • Use named versions para marcar releases e mantenha um changelog.
  • Governança: RFC, Branches para features, review antes de publicar, comunicação ao time.
✍️ Exercício

Publique e consuma sua Library

  1. No arquivo de DS criado nas lições anteriores, publique a Library incluindo components, styles e variables;
  2. Crie um novo arquivo chamado "Produto — Tela de Login" no mesmo Team;
  3. Habilite a Library do DS nesse arquivo;
  4. Monte uma tela de login usando apenas componentes da Library (Button, Input, Text Styles) e Variables para as cores;
  5. Volte ao arquivo de DS e faça uma pequena mudança (ex: aumente o corner radius do Button de 8 para 12);
  6. Publique a mudança e aceite o update no arquivo de produto.
Critério de sucesso: após aceitar o update, os botões na tela de login refletem o novo radius sem nenhuma edição manual. A instância ainda está vinculada à Library (ícone de componente visível no painel).
🏆 Desafio

Multi-Library architecture

Separe seu DS em duas Libraries: uma de Foundations (tokens, styles, variáveis primitivas e semânticas) e uma de Components (todos os componentes que consomem as foundations). Configure a Library de Components para ter a de Foundations como dependência (ative Foundations na Library de Components). Crie um arquivo de produto que habilita apenas a Components Library — confirme que os tokens da Foundations Library também estão disponíveis via transitivo (pois Components os usa).

QuizTeste seu conhecimento

1. O que acontece com uma instância de componente de Library quando o componente original é atualizado?

  • A instância é automaticamente atualizada sem nenhuma ação do designer
  • A instância é deletada e precisa ser reinserida
  • Uma notificação aparece no arquivo consumidor; o designer escolhe quando aceitar o update
  • A instância fica desconectada da Library permanentemente
O Figma notifica os arquivos consumidores sobre updates disponíveis, mas não aplica automaticamente — o designer escolhe quando aceitar, podendo revisar o diff antes. Isso evita surpresas em trabalho em andamento.

2. Para que serve o recurso Figma Branches aplicado a Libraries?

  • Permite trabalhar em mudanças na Library em isolamento sem afetar a versão publicada, fazendo merge quando pronto
  • Cria múltiplas versões do arquivo de DS para diferentes times usarem simultaneamente
  • Faz backup automático do arquivo de Library em um repositório Git externo
  • Permite que múltiplos designers publiquem a Library ao mesmo tempo sem conflitos
Branches funcionam como branches de Git para design: você cria um branch para uma nova feature ou refatoração, trabalha sem afetar a versão publicada e faz o merge quando tudo está revisado e aprovado.

3. Qual é a principal vantagem de usar componentes de uma Library ao invés de copiar componentes diretamente para os arquivos de produto?

  • Componentes de Library são mais rápidos de renderizar no Figma
  • Mantêm conexão com o componente original; quando o DS atualiza, todos os arquivos consumidores podem aceitar a mudança com um clique
  • Componentes de Library ocupam menos espaço no arquivo
  • Só componentes de Library podem ter Variants e Component Properties
A conexão com a Library é o superpoder: uma mudança no DS se propaga para todos os arquivos de produto ao aceitar o update — mantendo consistência em escala sem trabalho manual em cada arquivo.
