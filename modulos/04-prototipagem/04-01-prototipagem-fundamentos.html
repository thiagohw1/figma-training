Fundamentos de prototipagem

Um protótipo transforma telas estáticas em experiências clicáveis — sem escrever uma linha de código. Nesta lição você vai entender como o Figma conecta telas, quais gatilhos e ações existem e como apresentar um fluxo funcional para a sua equipe.

⏱️ Leitura: ~22 min 🎯 Nível: Intermediário 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Navegar pela aba Prototype e entender cada seção do painel;
  • Criar Flows com Starting points para organizar fluxos de múltiplos usuários;
  • Adicionar conexões (Connections) entre frames usando qualquer Trigger disponível;
  • Escolher a Action correta para cada necessidade (Navigate, Overlay, Link, etc.);
  • Apresentar e compartilhar um protótipo clicável pelo Present/Preview.

O que é prototipagem no Figma?

Prototipagem é o processo de conectar frames (telas) com interações para simular o comportamento real de um produto digital. Em vez de descrever em palavras como uma tela leva à outra, você mostra — o usuário clica em um botão e a próxima tela aparece, exatamente como faria no app real.

O Figma guarda todas as informações de prototipagem separadas do design: enquanto você estiver na aba Design do painel direito, as conexões ficam invisíveis. Ao trocar para a aba Prototype, uma seta azul surge entre cada par de frames conectados, revelando toda a "teia" do fluxo.

Por que prototipar antes de desenvolver?

Testar um protótipo com usuários reais custa horas de designer. Corrigir o mesmo problema depois de codificado pode custar dias de desenvolvimento. Segundo estudos da Nielsen Norman Group, cada hora de teste de usabilidade economiza em média 6 horas de retrabalho. Prototipar cedo é um investimento, não um extra.

A aba Prototype

Para acessar, clique na aba Prototype no painel direito (ao lado de Design e Inspect). O painel se reorganiza e passa a mostrar:

  • Device & Preview: moldura do dispositivo (iPhone, Android, Desktop, Custom…) e cor de fundo exibida no Present mode.
  • Flows: lista de Starting points — os "pontos de entrada" do protótipo.
  • Interactions: quando um frame ou objeto está selecionado, aqui aparecem todas as conexões daquele elemento.
Atalho para alternar abas

Pressione Alt + 8 (Windows) ou ⌥ + 8 (Mac) para ir direto à aba Prototype sem usar o mouse.

Flows e Starting Points

Um Flow é um caminho lógico pelo protótipo: por exemplo, "Onboarding", "Compra" ou "Login". Você pode ter vários flows em um único arquivo — útil quando o mesmo projeto tem fluxos de usuário distintos (usuário comum vs. administrador).

O Starting Point é o frame inicial de cada Flow. Para definir um:

  1. Selecione um Frame (não um componente solto, mas um frame de nível superior no canvas).
  2. Na aba Prototype, clique em + Add starting point na seção Flows.
  3. Dê um nome descritivo ao Flow ("Login flow", "Checkout flow").

No Present mode, você poderá escolher qual Flow deseja apresentar, iniciando pela tela certa sem precisar navegar por frames aleatórios.

Starting Point vs. frame selecionado

Se você pressionar Ctrl/⌘ + Enter sem nenhum Starting Point definido, o Figma apresenta o frame selecionado. Com um Starting Point, ele sempre inicia pelo frame designado — comportamento mais previsível em demos.

Connections — conectando telas

Uma Connection é uma seta que liga um elemento (ou frame inteiro) a outro frame, dizendo ao Figma: "quando X acontecer aqui, faça Y ali". Para criar uma conexão:

  1. Abra a aba Prototype. Certifique-se de estar na aba Prototype do painel direito; o painel mostra as opções de interação.
  2. Selecione o elemento de origem. Clique no botão, ícone ou frame que vai disparar a ação. Se você quiser que o frame inteiro seja clicável, selecione o próprio frame.
  3. Arraste o hotspot azul. Passe o mouse sobre o elemento selecionado até aparecer um círculo azul (+) na borda direita. Arraste esse círculo até o frame de destino.
  4. Configure o modal de interação. Um modal flutuante abre automaticamente com opções de Trigger, Action e Transition. Configure cada um conforme a necessidade (veja seções abaixo).
  5. Feche o modal. Clique fora do modal ou pressione Esc para fechar. A seta azul permanece no canvas indicando a conexão.
Editar uma conexão existente

Para editar, clique na seta azul no canvas — o modal de interação reabre. Para deletar, selecione a seta e pressione Delete ou Backspace.

Triggers — o que dispara a interação

Um Trigger define o gesto ou evento do usuário que ativa a ação. O Figma oferece os seguintes triggers em 2025/2026:

TriggerQuando é ativadoUso típico
On clickToque/clique simples no elementoBotões, links, cards
On dragArrastar o elemento em uma direçãoSwipe para deletar, carrossel
While hoveringEnquanto o cursor está sobre o elementoTooltips, estados hover de menu
While pressingEnquanto mantém o botão pressionadoLong press, botões de gravação
Key/GamepadTecla de teclado específica é pressionadaNavegação por teclado, atalhos
After delayApós N milissegundos sem interaçãoSplash screens, auto-play de slides
Mouse enterCursor entra na área do elementoDropdowns, pré-carregamento visual
Mouse leaveCursor sai da área do elementoFechar tooltip, reverter hover
Mouse downBotão do mouse é pressionado (antes de soltar)Efeito pressed imediato
Mouse upBotão do mouse é soltoConfirmação de clique

Actions — o que acontece quando o trigger é ativado

A Action define o que o protótipo faz quando o trigger dispara. Cada action tem parâmetros específicos:

ActionO que fazParâmetros principais
Navigate toNavega para outro frame (substitui a tela atual)Frame de destino, transição
BackVolta ao frame anterior no histórico de navegaçãoTransição de saída
Close overlayFecha um overlay abertoTransição de saída
Open overlayAbre um frame por cima da tela atual (modal, drawer, tooltip)Frame de destino, posição, backdrop
Swap overlaySubstitui um overlay aberto por outroFrame de destino, transição
Open linkAbre uma URL externa no navegadorURL completa
Set variableAltera o valor de uma VariableVariável, novo valor ou expressão
ConditionalAvalia uma condição e executa uma action diferente dependendo do resultadoCondição (if/else), actions para cada ramo
Scroll toRola até um elemento específico dentro do frameElemento de destino, animação
Navigate to vs. Open overlay

Navigate to troca a tela inteira — como navegar entre páginas de um site. Open overlay exibe um novo frame por cima da tela atual, mantendo o contexto — como um modal ou um drawer lateral. Usar o errado quebra a sensação de continuidade do protótipo.

Present mode e Preview

Depois de criar as conexões, é hora de testar. Existem duas formas:

  • Preview inline: o pequeno botão de "play" no canto superior direito abre um painel de preview ao lado do canvas. Rápido para checar interações pontuais sem abrir uma nova aba.
  • Present mode (Ctrl/⌘ + Enter): abre o protótipo em tela cheia ou em uma nova aba do navegador, com moldura do dispositivo e todos os fluxos disponíveis. É o modo ideal para apresentações e testes com usuários.

No Present mode, use as setas de teclado para navegar manualmente entre frames mesmo sem conexões, ou clique nos hotspots para seguir o fluxo real do protótipo.

Dica de profissional: organize múltiplos flows

Em projetos grandes, crie um Starting Point para cada jornada do usuário (onboarding, compra, configurações). No Present mode, um menu de Flows permite selecionar qual jornada apresentar — sem precisar explicar verbalmente para onde ir primeiro. Nomes claros nos Flows economizam tempo em demos com stakeholders.

Exemplo de uso real

Imagine o protótipo de um app de delivery. Você tem três fluxos:

  1. Fluxo de Busca: Home → Resultado de busca → Detalhe do restaurante → Carrinho → Confirmação.
  2. Fluxo de Reorder: Home → Pedido anterior → Confirmação (caminho mais curto).
  3. Fluxo de Conta: Home → Perfil → Editar dados → Salvo.

Cada fluxo tem seu próprio Starting Point. Ao apresentar para o time de produto, você alterna entre os flows em segundos. Ao apresentar para o time de marketing, mostra só o Fluxo de Busca. Um único arquivo, múltiplas narrativas.

Resumo

  • A aba Prototype separa as conexões do design, mantendo o painel limpo.
  • Flows e Starting Points organizam múltiplas jornadas em um único arquivo.
  • Uma Connection tem três partes: elemento de origem, Trigger (evento) e Action (o que acontece).
  • Os 10 Triggers cobrem desde clique simples até após delay automático.
  • As Actions incluem navegar entre telas, abrir overlays, voltar, abrir links e até lógica condicional com Variables.
  • O Present mode (Ctrl/⌘ + Enter) exibe o protótipo em tela cheia para demos e testes.
✍️ Exercício

Conecte três telas de um app

Crie um mini-fluxo de onboarding com três telas: Boas-vindas → Criar conta → Home.

  1. Crie três frames (use o preset "iPhone 14" no campo de Frame: F).
  2. Nomeie-os "Boas-vindas", "Criar conta" e "Home".
  3. Adicione um botão em cada tela e conecte-os em sequência usando On click → Navigate to.
  4. Defina o frame "Boas-vindas" como Starting Point do Flow "Onboarding".
  5. Abra o Present mode e teste o fluxo clicando pelos botões.
Critério de sucesso: ao clicar nos botões em sequência no Present mode, a navegação Boas-vindas → Criar conta → Home funciona sem travar, e o Flow "Onboarding" aparece no menu de flows.
🏆 Desafio

Fluxo completo com Back e dois Starting Points

Expanda o exercício: crie um segundo fluxo "Login" (Login → Home) no mesmo arquivo. Adicione um botão "Voltar" em cada tela interna com a action Back. Na tela de Boas-vindas, adicione dois botões: "Criar conta" e "Já tenho conta" — cada um iniciando seu respectivo flow. No Present mode, confirme que ambos os Flows aparecem no seletor e que o botão Voltar funciona em cada tela.

QuizTeste seu conhecimento

1. Qual é a diferença entre as actions "Navigate to" e "Open overlay"?

  • Navigate to é para mobile e Open overlay é para desktop
  • Navigate to substitui a tela atual; Open overlay exibe um frame por cima, mantendo o contexto
  • Navigate to só funciona com On click; Open overlay aceita qualquer trigger
  • Não há diferença funcional, apenas de nomenclatura
Navigate to troca a tela inteira (como trocar de página), enquanto Open overlay empilha um frame por cima da tela atual — ideal para modais, drawers e tooltips que precisam manter o contexto visível.

2. Para que serve um "Starting Point" em um Flow?

  • Define o frame que sempre aparece em todas as transições
  • Marca o frame mais importante visualmente no canvas
  • Define o frame inicial de um Flow, permitindo escolher qual jornada apresentar no Present mode
  • Sincroniza o protótipo com um arquivo externo de dados
O Starting Point é o frame de entrada de um Flow. No Present mode, você pode selecionar qual Flow (e portanto qual Starting Point) iniciar — fundamental quando um arquivo tem múltiplas jornadas de usuário.

3. Qual trigger você usaria para criar uma splash screen que avança automaticamente após 3 segundos?

  • While hovering
  • On drag
  • Mouse enter
  • After delay
After delay dispara a ação automaticamente após um tempo definido (em milissegundos) sem nenhuma interação do usuário — perfeito para splash screens, tutoriais automáticos e auto-play de slides.
