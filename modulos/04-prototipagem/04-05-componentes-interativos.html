Componentes interativos

Sem Interactive Components, criar um protótipo com 50 botões em estados diferentes exigiria 50 conexões individuais. Com Interactive Components, você define a interação uma única vez dentro do componente — e ela funciona em todas as instâncias automaticamente, eliminando a "teia de setas" que torna os protótipos difíceis de manter.

⏱️ Leitura: ~20 min 🎯 Nível: Intermediário/Avançado 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Explicar o que são Interactive Components e como eles diferem das conexões normais;
  • Adicionar interações dentro de um Component Set entre suas Variants;
  • Criar estados Hover, Pressed e outros usando While hovering / While pressing;
  • Implementar componentes interativos comuns: botão, toggle, tabs e accordion;
  • Usar nested interactive components para combinar comportamentos.

O problema que Interactive Components resolve

Imagine um formulário de login com 10 campos de input. Sem Interactive Components, para mostrar o estado "focused" de cada campo você precisaria criar 10 conexões separadas (cada instância do campo → sua versão focused). Isso é trabalhoso, difícil de atualizar e cria uma teia de setas ilegível no canvas.

Com Interactive Components, a interação vive dentro do Component Set, entre suas variants. Cada instância do componente herda a interação automaticamente. Você define uma vez, funciona em todo lugar.

Pré-requisito: Component Sets com Variants

Interactive Components funcionam dentro de um Component Set — o quadrado tracejado que agrupa todas as variants de um componente. Se você ainda não está confortável com Variants, revise a Lição 6 do Módulo 3 antes de continuar.

Como funciona: interações entre variants

Dentro de um Component Set, cada variant é uma versão do componente (Default, Hover, Pressed, Focused, Disabled, etc.). Com Interactive Components, você pode criar conexões entre essas variants — da mesma forma que cria conexões entre frames normais:

  1. Abra o Component Set. Entre em modo de edição do componente (duplo clique).
  2. Vá para a aba Prototype.
  3. Selecione a variant "Default" e arraste o hotspot para a variant "Hover".
  4. Configure: Trigger = While hovering, Animation = Smart Animate.
  5. Agora toda instância deste componente no canvas automaticamente mostra o estado Hover quando o cursor passa por cima.

Dentro do Component Set, setas conectam as variants. Toda instância do componente herda automaticamente essas interações.

Os triggers mais usados em Interactive Components

While hovering

Ativado enquanto o cursor está sobre o componente. Perfeito para estados Hover de botões, cards, links e ícones. A transição acontece ao entrar e a reversão ao sair — automaticamente, sem configurar o "retorno".

While pressing

Ativado enquanto o usuário mantém o clique pressionado. Ideal para feedback visual de botões (estado Pressed) e long-press em mobile. A variant retorna ao estado anterior ao soltar.

On click

Disparado em um único clique. Usado para toggles (alternar entre dois estados permanentemente), checkboxes, radio buttons e qualquer componente cujo estado muda e persiste após a interação.

Mouse enter / Mouse leave

Similar ao While hovering, mas com controle mais granular: Mouse enter dispara ao entrar, Mouse leave ao sair. Útil quando a animação de entrada e saída deve ser diferente (ex.: tooltip que aparece rápido e desaparece devagar).

Exemplos práticos

Botão com estados Default, Hover e Pressed

  • 3 variants no Component Set: Default, Hover, Pressed.
  • Default → Hover: While hovering, Smart Animate, 150 ms, Ease Out.
  • Hover → Pressed: While pressing, Smart Animate, 80 ms, Ease Out.
  • O Figma cria automaticamente as transições de retorno (Hover → Default ao sair, Pressed → Hover ao soltar).

Toggle (checkbox ou switch)

  • 2 variants: Checked=false, Checked=true.
  • Checked=false → Checked=true: On click, Smart Animate, 200 ms, Ease Out.
  • Checked=true → Checked=false: On click, Smart Animate, 200 ms, Ease Out (retorno).
  • Em cada instância do canvas, o toggle funciona independentemente — sem conexões extras.

Tabs (abas de navegação)

  • 4 variants: Tab1 ativo, Tab2 ativo, Tab3 ativo, Tab4 ativo.
  • Cada variant tem a aba correspondente marcada como ativa (cor diferente, underline, etc.).
  • Conecte cada aba com On click → Smart Animate para a variant correspondente.
  • O indicador ativo desliza suavemente entre as abas graças ao Smart Animate (layers com mesmo nome).

Accordion (expansão de seção)

  • 2 variants: Collapsed, Expanded.
  • Collapsed: altura reduzida, ícone de seta para baixo.
  • Expanded: altura completa, conteúdo visível, ícone rotacionado 180°.
  • On click → Smart Animate, 300 ms. A altura anima e a seta gira.
Nomeie as variants de forma semântica

Use propriedades de variant claras: State = Default/Hover/Pressed/Focused/Disabled. Isso facilita a seleção de instâncias no canvas e mantém o sistema de componentes legível para toda a equipe.

Nested Interactive Components

Componentes interativos podem ser aninhados dentro de outros componentes. Por exemplo: um card de produto que contém um botão de "Favoritar" (toggle interativo). O botão funciona independentemente dentro do card, e o card pode ter suas próprias interações por cima.

Regras importantes para nested interactive components:

  • As interações do componente filho não interferem nas interações do componente pai — cada um age independentemente.
  • No Present mode, você pode clicar no toggle dentro do card sem acionar o clique do card.
  • Não há limite de níveis de aninhamento, mas muitos níveis podem tornar a estrutura difícil de manter.
Interações de instância vs. interações do Component Set

Você pode adicionar interações diretamente em uma instância no canvas (não no Component Set). Essas interações são locais — só funcionam naquela instância. Interações no Component Set são globais — funcionam em todas as instâncias. Para comportamentos padrão, defina sempre no Component Set. Reserve interações de instância para exceções.

Por que Interactive Components reduzem a "teia de setas"

Considere uma tela de formulário com 20 campos de input, cada um com estados Default, Focused, Filled e Error. Sem Interactive Components, você precisaria de 20 × 4 = até 80 conexões para cobrir todas as transições de cada campo. O canvas ficaria ilegível.

Com Interactive Components, você define as 4 transições uma única vez no Component Set do Input. Nos 20 campos da tela, zero conexões adicionais são necessárias. O canvas fica limpo e o protótipo funciona perfeitamente.

Exemplo de uso real

Em um Design System corporativo, o componente Button tem 5 variants de estado (Default, Hover, Pressed, Focused, Disabled) e 3 tipos (Primary, Secondary, Destructive). Com Interactive Components, os 15 botões resultantes têm seus estados configurados uma única vez. Ao longo de 200 telas de um produto, cada botão se comporta corretamente sem nenhuma conexão manual nas telas.

Resumo

  • Interactive Components são interações definidas dentro do Component Set entre suas variants.
  • Toda instância do componente herda as interações — zero conexões manuais nas telas.
  • Os triggers mais usados: While hovering, While pressing, On click.
  • Combine com Smart Animate para transições fluidas entre estados.
  • Nested interactive components permitem comportamentos independentes em componentes aninhados.
  • Defina interações no Component Set para comportamento global; reserve interações de instância para exceções.
✍️ Exercício

Botão com três estados

  1. Crie um Component Set com 3 variants de botão: Default (azul sólido), Hover (azul mais escuro, leve sombra), Pressed (azul bem escuro, escala ligeiramente menor).
  2. Dentro do Component Set (aba Prototype), adicione as interações: Default → Hover (While hovering, Smart Animate, 150 ms), Hover → Pressed (While pressing, Smart Animate, 80 ms).
  3. Volte ao canvas. Coloque 5 instâncias do botão em uma tela.
  4. No Present mode, confirme que todos os 5 botões respondem ao hover e ao press — sem nenhuma conexão nas telas.
Critério de sucesso: todos os botões têm os estados funcionando no Present mode. O canvas não tem setas de conexão fora do Component Set.
🏆 Desafio

Sistema de tabs com indicador animado

Crie um componente de Tab Bar com 4 abas. Cada aba deve ter um "indicator" (underline ou ponto) que desliza para a aba ativa com Smart Animate quando o usuário clica. O layer do indicator deve ter o mesmo nome nas 4 variants para que o Smart Animate o anime corretamente. Coloque 3 instâncias do componente em uma tela e confirme que cada uma navega independentemente.

QuizTeste seu conhecimento

1. Qual é a principal vantagem de definir interações dentro de um Component Set em vez de nas instâncias no canvas?

  • As interações ficam visíveis somente no Present mode, não no canvas
  • Permite usar triggers que não existem em frames normais
  • Todas as instâncias do componente herdam a interação automaticamente, eliminando conexões manuais nas telas
  • As animações ficam mais rápidas no Present mode
A vantagem principal é que todas as instâncias herdam automaticamente as interações definidas no Component Set — sem precisar adicionar conexões em cada instância individualmente. Isso elimina a "teia de setas" e facilita manutenção.

2. Qual trigger você usaria para um botão que deve mostrar feedback visual apenas enquanto o usuário mantém o dedo/mouse pressionado?

  • On click
  • While pressing
  • Mouse down
  • After delay
While pressing ativa a variant enquanto o botão é mantido pressionado e reverte automaticamente ao soltar — ideal para o estado "Pressed" de botões. On click dispara apenas uma vez ao clicar, sem reter o estado durante o press.

3. Você tem um card interativo que contém um botão "Favoritar" (também interativo). O que acontece quando o usuário clica no botão no Present mode?

  • O botão Favoritar responde à sua própria interação; o card não é acionado
  • O card captura o clique e o botão não responde
  • Ocorre um erro — não é possível aninhar componentes interativos
  • Ambas as interações disparam ao mesmo tempo
Nested interactive components funcionam de forma independente. O clique no botão Favoritar aciona apenas a interação daquele componente filho, sem propagar para o componente pai (o card). Cada componente gerencia suas próprias interações.
