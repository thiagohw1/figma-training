Figma Sites — publicar sites

E se você pudesse publicar um site direto do Figma, sem precisar de um desenvolvedor ou de uma ferramenta de no-code separada? O Figma Sites torna isso realidade — do design ao ar em minutos.

⏱️ Leitura: ~18 min 🎯 Nível: Intermediário 🛠️ Pratique no Figma Sites

Ao final desta lição você será capaz de

  • Entender o que é o Figma Sites e quais tipos de projetos ele atende;
  • Configurar breakpoints para responsividade em diferentes tamanhos de tela;
  • Adicionar interações nativas (scroll, parallax, marquee);
  • Fazer preview do HTML gerado diretamente no canvas;
  • Publicar um site na web pelo Figma Sites.

O que é o Figma Sites?

Figma Sites é a funcionalidade do Figma que permite transformar designs em sites reais publicados na web, sem precisar escrever código. Foi anunciado na Config 2025 como uma das maiores novidades da plataforma.

A proposta é fechar o gap entre design e publicação para determinados tipos de site — especialmente landing pages, sites de produto, portfólios e microsites de campanha. Para projetos com necessidade de back-end, autenticação ou lógica complexa, o Figma Sites não é a ferramenta ideal; nesse caso, o Figma Make (próxima lição) ou o fluxo de handoff para desenvolvimento continuam sendo o caminho.

Figma Sites vs. Figma Prototyping

O Figma Prototyping simula interações dentro do Figma para testes de usabilidade. O Figma Sites publica HTML real na internet — o resultado é um site indexável, compartilhável via URL e acessível em qualquer browser, não um protótipo encapsulado na plataforma.

Do design ao site: o fluxo

O fluxo do Figma Sites começa em um arquivo de design comum do Figma. Você desenha normalmente, usando frames, Auto Layout, componentes e variáveis. Quando estiver pronto para publicar, ativa o Figma Sites e ele "interpreta" seu design como HTML/CSS.

O fluxo completo do Figma Sites: do design até o URL público.

Breakpoints e responsividade

Um dos recursos mais importantes do Figma Sites é o suporte a breakpoints — pontos de quebra em que o layout muda para se adaptar a diferentes tamanhos de tela (desktop, tablet, mobile).

Como configurar breakpoints

No painel do Figma Sites (acessível via menu "Sites" ou plugin), você define os breakpoints desejados. Para cada breakpoint, você cria ou ajusta um frame no arquivo de design com a largura correspondente. O Figma Sites entende que esses frames são versões responsivas da mesma página:

  • Desktop: frame com 1440 px de largura (ou 1280 px)
  • Tablet: frame com 768 px de largura
  • Mobile: frame com 390 px de largura

A lógica de responsividade é baseada nos Constraints e no Auto Layout que você já configurou nos frames. Por isso, designs bem estruturados com Auto Layout e Constraints corretos "se adaptam" naturalmente ao serem publicados.

Auto Layout é o segredo da responsividade

Quanto mais você usar Auto Layout com tamanhos "Fill container" e "Hug content" em vez de valores fixos em pixels, melhor o Figma Sites consegue adaptar o layout para diferentes larguras. É o mesmo princípio do Flexbox no CSS.

Interações nativas

O Figma Sites suporta interações CSS e JavaScript nativas que você configura visualmente:

Scroll

Seções com scroll interno (overflow: scroll) podem ser configuradas no painel do Figma Sites. Carrosséis horizontais e listas scrolláveis são exemplos de uso.

Parallax

Efeito de paralaxe — onde elementos se movem a velocidades diferentes durante o scroll da página, criando profundidade. No Figma Sites, você seleciona um elemento e define o fator de parallax (ex.: 0.5 = move à metade da velocidade do scroll).

Marquee (texto em loop)

Faixa de texto ou logos que se movem continuamente da direita para a esquerda (estilo "ticker"). Bastante popular em landing pages modernas para exibir logos de clientes, badges ou headlines. Configure via painel de efeitos do Figma Sites.

Animações de entrada

Você pode definir que elementos apareçam com uma animação quando entram na viewport durante o scroll (fade in, slide up, etc.). Esses efeitos são configurados por elemento no painel do Sites.

Limitações de interação

O Figma Sites não suporta lógica de programação — não há formulários com envio real de dados, login, queries a banco de dados ou lógica condicional complexa. Para essas necessidades, use o Figma Make ou desenvolva com um framework.

Preview de HTML no canvas

Um recurso exclusivo do Figma Sites é poder ver o preview do HTML gerado diretamente no canvas do Figma. Isso funciona assim: com o painel do Sites aberto, você tem um botão "Preview" que renderiza uma prévia interativa do site dentro de um frame no próprio Figma. Você pode testar o scroll, clicar em links e verificar a responsividade sem precisar publicar.

Isso acelera muito o ciclo de iteração — você ajusta o design, confere o preview, ajusta novamente, tudo sem sair do Figma.

Publicar na web

Quando o site estiver pronto, clique em "Publish" no painel do Figma Sites. O processo:

  1. O Figma converte o design em HTML, CSS e JavaScript otimizados.
  2. O site é hospedado na infraestrutura da Figma (seusite.figma.site por padrão).
  3. Você recebe uma URL pública para compartilhar.
  4. É possível configurar um domínio personalizado nas configurações do site (feature disponível em planos pagos).
Domínio personalizado e CMS

O Figma Sites suporta a configuração de domínios personalizados via CNAME. Recursos de CMS (gerenciamento de conteúdo por não-designers) e Code Layers (camadas que injetam HTML/CSS/JS personalizado) são funcionalidades em desenvolvimento ativo, com disponibilidade variando conforme o plano. Consulte a documentação oficial para o status atual.

Code Layers (menção)

Code Layers são camadas especiais no Figma Sites onde você pode injetar HTML, CSS ou JavaScript personalizado — estendendo as capacidades além do que o editor visual permite. Por exemplo: incorporar um widget de chat, adicionar um script de analytics, ou criar uma animação CSS que não está disponível nativamente. Esse recurso é destinado a designers com conhecimento de código ou em colaboração com desenvolvedores.

Passo a passo conceitual: do design ao site

  1. Desenhe a landing page no Figma Design. Crie frames para Desktop (1440 px) e Mobile (390 px) com Auto Layout e Constraints bem configurados. Sections em Auto Layout vertical, conteúdo com Fill container.
  2. Ative o Figma Sites. No menu do arquivo ou no painel direito, acesse a seção Sites. Associe os frames de Desktop e Mobile às suas respectivas viewport widths.
  3. Configure as interações. Selecione os elementos que devem ter parallax, marquee ou animações de entrada. Configure pelo painel de efeitos do Sites.
  4. Visualize o preview no canvas. Clique em "Preview" e confira o site renderizado. Teste o scroll e a responsividade. Ajuste os frames conforme necessário.
  5. Configure SEO básico. No painel do Sites, preencha título da página, descrição e imagem de OG (Open Graph) para compartilhamentos em redes sociais.
  6. Publique. Clique em "Publish". Aguarde o build e receba a URL pública. Se quiser domínio personalizado, configure nas Settings do site.

Exemplo de uso real

Uma agência de design criou a landing page de lançamento de um aplicativo de meditação. O designer desenhou o layout no Figma com três breakpoints (1440, 768 e 390 px). Usou Auto Layout em todas as seções e Constraints corretos nas imagens. Configurou um efeito de parallax no hero (a imagem do app se move mais devagar que o texto ao fazer scroll) e um marquee com logos de imprensa na seção de validação. Em vez de esperar o desenvolvedor disponível, o próprio designer publicou o site no Figma Sites, com um subdomínio applaunch.figma.site, e enviou para aprovação do cliente no mesmo dia. Depois de aprovado, configuraram o domínio personalizado meditalancar.com.br.

Resumo

  • Figma Sites transforma designs do Figma em sites HTML reais publicados na web.
  • Ideal para landing pages, portfólios e microsites — não para apps complexos com back-end.
  • Breakpoints são configurados associando frames de diferentes larguras a viewport widths.
  • Interações nativas: scroll, parallax, marquee e animações de entrada.
  • Preview do HTML roda diretamente no canvas sem precisar publicar.
  • Publicação gera uma URL *.figma.site; domínio personalizado disponível em planos pagos.
✍️ Exercício

Landing page de um app fictício

Crie uma landing page simples para um app de tarefas fictício chamado "TaskFlow":

  1. Crie dois frames: Desktop (1440 px) e Mobile (390 px).
  2. Hero section: título grande, subtítulo, botão CTA e uma imagem placeholder.
  3. Features section: 3 cards de benefícios com ícone e texto.
  4. Footer: copyright e dois links fictícios.
  5. Configure Auto Layout e Constraints corretos em todos os elementos.
  6. Ative o Figma Sites e visualize o preview.
Critério de sucesso: o preview no canvas mostra o layout correto em Desktop e Mobile sem elementos sobrepostos ou cortados.
🏆 Desafio

Parallax e marquee na prática

Adicione ao seu site TaskFlow: (1) um efeito de parallax no hero image — a imagem se move 30% mais devagar que o restante da página durante o scroll; (2) uma faixa marquee com o texto "Disponível para iOS e Android · Grátis para sempre · 50 mil usuários · " repetido em loop. Configure ambos pelo painel do Figma Sites e verifique no preview. Publique o site e compartilhe a URL.

2. Para que serve o recurso "Preview" no Figma Sites?

  • Para exportar o HTML do site como arquivo .zip
  • Para compartilhar o site com o cliente antes de publicar
  • Para testar o protótipo no Figma Prototyping
  • Para renderizar e testar o site diretamente no canvas do Figma, sem publicar
O Preview renderiza o HTML resultante diretamente no canvas do Figma, permitindo testar scroll, responsividade e interações sem precisar publicar — acelerando a iteração.

3. Qual recurso do design Figma é mais importante para garantir boa responsividade no Figma Sites?

  • Auto Layout com tamanhos Fill e Hug, e Constraints bem configurados
  • Usar somente cores sólidas sem gradientes
  • Criar todos os frames com largura exatamente de 1440 px
  • Usar apenas fontes do Google Fonts
Auto Layout com Fill/Hug e Constraints corretos fazem os elementos se adaptarem naturalmente a diferentes larguras — o mesmo princípio do Flexbox no CSS. É o que o Figma Sites usa para gerar o CSS responsivo.
