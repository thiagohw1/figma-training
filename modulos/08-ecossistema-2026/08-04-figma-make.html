Figma Make — IA prompt-to-code

Escreva o que você quer em linguagem natural e o Figma Make transforma isso em um protótipo funcional rodando no browser. É a fusão entre ideação e código — acelerada por inteligência artificial.

⏱️ Leitura: ~17 min 🎯 Nível: Intermediário/Avançado 🛠️ Experimente no Figma Make

Ao final desta lição você será capaz de

  • Entender o que é o Figma Make e como ele difere do Figma Sites;
  • Criar um app funcional a partir de um prompt descritivo;
  • Iterar sobre o resultado conversando com a IA;
  • Reconhecer os pontos fortes e os limites do Figma Make;
  • Decidir quando usar o Make vs. outros fluxos de prototipagem ou desenvolvimento.

O que é o Figma Make?

Figma Make é a ferramenta de geração de código por IA do Figma, anunciada na Config 2025. Diferente do Figma Sites (que publica HTML estático a partir de um design), o Figma Make gera código funcional — HTML, CSS e JavaScript — a partir de um prompt de texto ou de um design existente no Figma.

O resultado é um web app interativo: formulários que funcionam, navegação entre telas, animações, lógica condicional básica. Você pode pensar nele como "Cursor/v0 dentro do Figma", voltado especificamente para o fluxo de trabalho de designers.

Figma Make vs. Figma Sites

O Figma Sites parte de um design visual e o publica como site estático. O Figma Make parte de uma descrição em linguagem natural (ou de um design) e gera código funcional com interatividade e lógica. O Make é para prototipagem rápida de apps; o Sites é para publicação de sites de marketing.

Como o Figma Make funciona

O Figma Make funciona como um loop de chat com uma IA especializada em geração de UI:

  1. Você descreve o que quer em linguagem natural.
  2. A IA gera o código (HTML/CSS/JS ou React, dependendo das opções) e renderiza um preview ao vivo.
  3. Você vê o resultado e pode pedir ajustes conversacionalmente.
  4. A IA modifica o código e atualiza o preview.
  5. Quando estiver satisfeito, você pode exportar o código ou publicar como protótipo.

Você também pode começar a partir de um frame do Figma Design: selecione um frame e peça ao Make para transformá-lo em código funcional. A IA usa o design como referência visual e gera o código correspondente.

Fluxo prompt → app: exemplo passo a passo

Vamos criar um app de lista de tarefas (to-do list) usando o Figma Make:

  1. Abra o Figma Make. No arquivo Figma, acesse o menu "Make" (ou via painel lateral). A interface de chat abre ao lado do canvas.
  2. Digite seu prompt inicial. Escreva algo como: "Crie um app de lista de tarefas com fundo branco. O usuário deve conseguir adicionar tarefas digitando num campo e apertando Enter. Cada tarefa aparece na lista com um checkbox para marcar como concluída. Tarefas concluídas ficam riscadas. Deve haver um botão para limpar as tarefas concluídas. Design minimalista com fonte Inter e cor primária #6C4CF1."
  3. Aguarde a geração. A IA processa o prompt e em segundos gera o código HTML/CSS/JS. Um preview aparece ao lado do chat.
  4. Teste o app gerado. Clique no preview, adicione algumas tarefas, marque como concluídas, clique em limpar. Avalie o que funcionou e o que precisa de ajuste.
  5. Itere com mensagens de ajuste. Digite pedidos específicos no chat: "O checkbox está muito pequeno. Aumente para 20px." ou "Adicione uma contagem de tarefas pendentes no topo da lista." A IA modifica apenas o trecho relevante do código.
  6. Adicione uma feature nova. "Adicione a possibilidade de editar uma tarefa clicando duas vezes no texto dela." — peça funcionalidades progressivamente.
  7. Exporte ou publique. Quando estiver satisfeito, use "Export" para baixar o código ou "Publish" para gerar uma URL compartilhável do protótipo.
Prompts mais eficazes

Seja específico sobre: (1) o que o app faz, (2) as interações principais, (3) o estilo visual desejado (cores, fontes, feel). Evite prompts vagos como "faça um app bonito". Quanto mais contexto você der, mais próximo do resultado esperado será a primeira geração — e menos iterações você vai precisar.

Pontos fortes do Figma Make

  • Velocidade extrema: de zero a protótipo funcional em minutos, sem escrever uma linha de código manualmente.
  • Iteração conversacional: em vez de editar código diretamente, você descreve o que quer mudar em linguagem natural.
  • Integração com o design: pode usar um frame do Figma Design como ponto de partida visual.
  • Prototipagem de alta fidelidade: o resultado tem interatividade real (formulários, estados, navegação) que o Prototyping nativo do Figma não consegue simular com a mesma facilidade.
  • Validação rápida: ideal para testar hipóteses de UX com usuários antes de comprometer tempo de desenvolvimento real.

Limites do Figma Make

  • Não é produção: o código gerado é para prototipagem e demonstração, não necessariamente para ir para um ambiente de produção sem revisão de um desenvolvedor.
  • Sem back-end: não há persistência de dados real. Dados digitados somem ao recarregar a página (a menos que use localStorage, que você pode pedir no prompt).
  • Qualidade do código varia: a IA pode gerar código funcional mas não otimizado ou não acessível. Revisão técnica é recomendada se o código for para produção.
  • Complexidade tem limites: apps muito complexos com muitas telas e lógica de negócio acabam saindo do controle da IA. Divida em partes menores.
  • Dependência de créditos de IA: o uso do Make consome créditos de IA do plano Figma. Planos gratuitos têm limites.
Use o Make para aprender e prototipar, não para produção

O Figma Make é uma ferramenta de exploração e comunicação, não um substituto para desenvolvimento de software. O código gerado deve ser revisado por um desenvolvedor antes de ir para produção. Pense nele como um "esboço em código" — útil para validar ideias rapidamente.

Dica de profissional: design + Make como pitch

Um fluxo poderoso: (1) desenhe as principais telas no Figma Design com atenção visual, (2) use o Make para transformar o design em protótipo funcional rápido, (3) apresente aos stakeholders ou ao time de engenharia um demo que "pareça real" sem esperar semanas de desenvolvimento. Isso acelera decisões de produto.

Exemplo de uso real

Um time de produto precisava validar se usuários de um app de finanças usariam um recurso de metas de economia. Em vez de esperar o desenvolvedor, o designer usou o Figma Make com o prompt: "Crie a tela de 'Nova Meta de Economia'. O usuário digita o nome da meta, o valor total e a data limite. Ao salvar, aparece um card na lista com um progress bar de 0%. O design deve seguir Material Design 3 com cor primária #1976D2." Em 15 minutos, tinha um protótipo funcional. Testou com 5 usuários no mesmo dia. Com o feedback, voltou ao Make, pediu ajustes e fez mais um round de testes no dia seguinte — tudo antes de qualquer linha de código de produção.

Resumo

  • Figma Make gera código funcional (HTML/CSS/JS) a partir de prompts ou designs do Figma.
  • Diferente do Figma Sites (sites estáticos), o Make cria apps interativos com lógica real.
  • A iteração é conversacional: você pede ajustes em linguagem natural.
  • Pontos fortes: velocidade, prototipagem funcional, integração com design.
  • Limites: sem back-end real, qualidade de código variável, não é para produção direta.
  • Ideal para: testes de usabilidade, demos para stakeholders e validação de hipóteses.
✍️ Exercício

Crie um app de clima com prompt

Use o Figma Make para criar um mini-app de previsão do tempo fictício:

  1. Prompt inicial: "Crie um app de clima com fundo gradiente de azul escuro para azul claro. Mostra a cidade atual (use 'São Paulo' como fixo), temperatura em °C, condição do tempo (Ensolarado), e três cards menores com a previsão dos próximos 3 dias. Design moderno e minimalista."
  2. Teste o resultado e anote 2–3 pontos que você quer melhorar.
  3. Faça pelo menos 3 pedidos de ajuste conversacionais (ex.: mudar cor, adicionar ícone, ajustar tipografia).
Critério de sucesso: o app resultante tem o layout de clima descrito, passou por pelo menos 3 iterações e o resultado final ficou visivelmente diferente (e melhor) do que a primeira geração.
🏆 Desafio

Design → Make: transforme um frame em app

Desenhe no Figma Design uma tela de login com email, senha e botão "Entrar". Selecione o frame e use o Figma Make com a instrução "Transforme este design em código funcional. O formulário deve validar se o email é válido e se a senha tem pelo menos 8 caracteres. Exiba mensagens de erro inline. Ao clicar em Entrar com dados válidos, navegue para uma tela de boas-vindas simples." Itere até ter um formulário com validação funcional e navegação entre telas.

QuizTeste seu conhecimento

1. Qual é a principal diferença entre o Figma Make e o Figma Sites?

  • O Make é gratuito; o Sites é pago
  • O Make gera código funcional com interatividade e lógica; o Sites publica HTML estático de designs visuais
  • O Make funciona só com designs existentes; o Sites aceita prompts de texto
  • O Make é para mobile; o Sites é para desktop
O Figma Make parte de um prompt e gera código funcional (com lógica, estados, interações reais). O Figma Sites transforma um design visual em HTML estático publicado. São ferramentas complementares para casos de uso diferentes.

2. Por que o Figma Make NÃO deve ser usado diretamente para código de produção sem revisão?

  • Porque ele gera código apenas em Figma DSL, não em HTML/JS padrão
  • Porque o código gerado tem licença restrita
  • Porque o código pode não ser otimizado, não ser acessível e pode ter falhas de segurança não visíveis na interface
  • Porque o Make não suporta CSS — apenas estilos inline
O código gerado por IA pode ser funcional visualmente mas carecer de acessibilidade, otimização de performance, tratamento de erros adequado e padrões de segurança. Revisão por um desenvolvedor é essencial antes de ir para produção.

3. Qual é o melhor cenário de uso para o Figma Make?

  • Criar um protótipo funcional para teste de usabilidade com usuários reais em poucas horas
  • Desenvolver o back-end de um aplicativo SaaS
  • Substituir completamente o trabalho de um desenvolvedor front-end sênior
  • Publicar um site de e-commerce com pagamento real
O grande valor do Make está na velocidade de prototipagem: em horas você tem um app interativo funcional o suficiente para testes de usabilidade reais, sem esperar semanas de desenvolvimento.
