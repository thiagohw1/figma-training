Performance e higiene de arquivos

Um arquivo Figma lento trava reuniões, frustra o time e destrói a produtividade. Entenda o que pesa, como limpar e como manter seu arquivo rápido e organizado ao longo do projeto.

⏱️ Leitura: ~18 min 🎯 Nível: Profissional 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Identificar os principais causadores de lentidão em arquivos Figma;
  • Otimizar o uso de imagens, instâncias e efeitos para manter o arquivo ágil;
  • Limpar estilos, variáveis e componentes não utilizados;
  • Organizar e arquivar conteúdo sem perder histórico;
  • Decidir quando dividir um arquivo grande em múltiplos arquivos menores.

Por que arquivos Figma ficam lentos?

O Figma renderiza tudo no browser via WebGL. Cada camada visível, cada efeito e cada imagem contribui para a carga de processamento. Em arquivos de longa duração, o acúmulo de camadas ocultas, imagens não otimizadas, efeitos custosos e instâncias quebradas vai degradando a performance progressivamente.

Os principais culpados, em ordem de impacto:

Imagens não otimizadas são a maior causa de lentidão. Efeitos em excesso vêm logo depois.

Imagens: o maior peso do arquivo

Uma foto de produto em 4K (4000×3000 px, 8 MB) inserida num frame de 300×200 px no Figma ainda pesa 8 MB. O Figma não redimensiona nem comprime automaticamente. Multiplique por 50 imagens assim e você tem 400 MB de arquivo.

Boas práticas para imagens

  • Redimensione antes de importar. Se a imagem vai ser exibida em 600px de largura, exporte-a a 1200px (2× para Retina) e comprima antes de importar. Use ferramentas como Squoosh, TinyPNG ou ImageOptim.
  • Use o formato correto. JPEG para fotos; PNG para imagens com transparência; WebP para web (menor tamanho). No Figma, PNG é o padrão de importação.
  • Evite imagens vetoriais como bitmap. Se você tem um ícone SVG, importe como SVG (File → Place Image ou arraste o .svg), não como PNG. Vetores são infinitamente escaláveis e pesam bytes, não megabytes.
  • Use fill em vez de imagem solta. Em vez de colocar uma imagem sobre um frame, use-a como Fill do próprio frame (clique no fill, troque para Image). Isso evita uma camada extra e mantém o recorte consistente.
Verifique o tamanho do arquivo

No menu principal do Figma, vá em File → File size. Arquivos acima de 50 MB começam a ficar lentos em conexões normais; acima de 100 MB, espere lentidão mesmo em boas conexões. Se seu arquivo está nessa faixa, é hora de agir.

Instâncias vs. cópias: não duplique, instancie

Quando você pressiona Ctrl/⌘ + C e Ctrl/⌘ + V em um componente, você cria uma instância — uma referência ao componente mestre que compartilha a definição original. Isso é leve e correto.

O problema é quando você usa Ctrl/⌘ + D (duplicate) em um frame que não é componente, ou quando desanexa instâncias desnecessariamente. Cada cópia desanexada é um objeto independente que carrega todo o seu conteúdo duplicado.

Como identificar cópias desnecessárias

  1. Selecione todos os frames de tela. Use Ctrl/⌘ + A na página, depois filtre por frames no painel esquerdo.
  2. Verifique quais são instâncias de componente. Instâncias mostram o ícone de componente (losango roxo) na sidebar. Elementos sem esse ícone são cópias soltas.
  3. Reconverta grupos repetidos em componentes. Se você tem o mesmo card copiado 20 vezes, selecione uma cópia, pressione Ctrl/⌘ + Alt + K para criar o componente mestre, depois substitua as cópias por instâncias.
  4. Use o plugin "Similayer" para localizar duplicatas. O Similayer identifica camadas com o mesmo nome ou estrutura e ajuda a consolidá-las em componentes.

Efeitos custosos: use com moderação

O Figma calcula efeitos como Background Blur, Layer Blur e Drop Shadow complexas em tempo real. Em telas com muitos elementos com blur ou sombras sofisticadas, o desempenho de renderização cai visivelmente.

Regras práticas para efeitos

  • Blur: limite a 1–2 elementos com blur por tela. Background blur (frosted glass) é especialmente pesado — nunca aplique em mais de 3 elementos por tela.
  • Sombras: prefira sombras simples (1 camada, offset pequeno, spread zero). Empilhar 3–4 camadas de sombra num card multiplica o custo de renderização.
  • Gradientes em texto: texto com fill de gradiente é calculado de forma diferente do texto com cor sólida. Use com parcimônia.
  • Efeitos em grupos grandes: aplicar blur ou sombra num frame que contém 50 camadas é muito mais custoso do que aplicar no frame mais interno.
Background blur no iOS/Android é ilusão no Figma

No Figma, o Background Blur usa o conteúdo do próprio arquivo como fundo, não o conteúdo real do app. Em protótipos exportados, o efeito pode não aparecer corretamente se não houver conteúdo atrás. Sempre coloque um fundo colorido ou uma imagem representativa atrás dos elementos com blur para o protótipo ficar correto.

Camadas órfãs: o lixo invisível

"Camadas órfãs" são objetos que estão no arquivo mas não fazem parte de nenhuma tela entregável: elementos ocultos esquecidos, frames fora da área de trabalho, objetos que sobraram de tentativas descartadas. Elas contribuem para o tamanho do arquivo e para a confusão na sidebar.

Como limpar camadas órfãs

  1. Mude a visualização para "Show all layers". No painel de layers, certifique-se de que layers ocultas estão visíveis (ícone de olho na barra superior do painel).
  2. Selecione tudo na página com Ctrl/⌘ + A. Depois olhe quantos itens estão selecionados. Se o número for muito maior que o esperado, há conteúdo escondido.
  3. Mova objetos suspeitos para a página Archive. Nunca delete imediatamente — mova primeiro. Depois de uma sprint sem reclames, delete da Archive.
  4. Use o plugin "Clean Document". Este plugin identifica e lista camadas ocultas, frames vazios e elementos fora da área de trabalho para você revisar e limpar em lote.

Limpar estilos e variáveis não utilizados

Ao longo de um projeto, styles de cor, de texto e de efeitos acumulam: cores testadas e descartadas, tipografias trocadas, efeitos de uma versão antiga. No Figma, eles continuam existindo mesmo sem usar nenhum elemento.

Como limpar estilos não utilizados

Infelizmente o Figma nativo não tem um botão "Limpar estilos não utilizados". Use o plugin Style Organizer ou Variables Cleaner para:

  • Listar todos os estilos/variáveis do arquivo;
  • Identificar quais não têm nenhuma referência no documento;
  • Deletar em lote os não utilizados com um clique.

Execute essa limpeza ao final de cada fase do projeto (antes de uma revisão, antes de entregar para dev).

Limpeza como ritual de sprint

Os melhores times têm uma "sexta de limpeza": 30 minutos na última sexta de cada sprint dedicados exclusivamente à higiene do arquivo. Sem design novo, apenas limpeza: renomear, arquivar, limpar estilos, verificar componentes. Isso evita que a dívida técnica do design se acumule.

Quando dividir um arquivo grande

Às vezes o problema não é limpeza — é tamanho intrínseco. Um produto grande com 200 telas, sistema de design e protótipos em um único arquivo vai ser lento por natureza. Considere dividir quando:

  • O arquivo tem mais de 80–100 MB;
  • O carregamento inicial demora mais de 15–20 segundos;
  • Múltiplos designers trabalhando simultaneamente causam conflitos frequentes;
  • O arquivo mistura sistema de design com telas de produto (sempre devem ser arquivos separados).

Estratégia de divisão recomendada

Exemplo de uso real

O time de design do Nubank mantém o design system (Nautilus) em um arquivo separado do qual os arquivos de produto apenas importam componentes. Quando um arquivo de produto fica grande demais (geralmente acima de 60 MB), ele é dividido por squads: um arquivo por feature team. Cada squad tem seu próprio arquivo de produto que consome do sistema central.

Essa estrutura permite que dezenas de designers trabalhem em paralelo sem conflitos e sem degradar a performance do arquivo compartilhado.

Resumo

  • Otimize imagens antes de importar: redimensione para o tamanho de exibição × 2 e comprima (Squoosh, TinyPNG).
  • Prefira instâncias a cópias; nunca desanexe componentes sem necessidade.
  • Limite blur e sombras complexas; aplique efeitos nos frames mais internos possíveis.
  • Limpe camadas ocultas/órfãs e mova para Archive antes de deletar.
  • Use plugins (Clean Document, Style Organizer, Variables Cleaner) para limpeza em lote.
  • Divida arquivos acima de 80–100 MB em múltiplos arquivos por responsabilidade.
✍️ Exercício

Auditoria e limpeza de arquivo

Pegue um arquivo Figma que você usa (ou crie um com propósito), e execute uma auditoria completa de performance:

  1. Verifique o tamanho do arquivo em File → File size e anote o valor inicial.
  2. Identifique as 3 maiores imagens do arquivo (verifique os fills de frame). Se alguma passar de 1 MB, comprima e reimporte.
  3. Instale o plugin Clean Document e execute-o. Liste quantas camadas ocultas e frames vazios ele encontrou.
  4. Limpe os estilos não utilizados com o Style Organizer.
  5. Verifique o tamanho do arquivo novamente. Qual foi a redução?
Critério de sucesso: o arquivo ficou pelo menos 20% menor, ou você documentou por que não havia muito a limpar.
🏆 Desafio

Crie um ritual de manutenção para o seu time

Escreva um checklist de "higiene quinzenal de arquivo" para um time fictício de 4 designers. O checklist deve incluir: quando executar cada tarefa, quem é responsável, quais plugins usar e como medir o sucesso (ex.: arquivo abaixo de X MB, zero camadas sem nome). Formate o checklist como um frame no próprio Figma que pode ser colado na página Cover do arquivo.

QuizTeste seu conhecimento

1. Qual é o principal causador de lentidão em arquivos Figma, segundo as boas práticas?

  • Imagens grandes não otimizadas
  • Excesso de componentes criados
  • Muitas páginas no arquivo
  • Uso de variáveis em vez de estilos
Imagens grandes não otimizadas são o maior causador de arquivos pesados no Figma. Uma única foto em 4K pode pesar mais que centenas de frames vetoriais.

2. Qual é a diferença fundamental entre criar uma instância e fazer uma cópia de um frame no Figma?

  • Instâncias são mais difíceis de editar do que cópias
  • Cópias mantêm o vínculo com o componente mestre; instâncias não
  • Instâncias compartilham a definição do componente mestre; cópias são objetos independentes
  • Não há diferença — ambas pedem a mesma quantidade de memória
Instâncias são referências ao componente mestre — quando o mestre muda, todas as instâncias atualizam. Cópias desanexadas são objetos independentes que acumulam dados duplicados e não se atualizam com o mestre.

3. A partir de qual tamanho de arquivo o Figma começa a apresentar lentidão notável em condições normais de conexão?

  • 10 MB
  • 25 MB
  • 40 MB
  • 50–80 MB
Arquivos acima de 50 MB começam a ficar lentos em conexões normais. Acima de 100 MB, a lentidão é perceptível mesmo em boas conexões. O ideal é manter arquivos de produção abaixo de 50 MB.
