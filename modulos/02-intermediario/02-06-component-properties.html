Component Properties

Component Properties são a evolução das variações no Figma: em vez de criar uma variant para cada combinação possível, você expõe controles diretamente no painel da instance — mostrar/ocultar elementos, trocar ícones, editar textos — tudo sem sair da tela que está desenhando.

⏱️ Leitura: ~20 min 🎯 Nível: Intermediário 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Criar e configurar os quatro tipos de Component Property: Boolean, Instance swap, Text e Variant;
  • Expor properties de instâncias aninhadas para o nível superior;
  • Decidir quando usar cada tipo de property;
  • Construir um card configurável com imagem, ícone e texto editáveis.

Por que Component Properties?

Antes das Component Properties, para criar um card que podia ou não ter uma imagem, você criava duas variants: "with image" e "without image". Para um card com 5 elementos opcionais, você precisaria de 2⁵ = 32 variants. Impraticável.

Com Component Properties, você declara no componente: "este elemento pode ser mostrado ou oculto" (Boolean), "este ícone pode ser trocado" (Instance swap), "este texto pode ser editado" (Text). O resultado: um único componente com um painel de configuração rico e claro.

Onde ficam as Component Properties?

Ao selecionar um Main Component, você vê a seção Component properties no painel direito. Clique em "+" para adicionar uma property. Ao selecionar uma Instance, você vê os controles das properties expostas — menus, toggles e campos de texto diretamente no painel.

Tipo 1: Boolean Property — mostrar ou ocultar

A Boolean Property associa uma camada (ou grupo de camadas) a um toggle true/false. Quando false, a camada fica oculta; quando true, fica visível. O Auto Layout do componente se ajusta automaticamente ao aparecer ou desaparecer do espaço.

Como criar

  1. Selecione o elemento no Main Component que você quer tornar opcional. Ex.: o ícone à esquerda do texto do botão.
  2. No painel direito, encontre "Layer". Ao lado do ícone de visibilidade (olho), clique no ícone de property (◈). Se não aparecer, selecione o Main Component e adicione uma Boolean property na seção Component properties, depois associe-a à camada.
  3. Nomeie a property de forma descritiva: Show icon, Has badge, Show label.
  4. Teste na instance. Ao usar uma instance, você verá no painel um toggle para essa property. Ativar/desativar mostra ou oculta a camada.
Boolean substitui muitas variants

Um botão com/sem ícone, com/sem badge, com/sem tooltip — sem Boolean Properties, seriam 2³ = 8 variants. Com Boolean Properties, é um único componente com 3 toggles. O painel fica mais limpo e intuitivo para os membros da equipe.

Tipo 2: Instance Swap — trocar sub-componentes

Instance Swap permite trocar qual componente está sendo usado em uma posição específica dentro do componente. O caso de uso mais comum: trocar ícones.

Imagine um botão com ícone. Em vez de criar uma variant para cada ícone possível (seriam centenas), você usa Instance Swap: o painel da instance mostra um seletor de componente, e o designer pode escolher qualquer ícone da biblioteca sem sair do painel.

Como criar

  1. No Main Component, selecione o sub-componente que será intercambiável. Ex.: o ícone dentro do botão (que já é uma instance de um componente de ícone).
  2. Clique no ícone de property ao lado do nome da layer, ou vá ao painel do Main Component e adicione uma Instance swap property.
  3. Nomeie a property: Icon, Left icon, Avatar.
  4. Defina os preferred values (opcional mas recomendado): uma lista curada dos ícones mais comuns para aquela posição. Eles aparecem como sugestões rápidas no seletor.

Tipo 3: Text Property — texto editável controlado

Text Property expõe um campo de texto do componente como uma property com nome. Ao usar a instance, em vez de precisar clicar no texto interno para editar, o campo aparece diretamente no painel de configuração da instance.

Isso é especialmente útil em:

  • Componentes de notificação ou toast com mensagem configurável.
  • Cards com título e descrição editáveis expostos no painel.
  • Badges com contagem (ex.: 3 notificações).

Como criar

  1. No Main Component, selecione a camada de texto.
  2. Clique no ícone de property ao lado do campo de texto no painel direito (parece um campo com símbolo de property).
  3. Nomeie: Label, Title, Count, Description.
  4. Na instance, você verá um campo de texto editável com esse nome no painel — sem precisar entrar na hierarquia de camadas.

Tipo 4: Variant Property — integração com Component Set

Variant Property é a própria troca de variant, mas exposta formalmente no painel de configuração. Se você já criou um Component Set com Variants (lição anterior), as Variant Properties aparecem automaticamente. Você pode combiná-las com Boolean, Instance Swap e Text Properties no mesmo componente.

Expondo properties de instâncias aninhadas

Quando um componente contém outros componentes (aninhados), as properties do sub-componente ficam "escondidas" no segundo nível. Para facilitar o uso, você pode expor essas properties no nível superior.

Exemplo: um Card component contém uma instance de Button. O Button tem uma property de texto ("Label"). Você pode expor essa property no Card para que o designer edite o texto do botão diretamente no painel do Card, sem precisar entrar no Button.

Como expor

  1. Selecione o Main Component do Card.
  2. Na seção Component properties, clique em "+" e escolha o tipo da property que quer expor.
  3. Selecione a sub-instance (Button) e associe a property ao campo correspondente do Button.
  4. Na instance do Card, o campo "Button label" aparecerá diretamente no painel — o designer não precisa saber que existe um Button aninhado.
Filosofia de exposição de properties

Pense em um componente como uma API. O painel de properties é a interface pública — o que você expõe lá é o que a equipe vai usar. Detalhes internos (como a estrutura exata do layout) ficam encapsulados. Exponha apenas o que precisa ser configurado; esconda a complexidade interna.

Quando usar cada tipo

TipoUse quandoAlternativa evitada
Boolean Um elemento é opcional (ícone, badge, label de erro) Variant "with icon" / "without icon"
Instance Swap Uma posição aceita diferentes componentes (ícone, avatar, thumbnail) Dezenas de variants para cada ícone possível
Text O texto muda entre instâncias mas não altera a aparência Override manual de camada de texto
Variant A aparência visual muda estruturalmente (cor, tamanho, forma) Componentes completamente separados

Exemplo de uso real: card configurável

Um card de produto de e-commerce pode ter:

  • Boolean: Show image (com/sem foto do produto)
  • Instance Swap: Badge icon (ícone de promoção, novidade, melhor avaliado)
  • Text: Product name, Price
  • Variant: Size (compact, default, featured)

Resumo

  • Boolean Property mostra/oculta camadas — substitui variants "with/without".
  • Instance Swap Property troca sub-componentes (ícones, avatars) sem variants extras.
  • Text Property expõe textos editáveis diretamente no painel da instance.
  • Variant Property é a troca formal de variant, integrada ao painel de properties.
  • Expose properties de sub-componentes para simplificar a interface de uso do componente.
  • Pense no componente como uma API: exponha só o que precisa ser configurado.
✍️ Exercício

Botão com ícone opcional e Instance Swap

  1. Crie um componente de botão com texto e um ícone à esquerda (use qualquer símbolo como placeholder de ícone — um frame 20×20 com uma letra).
  2. Adicione uma Boolean Property chamada Show icon associada ao ícone. Valor padrão: True.
  3. Adicione uma Text Property chamada Label associada ao texto. Valor padrão: Continuar.
  4. Crie uma instance, troque o Label para "Enviar" e desative Show icon. O botão deve se ajustar automaticamente.
Critério de sucesso: o painel da instance mostra os controles Label (texto) e Show icon (toggle), e ambos funcionam sem necessidade de entrar na hierarquia de camadas do componente.
🏆 Desafio

Card de usuário configurável

Crie um componente Card/User com as seguintes properties: Show avatar (Boolean), Avatar (Instance Swap — conectado a um componente de avatar), Name (Text), Role (Text), Show actions (Boolean — controla visibilidade de dois botões de ação). Use o card em 3 instâncias com configurações diferentes. Verifique que alterar o avatar no Main Component de avatar atualiza todas as instances do card que usam a instância padrão.

QuizTeste seu conhecimento

1. Você tem um componente de botão que pode ou não exibir um spinner de carregamento à direita do texto. Qual tipo de Component Property resolver isso?

  • Text Property
  • Boolean Property
  • Instance Swap
  • Variant Property
Boolean Property é ideal para mostrar/ocultar elementos opcionais, como um spinner que aparece apenas durante o carregamento. Evita criar duas variants (Default e Loading) só por causa de um elemento opcional.

2. Um componente de item de menu pode usar diferentes ícones à esquerda (home, search, profile...). Qual tipo de property permite trocar o ícone no painel da instance?

  • Boolean Property
  • Text Property
  • Instance Swap
  • Variant Property
Instance Swap permite substituir um sub-componente por outro da biblioteca. No caso de ícones, o designer pode escolher qualquer ícone diretamente no painel — sem criar dezenas de variants para cada ícone possível.

3. O que significa "expor a property de uma instância aninhada"?

  • Tornar uma property de um sub-componente visível no painel do componente pai
  • Tornar um componente visível na biblioteca da equipe
  • Converter uma instance em Main Component
  • Publicar as properties da library
Expor uma property de instância aninhada significa que uma property que existe em um sub-componente passa a aparecer no painel do componente pai. Isso simplifica o uso: o designer configura tudo no nível superior, sem entrar nos sub-componentes.
