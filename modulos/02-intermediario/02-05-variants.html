Variants — estados e variações

Variants permitem agrupar todas as variações de um componente — tamanhos, estados, cores — em um único Component Set, tornando seu design system organizado, intuitivo e fácil de usar por toda a equipe.

⏱️ Leitura: ~22 min 🎯 Nível: Intermediário 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Criar um Component Set com múltiplas variações;
  • Definir Properties e Values para cada variant;
  • Combinar múltiplas properties (ex.: Size × State) em uma matriz de variants;
  • Navegar e trocar variants no painel direito ao usar uma instance;
  • Nomear variants corretamente seguindo a convenção Property=Value.

O que são Variants?

Antes dos Variants, um designer precisava criar componentes separados para cada variação de um botão: Button/Primary/Default, Button/Primary/Hover, Button/Primary/Disabled, etc. O resultado era uma biblioteca fragmentada, difícil de navegar e de manter.

Com Variants, você agrupa todas as variações em um único bloco chamado Component Set. Cada variação é um componente dentro do set, identificado por um conjunto de properties (dimensões de variação) e values (valores possíveis para cada dimensão).

Analogia: o selector de roupas

Pense em uma loja online: você escolhe a camiseta (componente) e depois seleciona Tamanho: P/M/G e Cor: Azul/Preto/Branco. Variants fazem exatamente isso com componentes. Ao invés de escolher em bibliotecas diferentes, o designer troca properties no painel direito e a instance se transforma na variação correta.

Anatomia de um Component Set

Um Component Set contém:

  • Properties: as "dimensões" de variação. Ex.: Size, State, Type.
  • Values: os valores possíveis de cada property. Ex.: Size tem values Small, Medium, Large.
  • Variants: cada combinação única de property+value. Ex.: Size=Medium, State=Hover é uma variant.

O número total de variants em um set é o produto dos valores: 3 tamanhos × 4 estados = 12 variants.

Criando Variants: passo a passo

  1. Crie os componentes base. Crie todas as variações visualmente. Para um botão, faça: Default (fundo roxo), Hover (fundo ligeiramente mais claro), Pressed (fundo mais escuro), Disabled (fundo cinza, texto esmaecido). Cada variação é um frame separado com Auto Layout.
  2. Selecione todos os componentes. Selecione as quatro variações. É mais fácil se elas já forem Main Components. Se não forem, o Figma criará os componentes automaticamente no próximo passo.
  3. Combine em Component Set. No painel direito, clique em Combine as variants. O Figma envolve tudo em um Component Set (um frame com borda tracejada roxa) e tenta inferir properties automaticamente.
  4. Configure as Properties. No painel direito, você verá a seção Variant Properties. Edite o nome da property (ex.: renomeie a property padrão para State) e os values para cada componente (Default, Hover, Pressed, Disabled).
  5. Teste a seleção. Arraste o Component Set para o canvas (isso cria uma instance). Com a instance selecionada, veja no painel direito o menu de Variants — você pode trocar o State com um clique.

Combinando múltiplas Properties: a matriz

O poder real dos Variants aparece quando você combina duas ou mais properties. Um botão profissional pode ter:

  • Size: Small, Medium, Large (3 valores)
  • State: Default, Hover, Pressed, Disabled, Focused (5 valores)

Total: 3 × 5 = 15 variants. O Figma organiza isso em uma grade (matriz) onde as linhas representam uma property e as colunas outra.

A matriz de variants. O designer usa uma instance e seleciona Size e State no painel direito — o Figma troca para a variação correta automaticamente.

Nomenclatura: a convenção Property=Value

Quando o Figma cria os componentes dentro do set, ele nomeia cada um usando a convenção Property=Value. Exemplos:

  • Size=Small, State=Default
  • Size=Medium, State=Hover
  • Size=Large, State=Disabled

Siga essa convenção rigorosamente — ela é lida pelo Figma, por ferramentas de handoff (como o Dev Mode) e por plugins de geração de código.

Atenção ao nomear

Evite usar espaços e caracteres especiais nos nomes de properties e values. Prefira PascalCase ou camelCase: State, não estado do botão. Values devem ser consistentes entre componentes do mesmo set: se um componente usa Default, não use Normal em outro — isso cria duas properties diferentes.

Exemplo de uso real: botão com Size e State

Um design system de produto real terá um Component Set de botões com pelo menos Size (Small, Medium, Large) e State (Default, Hover, Pressed, Disabled). O fluxo do designer:

  1. Arrasta a instance de Button do painel Assets para a tela.
  2. No painel direito, vê os campos: Size: Medium e State: Default.
  3. Troca Size para Large e State para Disabled — a instance muda instantaneamente para a variação correta, sem procurar em listas de camadas.

Subconjunto da matriz de variants: 3 Sizes × 3 States. Ao usar uma instance, o painel direito mostra menus dropdown para selecionar Size e State — uma experiência muito mais fluida que procurar em dezenas de componentes separados.

Boas práticas para Variants

  • Use o mesmo estado visual de design para o mesmo State name em todos os componentes (o Hover de um botão e o Hover de um item de menu devem ter o mesmo feeling).
  • Comece com o Default e construa as outras variações a partir dele — mude o mínimo possível entre states.
  • Organize o Component Set visualmente na mesma ordem que os usuários pensam: da esquerda para a direita, Default → Hover → Pressed → Disabled.
  • Não crie variants desnecessárias. Se uma variação pode ser feita com um override simples (ex.: mudar o texto), prefira o override a criar uma variant.

Resumo

  • Variants agrupam variações de um componente em um único Component Set.
  • Properties são as dimensões de variação (Size, State, Type); Values são os valores possíveis.
  • A convenção de nomenclatura é Property=Value — siga rigorosamente.
  • Múltiplas properties criam uma matriz de variants. 3 sizes × 4 states = 12 variants.
  • O designer usa um menu dropdown no painel direito para trocar variants — sem procurar em listas.
✍️ Exercício

Botão com Size e State

  1. Crie visualmente 6 variações de botão: Small/Default, Small/Disabled, Medium/Default, Medium/Hover, Medium/Disabled, Large/Default.
  2. Selecione todas e clique em Combine as variants.
  3. Configure as properties: renomeie para Size (Small, Medium, Large) e State (Default, Hover, Disabled).
  4. Arraste uma instance do Component Set para o canvas. No painel direito, troque Size e State e confirme que a instância muda.
Critério de sucesso: com a instance selecionada, é possível trocar Size e State no painel direito e a instance muda visualmente para a variação correta.
🏆 Desafio

Toggle/Switch com todos os estados

Crie um Component Set para um toggle switch (componente de ligar/desligar) com as properties State (Off, On) e Disabled (False, True). Isso resulta em 4 variants: On/False, On/True, Off/False, Off/True. O toggle "On" deve ser roxo; o "Off", cinza; o "Disabled", opaco. Use Auto Layout em cada variant para garantir que são layouts consistentes.

2. Qual é a convenção de nomenclatura correta para uma variant?

  • button-small-hover
  • Small/Hover
  • Size=Small, State=Hover
  • small hover
A convenção oficial do Figma é Property=Value separado por vírgulas: Size=Small, State=Hover. Essa convenção é usada pelo Figma, Dev Mode e ferramentas de geração de código.

3. Um designer quer que um botão tenha texto diferente em telas diferentes sem criar uma variant. Como ele deve fazer?

  • Usar um override de texto na instance
  • Criar uma nova variant para cada texto
  • Fazer detach da instance
  • Criar um novo componente separado
Override de texto é a maneira correta: selecione a instance, clique no texto interno e edite. Não é necessário criar variants para conteúdo textual que varia entre instâncias — variants são para variações estruturais e visuais formais.
