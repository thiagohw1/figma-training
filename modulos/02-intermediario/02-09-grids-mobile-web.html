Grids e layout: mobile vs web/desktop

Um grid não é apenas linhas no fundo da tela — é o sistema que garante alinhamento, ritmo visual e consistência entre telas, breakpoints e plataformas. Nesta lição você aprende os padrões de grid para cada contexto e como configurá-los no Figma.

⏱️ Leitura: ~22 min 🎯 Nível: Intermediário 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Configurar grids de coluna para mobile, tablet e desktop no Figma;
  • Compreender margens, gutters e max-width de container;
  • Aplicar os breakpoints mais comuns no design responsivo;
  • Considerar safe areas no mobile e densidade de layout por plataforma.

O que é um sistema de grid?

Um sistema de grid divide a largura de uma tela em unidades repetíveis (colunas) separadas por espaços (gutters) e com margens nas bordas. Ele cria uma estrutura invisível que:

  • Garante que elementos se alinhem entre si em diferentes componentes e seções.
  • Define o ritmo horizontal da interface — a sensação de ordem e coerência.
  • Facilita o handoff: o desenvolvedor sabe exatamente quais larguras e espaçamentos usar.
  • Permite calcular a largura de elementos fluidos em relação às colunas (ex.: "este card ocupa 4 de 12 colunas = 33.3%").
Grid no Figma: Layout Grid

Para adicionar um grid a um frame no Figma, selecione o frame e no painel direito, na seção Layout grid, clique em "+". Você pode escolher entre Grid (grade uniforme), Columns (colunas) e Rows (linhas). Para colunas responsivas, use sempre Columns com a opção de Auto no count ou valores fixos. Salve como um Grid Style para reutilizar em toda a equipe (lição anterior).

Os três tipos de grid no Figma

No painel de Layout Grid, você configura:

  • Grid: uma grade uniforme de quadrados. Útil para verificar alinhamento em 8px ou 4px, mas não é o grid de colunas.
  • Columns: colunas verticais com count, gutter e margin configuráveis. Este é o grid de layout responsivo.
  • Rows: linhas horizontais. Menos comum no design de UI, mas útil para verificar espaçamento vertical.

Configurando um grid de colunas

  1. Selecione o frame que representa sua tela (ex.: Mobile 390×844).
  2. No painel direito, em Layout grid, clique em "+". Aparece um grid padrão. Clique no ícone de ajuste (quatro quadradinhos) para editar.
  3. Mude de "Grid" para "Columns" no seletor de tipo. Configure: Count (número de colunas), Type (Stretch para colunas que preenchem a largura, Fixed para largura fixa), Width (se Fixed), Margin e Gutter.
  4. Escolha uma cor de referência. Defina uma opacidade baixa (10–15%) para o grid ser visível mas discreto. Use rosa/vermelho para mobile, azul para tablet, verde para desktop — convenção comum.
  5. Salve como Grid Style (Grid/Mobile, Grid/Desktop) clicando no ícone de style ao lado do nome do grid.

Breakpoints são guias, não regras absolutas

Os breakpoints da tabela acima são os mais usados (especialmente no contexto do Tailwind CSS e Bootstrap), mas você pode definir os seus próprios. O importante é que a equipe de design e desenvolvimento use os mesmos valores. Documente os breakpoints no arquivo de design ou no CLAUDE.md do projeto.

Safe Areas no mobile

Dispositivos modernos têm áreas de tela "reservadas" pelo sistema operacional onde o conteúdo da app não deve aparecer:

  • Status bar (topo): onde aparecem hora, bateria, sinal. Em iPhones com Dynamic Island: ~59px. Em Androids: ~24–48px dependendo do modelo.
  • Home indicator / Navigation bar (base): a barra de gesto home ou os botões de navegação. Em iPhones modernos: 34px de safe area + o indicador visual. Em Androids com gestos: 20–48px.
  • Notch / Dynamic Island: recorte na parte superior que a câmera frontal ocupa.

No Figma, represente as safe areas com retângulos ou guides no topo e na base do frame. Muitas teams usam um componente de "Device Shell" que já inclui as safe areas.

Conteúdo interativo nas safe areas

Nunca coloque botões, campos de texto ou conteúdo crítico dentro das safe areas. O sistema operacional pode interceptar gestos nessa região. Mantenha o conteúdo da app dentro da área segura — o que está abaixo do status bar e acima do home indicator.

Padrões de layout por plataforma

Mobile: layout de coluna única

Em mobile, o layout é quase sempre de coluna única. O conteúdo flui de cima para baixo. As quatro colunas do grid raramente são usadas para criar duas colunas side-by-side — a tela é estreita demais. As colunas servem principalmente para:

  • Alinhar margens (o conteúdo fica nas colunas 1 a 4).
  • Criar grades de cards 2×N (2 colunas de cards em uma galeria).
  • Calcular larguras de elementos que devem ser 50% ou 100% da área útil.

Tablet: layout híbrido

Com 8 colunas, o tablet permite layouts mais ricos: uma sidebar de 3 colunas + conteúdo de 5 colunas, ou cards de 4 colunas lado a lado. É o breakpoint mais desafiador porque comporta os dois mundos — a interação mobile e a densidade desktop.

Desktop: layout multi-coluna

O desktop de 12 colunas é o mais flexível. Padrões comuns:

  • Layout editorial: sidebar 3 colunas + conteúdo 6 colunas + aside 3 colunas.
  • Dashboard: sidebar 2 colunas + área principal 10 colunas.
  • Grid de cards: 4 cards de 3 colunas cada = 4 × 3 = 12 colunas.
  • Hero full-width: conteúdo central de 8 colunas centralizado (2 colunas vazias de cada lado).

Exemplo de uso real: configurando grids no Figma para um produto

Ao iniciar o design de um produto responsivo, o workflow recomendado é:

  1. Crie três frames de referência. Mobile — 390×844, Tablet — 768×1024, Desktop — 1440×900. Nomeie-os claramente.
  2. Configure o grid em cada frame. Mobile: 4 colunas, margin 20, gutter 16. Tablet: 8 colunas, margin 24, gutter 20. Desktop: 12 colunas, margin 80, gutter 24.
  3. Salve como Grid Styles. Renomeie como Grid/Mobile, Grid/Tablet, Grid/Desktop. Agora qualquer designer da equipe aplica o grid correto em um clique.
  4. Adicione as safe areas no mobile. Crie um retângulo de 59px no topo (Status bar + Dynamic Island) e outro de 34px na base (Home indicator). Use fills com baixa opacidade como guia visual.
  5. Projete desktop primeiro ou mobile first? Não há resposta única — depende do produto e da audiência. Apps mobile-first: comece pelo mobile. Sistemas de administração e dashboards: comece pelo desktop.

Resumo

  • Grids de coluna garantem alinhamento, ritmo e consistência entre designs e desenvolvimento.
  • Mobile: 4 colunas, margin 16–24px, gutter 16px. Tablet: 8 colunas. Desktop: 12 colunas, margin 80px.
  • Breakpoints padrões: sm (480px), md (768px), lg (1024px), xl (1440px), 2xl (1920px).
  • Safe areas no mobile: não coloque conteúdo interativo na status bar (~59px) nem no home indicator (~34px).
  • Mobile exige alvos de toque mínimos de 44–48px; desktop pode ser mais compacto.
  • Salve grids como Grid Styles para reuso fácil em toda a equipe.
✍️ Exercício

Três frames responsivos com grid

  1. Crie três frames: Mobile 390×844, Tablet 768×1024, Desktop 1440×900.
  2. Configure o grid de colunas em cada frame conforme os valores da tabela desta lição.
  3. Salve cada grid como um Grid Style: Grid/Mobile, Grid/Tablet, Grid/Desktop.
  4. No frame Mobile, marque as safe areas com retângulos de 59px (topo) e 34px (base) em fill vermelho a 10% de opacidade.
  5. Em cada frame, desenhe um header simples que respeita as colunas (full-width) e um card que ocupa 2 colunas no mobile, 4 no tablet e 3 no desktop.
Critério de sucesso: os três frames têm grids salvos como styles, as safe areas estão marcadas no mobile, e o card muda de largura (mas mantém o conteúdo) nos três breakpoints.
🏆 Desafio

Layout responsivo completo de uma landing page

Projete a seção hero de uma landing page nos três breakpoints. No mobile: hero de coluna única, headline grande, CTA centralizado, imagem abaixo do texto (stacked). No tablet: headline à esquerda (5 colunas), imagem à direita (3 colunas). No desktop: headline e subtítulo à esquerda (6 colunas), ilustração animada à direita (6 colunas), CTAs alinhados ao grid. Todos os elementos devem se alinhar às colunas do grid da plataforma respectiva.

QuizTeste seu conhecimento

1. Qual é a configuração de grid padrão mais comum para um frame desktop de 1440px?

  • 12 colunas, margin 80px, gutter 24px
  • 4 colunas, margin 20px, gutter 16px
  • 8 colunas, margin 40px, gutter 16px
  • 16 colunas, margin 60px, gutter 16px
12 colunas, margin 80px, gutter 24px é o grid desktop mais comum, adotado pela maioria dos design systems (Material Design, Atlassian, IBM Carbon). As 12 colunas permitem dividir o layout em 2, 3 ou 4 partes iguais com facilidade.

2. Por que o tamanho mínimo de alvo de toque em mobile é 44×44px enquanto em desktop pode ser menor?

  • Porque telas mobile têm resolução menor
  • Por convenção, não há razão funcional
  • Porque o dedo é impreciso; o cursor do mouse permite áreas menores
  • Porque o sistema operacional bloqueia cliques menores que 44px
O dedo humano cobre uma área de contato de aproximadamente 44–57px. Um cursor de mouse é um ponto exato. Por isso, interfaces mobile precisam de alvos maiores para evitar cliques acidentais no elemento errado — esse é um dos princípios de acessibilidade das HIG da Apple e das diretrizes do Material Design.

3. O que são "safe areas" em design mobile?

  • Regiões de texto que nunca devem mudar de cor
  • Áreas reservadas pelo sistema operacional (barra de status, home indicator) onde conteúdo interativo não deve ficar
  • Zonas de margem do grid que garantem espaçamento consistente
  • Limite da área visível sem scroll na tela inicial
Safe areas são as regiões ocupadas pelo sistema operacional — barra de status no topo (com hora, bateria, sinal) e home indicator na base (em iPhones sem botão físico). Colocar conteúdo interativo nessas áreas causa problemas de usabilidade, pois o SO pode interceptar gestos.
