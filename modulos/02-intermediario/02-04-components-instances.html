Components e instances

Components são a base de qualquer design system no Figma: crie uma vez, use em qualquer lugar e, ao atualizar o original, todas as cópias se atualizam automaticamente. Essa é a diferença entre um arquivo de 100 frames e um design system real.

⏱️ Leitura: ~20 min 🎯 Nível: Intermediário 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Criar um componente (Main Component) a partir de qualquer elemento;
  • Usar e distribuir instances em múltiplas telas;
  • Aplicar overrides de texto, cor e layout em uma instance sem afetar o Main;
  • Resetar overrides, fazer detach e navegar no painel Assets;
  • Estruturar componentes aninhados para máxima flexibilidade.

Main Component vs Instance

O Figma trabalha com um modelo de herança unidirecional: existe o componente original (Main Component) e existem suas cópias (Instances). A relação é simples:

  • Alterações feitas no Main Component se propagam para todas as instances.
  • Alterações feitas em uma instance (chamadas de overrides) ficam locais — não afetam o Main nem outras instances.
  • Se o Main mudar, as instances recebem a atualização, mas mantêm seus próprios overrides quando possível.
Identificando Main Component e Instance visualmente

No canvas, o Main Component tem um ícone de losango com borda sólida (◆) na lista de Layers e no cabeçalho do painel. A Instance tem um losango cheio (◈). No painel direito, ao selecionar uma instance, você verá o nome do componente de origem e um botão de link para ir até o Main.

Criando um componente

  1. Desenhe o elemento. Crie o elemento que você quer tornar reutilizável. Por exemplo: um botão com Auto Layout horizontal, padding 12×20, texto "Primário", fill com a cor da marca, border-radius 8.
  2. Selecione e crie o componente. Com o elemento selecionado, pressione Ctrl + Alt + K (Windows) / ⌘ + ⌥ + K (Mac). Ou clique com o botão direito e escolha Create component. O ícone na lista de Layers muda para o losango de Main Component.
  3. Nomeie com cuidado. Dê um nome descritivo. Para organizar em grupos no painel Assets, use a barra "/" como separador: Buttons/Primary, Buttons/Secondary, Forms/Input.
  4. Crie uma instance. Segure Alt (Windows) / ⌥ (Mac) e arraste o Main Component — isso cria uma instance no lugar. Ou pressione Ctrl + D para duplicar (também gera uma instance).
Boas práticas de organização

Mantenha seus Main Components em uma página separada chamada "🧩 Components" ou "Library". Assim, o arquivo de design fica limpo e você sabe exatamente onde está cada componente. O Figma permite publicar essa biblioteca para toda a equipe via Publish styles and components.

Overrides: personalizando sem quebrar

Uma instance herda tudo do Main Component — mas você pode sobrescrever (override) certas propriedades para adaptar à situação. As overrides possíveis em instances simples são:

O que você NÃO deve (ou não pode) fazer em uma instance

Você não pode mover camadas internas de uma instance para fora dela, nem adicionar novas camadas. Se você precisar dessas alterações estruturais, use Detach (veja adiante) ou, melhor ainda, use Variants e Component Properties (próximas lições) para criar variações formais no próprio componente.

Resetar overrides

Se você fez overrides em uma instance e quer voltar ao estado do Main Component, clique com o botão direito na instance e escolha Reset all overrides. Para resetar apenas uma propriedade específica, clique com o botão direito na camada interna e escolha Reset changes.

Detach: desconectando uma instance

Às vezes você precisa modificar estruturalmente uma cópia — adicionar uma camada, mover elementos internos, alterar a hierarquia. Para isso, use o Detach instance: a instance se transforma em um frame comum, sem vínculo com o Main Component. Alterações futuras no Main não mais afetarão essa cópia.

Para fazer o detach: clique com o botão direito na instance e escolha Detach instance, ou use Ctrl + Alt + B (Windows) / ⌘ + ⌥ + B (Mac).

Detach é irreversível

Após o detach, não existe "re-attach". Se você perceber que precisava de uma variação formal, o caminho correto é criar um Variant (próxima lição) ou uma Component Property no componente original, não fazer detach. Use detach apenas quando realmente precisa de uma versão completamente única e ad-hoc.

O painel Assets

O painel Assets (ícone de quatro quadradinhos na barra esquerda, ou Ctrl + Alt + O / ⌘ + ⌥ + O) é onde você encontra todos os componentes disponíveis — do arquivo local e de bibliotecas publicadas da equipe.

Funcionalidades do painel Assets:

  • Busca: encontre rapidamente qualquer componente pelo nome.
  • Grupos: componentes nomeados com "/" aparecem organizados em pastas.
  • Drag-and-drop: arraste um componente do painel para o canvas — o Figma cria automaticamente uma instance.
  • Libraries: ative ou desative bibliotecas de equipe na aba Libraries.

Instâncias aninhadas

Componentes podem conter outros componentes dentro deles — são as instâncias aninhadas. Isso é fundamental para design systems mais complexos:

  • Um componente Card/Product pode conter uma instance de Button/Primary.
  • Um componente Navigation/Header pode conter instances de Icon/Menu e Avatar/Small.

Quando o componente de botão interno for atualizado (ex.: nova cor ou border-radius), todos os cards que usam esse botão se atualizam automaticamente. Isso é a base de um design system verdadeiro.

Substituindo instâncias aninhadas (Instance swap)

Dentro de uma instance, você pode trocar um sub-componente por outro: selecione a instance aninhada, e no painel direito você verá um menu de seleção de componente. Use isso para trocar ícones sem fazer detach. Na próxima lição vamos ver como formalizar isso com Component Properties do tipo Instance Swap.

Exemplo de uso real: botão reutilizável em 20 telas

Imagine um app com 20 telas. Cada tela tem ao menos um botão principal. Sem components, você tem 20 retângulos independentes — mudar a cor do botão exige 20 alterações manuais.

Com components: você cria um único Main Component Button/Primary. Em cada tela, você usa uma instance. Quando o cliente pede "o botão agora é verde, não roxo", você muda a cor no Main Component. Todas as 20 telas se atualizam em um segundo.

Resumo

  • O Main Component é o único original; Instances são as cópias vinculadas.
  • Alterações no Main se propagam para todas as instances automaticamente.
  • Overrides (texto, cor, imagem, visibilidade) personalizam instances localmente sem afetar o Main.
  • Detach desvincula a instance permanentemente — use só quando necessário.
  • O painel Assets centraliza todos os componentes para arrastar e usar.
  • Componentes aninhados formam a estrutura de um design system real.
✍️ Exercício

Biblioteca de botões

  1. Crie três variações de botão com Auto Layout: Primary (fundo colorido), Secondary (apenas borda), Destructive (fundo vermelho). Nomeie-os como Button/Primary, Button/Secondary, Button/Destructive.
  2. Transforme cada um em Main Component (Ctrl/⌘ + Alt/⌥ + K).
  3. Crie uma tela de confirmação com todos os três: "Confirmar" (Primary), "Cancelar" (Secondary), "Excluir conta" (Destructive) — cada um como instance.
  4. Mude a cor de fundo do botão Primary. Verifique que a instance "Confirmar" se atualizou.
Critério de sucesso: ao alterar o Main Component Primary, a instance na tela de confirmação reflete a mudança imediatamente.
🏆 Desafio

Card aninhado com componentes

Crie um componente Card/Product que contenha internamente instances de Button/Primary e Badge/Sale (um badge que você também deve criar como componente). Use o card em três telas diferentes, com overrides de texto (nome do produto, preço) e imagem em cada instance. Ao final, altere o border-radius do card no Main Component — confirme que os três cards nas telas se atualizam.

QuizTeste seu conhecimento

1. Você alterou a cor do botão no Main Component. O que acontece com as instances já espalhadas pelas telas?

  • Recebem a atualização automaticamente, mantendo overrides individuais
  • Nada muda — cada instance é independente
  • Recebem a atualização, mas perdem todos os overrides
  • O Figma exibe um aviso pedindo confirmação para cada instance
Alterações no Main Component propagam para todas as instances automaticamente. Overrides existentes (como textos diferentes) são mantidos, pois sobreescrevem somente as propriedades que o designer alterou explicitamente.

2. Qual atalho cria um componente a partir da seleção?

  • Ctrl/⌘ + G
  • Ctrl/⌘ + K
  • Ctrl/⌘ + Alt/⌥ + K
  • Shift + C
Ctrl + Alt + K (Win) / ⌘ + ⌥ + K (Mac) cria um componente da seleção atual. O Ctrl + G cria um Group (sem superpoderes de componente).

3. Quando você deve usar "Detach instance"?

  • Sempre que quiser mudar o texto de uma instance
  • Para propagar uma mudança para todas as outras instances
  • Para criar uma nova variação formal do componente
  • Quando precisa modificar a estrutura interna de uma cópia específica de forma única e irreversível
Detach converte a instance em um frame comum, sem vínculo com o Main. Use apenas quando precisar de uma versão estruturalmente única, irreversível. Para variações formais, prefira Variants e Component Properties.
