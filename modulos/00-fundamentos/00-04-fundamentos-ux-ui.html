Fundamentos de UX/UI design

Antes de abrir o Figma e começar a desenhar telas, você precisa entender por que você está desenhando. Design sem fundamentos de UX é decoração — bonito, mas inútil se o usuário não consegue usar.

⏱️ Leitura: ~20 min 🎯 Nível: Fundamentos 🛠️ Reflexão e análise prática

Ao final desta lição você será capaz de

  • Distinguir UX (User Experience) de UI (User Interface) com clareza;
  • Descrever o processo de design do início ao fim: pesquisa → ideação → wireframe → protótipo → teste → handoff;
  • Explicar os conceitos essenciais: usabilidade, hierarquia visual, affordance, consistência e acessibilidade;
  • Diferenciar fidelidade baixa (low-fi) de alta (high-fi) e saber quando usar cada uma;
  • Analisar criticamente a interface de um app real usando esses conceitos.

UX vs. UI — a diferença que todos confundem

Esses termos aparecem juntos com tanta frequência que muitas pessoas pensam que são a mesma coisa. Não são — mas se complementam profundamente.

UX — User Experience (Experiência do Usuário)

UX é tudo que o usuário sente e pensa ao interagir com um produto. É a disciplina mais ampla: pesquisa com usuários, arquitetura de informação, fluxos de navegação, mapas de jornada, testes de usabilidade. UX responde perguntas como: O usuário consegue completar a tarefa? Ele se sente confuso? Onde ele abandona o fluxo?

Uma boa UX pode ser invisível — o usuário simplesmente consegue fazer o que quer, sem frustração, sem perceber que houve um trabalho enorme por trás.

UI — User Interface (Interface do Usuário)

UI é a camada visual e interativa: cores, tipografia, ícones, botões, espaçamentos, estados de hover/pressed/disabled, animações de transição. UI responde perguntas como: Qual cor é o botão principal? Qual fonte usar no título? Como o modal aparece na tela?

Uma boa UI torna a experiência agradável e transmite a identidade da marca. É a "pele" do produto — mas sem um esqueleto de UX bem estruturado, a pele não funciona.

A analogia do restaurante

UX é o layout do restaurante: onde ficam as mesas, o fluxo para chegar ao banheiro, a organização do cardápio, o tempo de espera. UI é a decoração: as cores das paredes, as fontes do cardápio, a iluminação, a louça. Você pode ter uma decoração linda em um restaurante mal organizado — e as pessoas não voltam. Você pode ter uma decoração simples em um restaurante com fluxo perfeito — e as pessoas adoram.

O processo de design

Design não é "abrir o Figma e começar a desenhar". É um processo iterativo que começa muito antes da primeira tela. Veja as fases:

1. Pesquisa (Research)

Quem são os usuários? Quais são seus problemas reais? Que contextos eles vivem? A pesquisa pode ser qualitativa (entrevistas, observação) ou quantitativa (surveys, analytics). Sem pesquisa, você está desenhando para você mesmo — não para o usuário.

2. Ideação (Ideation)

Com os problemas mapeados, o time gera ideias. Brainstorming, Crazy 8s (8 ideias em 8 minutos), análise de concorrentes, benchmarking de referências. O objetivo é gerar muitas possibilidades antes de comprometer com uma solução.

3. Wireframe

A estrutura sem estilo visual. Um wireframe de baixa fidelidade (low-fi) é geralmente feito em preto e branco, com caixas cinzas e texto simulado. O objetivo é validar a lógica da interface antes de investir tempo em design visual. É muito mais barato corrigir um wireframe do que refazer telas completas.

4. Protótipo

Uma versão navegável do design. Pode ser low-fi (wireframes clicáveis) ou high-fi (telas finais com transições). O protótipo simula a experiência sem precisar de código — e é aqui que o Figma brilha.

5. Teste com usuários

O protótipo é colocado na mão de usuários reais. Eles tentam completar tarefas enquanto o designer observa (sem ajudar). Cada momento de confusão, hesitação ou erro é dado valioso. Os achados voltam para o ciclo de ideação/design.

6. Handoff para desenvolvimento

Com o design aprovado, os arquivos são preparados para os desenvolvedores: especificações de espaçamento, comportamento de componentes, assets exportados e fluxos documentados. No Figma, isso acontece via Dev Mode.

O processo de design é iterativo — os achados dos testes retroalimentam o ciclo continuamente.

Conceitos essenciais de UX/UI

Estes são os pilares que todo designer de interfaces precisa internalizar. Cada um influencia diretamente as decisões que você vai tomar no Figma.

Usabilidade

A facilidade com que um usuário consegue aprender e usar um sistema. Jakob Nielsen definiu 10 heurísticas de usabilidade que são referência até hoje — entre elas: visibilidade do status do sistema, controle do usuário, prevenção de erros e reconhecimento em vez de memorização. Um design usável resolve o problema do usuário sem fazê-lo pensar mais do que o necessário.

Hierarquia visual

O olho humano não lê uma tela de forma linear — ele percorre elementos em ordem de destaque. A hierarquia visual guia esse percurso usando tamanho (maior = mais importante), peso (negrito chama atenção), cor (contraste destaca), espaço (elementos isolados têm mais peso) e posição (canto superior esquerdo é lido primeiro em culturas ocidentais).

Affordance

A percepção intuitiva de como usar um elemento. Um botão com borda, sombra e cor forte "parece clicável" — isso é affordance visual. Um campo de texto com uma linha embaixo sugere que você pode digitar ali. Quando o affordance falha (ex.: um link que parece texto normal), o usuário não clica e perde conteúdo.

Consistência

Elementos com a mesma função devem ter a mesma aparência. Se o botão primário é azul com texto branco em uma tela, ele deve ser igual em todas as telas. Inconsistência gera insegurança — o usuário fica em dúvida se aquele botão de cor diferente faz a mesma coisa. Isso é um dos principais problemas que design systems resolvem.

Acessibilidade

Design que funciona para todos, incluindo pessoas com deficiências visuais, motoras, cognitivas ou auditivas. No contexto visual, os pontos mais críticos são: contraste de cores (mínimo WCAG AA: 4.5:1 para texto normal), tamanho de fonte (mínimo 16px para corpo de texto em mobile), áreas de toque (mínimo 44×44px) e não depender só de cor para transmitir informação (ex.: usar ícone + cor para indicar erro).

Design centrado no usuário (DCU)

Uma abordagem filosófica onde todas as decisões de design são orientadas pelas necessidades reais dos usuários, não pelas preferências do designer ou pelas opiniões do CEO. O DCU envolve pesquisa contínua, testes frequentes e humildade para jogar fora um mês de trabalho se os dados mostrarem que o caminho está errado.

O erro do "eu mesmo sou usuário"

Um viés cognitivo perigoso em design é assumir que porque você entende como usar, todos vão entender. Designers são especialistas no próprio produto — eles não representam o usuário médio. Por isso, testar com pessoas reais é insubstituível.

Fidelidade: low-fi vs. high-fi

Fidelidade é o nível de detalhe e realismo de um design. Não existe "melhor" — existe o mais adequado para a fase do projeto:

AspectoLow Fidelity (Baixa)High Fidelity (Alta)
VisualPreto e branco, formas simples, texto placeholder ("Lorem")Cores reais, tipografia final, imagens reais, ícones
InteratividadeCliques básicos, sem animaçãoTransições, micro-interações, estados completos
VelocidadeMuito rápido de criar (horas)Mais lento (dias/semanas)
Custo de mudançaBaixo — fácil de jogar foraAlto — refazer custa tempo real
Quando usarDiscovery, validação de fluxo, apresentar para stakeholders antes de investirTeste com usuários de usabilidade, handoff para dev, apresentações executivas
FerramentasPapel, Figma (frames cinzas), FigJamFigma (design completo)
Dica de profissional: comece low-fi, sempre

Profissionais experientes fazem wireframes de baixa fidelidade antes de qualquer pixel colorido — não porque são iniciantes, mas porque sabem que é muito mais barato descobrir que um fluxo está errado em 5 minutos de wireframe do que em 5 dias de design de alta fidelidade.

Por que estudar UX/UI antes de abrir o Figma

Muitas pessoas que aprendem Figma tecnicamente — sabem usar todas as ferramentas, conhecem todos os atalhos — produzem designs que não funcionam na prática. O Figma é o meio, não o fim. Entender UX/UI te dá o porquê por trás de cada decisão:

  • Por que usar 16px de fonte em vez de 12px? — Acessibilidade.
  • Por que o botão principal é colorido e o secundário é ghost? — Hierarquia visual e affordance.
  • Por que as ações mais importantes ficam no centro/baixo da tela mobile? — Alcance do polegar (zona de conforto de toque).
  • Por que fazemos wireframe antes? — Custo de mudança baixo durante validação.

Com esses fundamentos, cada escolha no Figma vai ter um motivo — e você vai conseguir argumentar suas decisões de design para qualquer stakeholder.

Resumo

  • UX = a experiência completa (pesquisa, fluxos, usabilidade); UI = a camada visual (cores, tipografia, componentes). Ambos são essenciais.
  • O processo de design segue: Pesquisa → Ideação → Wireframe → Protótipo → Teste → Handoff — e é iterativo.
  • Conceitos essenciais: usabilidade, hierarquia visual, affordance, consistência, acessibilidade e design centrado no usuário.
  • Low-fi serve para validar lógica rapidamente; high-fi serve para validar experiência e entregar para dev.
  • Entender esses fundamentos é o que transforma um operador de ferramenta em um designer de verdade.
✍️ Exercício

Análise crítica de interface

Escolha um app que você usa no dia a dia (iFood, Instagram, WhatsApp, Mercado Livre, etc.) e analise a tela principal usando os conceitos desta lição:

  1. Identifique a hierarquia visual: qual é o elemento mais destacado? Por quê?
  2. Aponte 2 affordances: o que nessa tela claramente "parece clicável" ou "parece digitável"?
  3. Encontre um exemplo de consistência (elementos similares com aparência similar).
  4. Verifique acessibilidade básica: algum texto tem contraste muito baixo com o fundo?
  5. Identifique uma decisão de UX: algo que foi colocado em destaque porque é a ação mais importante.
Critério de sucesso: você conseguiu identificar e nomear pelo menos 4 dos 5 conceitos na tela escolhida.

QuizTeste seu conhecimento

1. Qual é a principal diferença entre UX e UI design?

  • UX cuida das cores e UI cuida do fluxo de navegação
  • UX é sobre a experiência e fluxo do usuário; UI é sobre a aparência visual da interface
  • UX é feito por desenvolvedores e UI por designers
  • UX é para mobile e UI é para web
UX (User Experience) abrange pesquisa, fluxos, usabilidade e arquitetura de informação. UI (User Interface) é a camada visual: cores, tipografia, ícones e estados dos componentes. Ambos são necessários em um produto de qualidade.

2. O que é "affordance" em design de interfaces?

  • A capacidade de um design de rodar em múltiplos dispositivos
  • O espaçamento entre elementos de uma interface
  • A percepção intuitiva de como interagir com um elemento (ex.: botão "parece clicável")
  • A cor usada para indicar ações de perigo
Affordance é a pista visual que diz ao usuário como interagir com um elemento. Um botão com sombra e cor de destaque tem boa affordance porque "parece clicável". Quando a affordance falha, o usuário não descobre como usar a interface.

3. Por que fazer wireframes de baixa fidelidade antes do design final?

  • Porque é muito mais barato descobrir problemas de fluxo em wireframes do que refazer telas de alta fidelidade
  • Porque stakeholders preferem designs em preto e branco
  • Porque o Figma não suporta cores em wireframes
  • Porque wireframes de baixa fidelidade são obrigatórios por lei em projetos digitais
O principal argumento para começar com baixa fidelidade é o custo de mudança: corrigir um wireframe em preto e branco leva minutos; refazer telas de alta fidelidade pode levar dias. Wireframes validam a lógica antes de investir em design visual.
