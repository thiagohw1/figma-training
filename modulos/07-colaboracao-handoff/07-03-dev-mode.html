Dev Mode: inspeção e specs

O Dev Mode é a interface do Figma projetada especificamente para desenvolvedores — um modo de leitura especializado onde cada propriedade de design se torna uma spec mensurável e copiável. Nesta lição você aprende a usá-lo para fazer um handoff preciso e sem ambiguidade.

⏱️ Leitura: ~24 min 🎯 Nível: Profissional 🛠️ Pratique junto no Figma

Ao final desta lição você será capaz de

  • Alternar para o Dev Mode e entender sua interface;
  • Inspecionar medidas, espaçamentos, cores e tipografia de qualquer elemento;
  • Copiar valores de propriedades prontos para colar no código;
  • Usar "Compare changes" para ver o que mudou entre versões;
  • Marcar frames como "Ready for dev" e usar o Focus view para navegação eficiente.

O que é o Dev Mode?

Até 2023, desenvolvedores inspecionavam designs usando o painel Inspect dentro do modo de edição do Figma — funcionava, mas era uma experiência de segunda classe. Em junho de 2023, o Figma lançou o Dev Mode: uma interface completamente separada, projetada do zero para o fluxo de trabalho de desenvolvimento.

No Dev Mode, o arquivo se comporta de forma diferente:

  • A interface é simplificada — sem as ferramentas de criação que o dev não precisa;
  • O painel direito mostra specs técnicas em vez de controles de edição;
  • Valores são copiáveis em um clique no formato pronto para o código;
  • Há integrações com ferramentas de desenvolvimento (VS Code, Jira, Storybook etc.);
  • Existe um sistema de status ("Ready for dev", "In progress", "Complete") para rastrear o que está pronto para implementar.
Dev Mode e planos do Figma

O Dev Mode com recursos completos (geração de código, plugins, compare changes) está disponível nos planos Professional e acima para visualizadores (viewers). Desenvolvedores podem ter um assento de "Dev" com preço diferente dos editores. No plano Starter, o acesso é limitado.

Alternando para o Dev Mode

Para entrar no Dev Mode, use o alternador no canto superior direito da tela: clique no ícone de sinal de menor/maior (</>). A interface muda imediatamente — o canvas permanece, mas os painéis laterais se transformam em ferramentas de inspeção.

Para sair, clique novamente no mesmo ícone ou use Shift + D. Usuários com acesso somente de visualização entram automaticamente no Dev Mode quando abrem o arquivo.

Inspecionando elementos

Com o Dev Mode ativo, clicar em qualquer elemento no canvas abre o painel de inspeção completo à direita. Esse painel é organizado em seções que correspondem às propriedades mais usadas no código:

Medidas e posicionamento

O painel mostra as dimensões exatas do elemento (W × H), sua posição no frame pai (X, Y), e os valores de border radius. Ao passar o mouse sobre outros elementos com um elemento selecionado, o Figma exibe medidas de distância em destaque vermelho — a mesma funcionalidade de "medir" do modo de edição, mas mais proeminente aqui.

Cores e opacidade

Todas as cores do elemento aparecem em formatos copiáveis: HEX, RGB, HSL e CSS. Se o projeto usa Variables (tokens), o nome da variável é exibido ao lado do valor hexadecimal. Para copiar, basta clicar no valor — ele vai para a área de transferência automaticamente.

Tipografia

Para elementos de texto, o painel mostra: font family, font weight, font size, line height, letter spacing, text transform e outras propriedades. Cada valor é individualmente copiável.

Estilos e componentes

Se o elemento usa um Color Style ou Text Style, o nome do estilo é exibido com link. Se for uma instância de Component, o painel mostra o nome do componente e quais propriedades (variants) estão ativas.

Auto Layout como Flexbox

Frames com Auto Layout têm suas propriedades traduzidas para termos de CSS: direction, gap, padding, align-items, justify-content. Isso elimina a necessidade de "tradução" manual pelo desenvolvedor.

Copiando valores para o código

No Dev Mode, toda propriedade tem um botão de cópia que aparece ao passar o mouse. Mas há uma forma mais eficiente: o painel de código à direita gera automaticamente snippets completos — você escolhe a linguagem (CSS, iOS/SwiftUI, Android/Compose) e copia o bloco inteiro.

Para um texto selecionado, por exemplo, o snippet CSS gerado pode ser algo como:

font-family: 'Inter', sans-serif;
font-size: 14px;
font-weight: 600;
line-height: 1.2;
color: #FFFFFF;

Para frames com Auto Layout, o snippet incluirá as propriedades flex:

display: flex;
flex-direction: row;
align-items: center;
gap: 8px;
padding: 12px 20px;
Clique duplo para copiar o valor isolado

No painel de inspeção, clicar uma vez numa propriedade copia o valor nú (ex.: #6C4CF1). O botão "Copy CSS" no painel de código copia o snippet completo com declarações CSS. Use o primeiro para colar em tokens; o segundo para colar diretamente no código.

Compare changes: vendo o que mudou

Um dos recursos mais poderosos do Dev Mode é o Compare changes. Ele permite que o desenvolvedor compare a versão atual do design com uma versão anterior, vendo exatamente quais frames foram alterados.

Para acessar: no Dev Mode, clique em Compare changes no painel ou acesse pelo menu. Selecione duas versões do histórico para comparar. O Figma exibe um overlay visual mostrando:

  • Verde = novo elemento ou frame adicionado;
  • Vermelho = elemento ou frame removido;
  • Amarelo/laranja = elemento modificado.

Isso é valioso quando o design muda após o início da implementação — o dev pode ver exatamente o que foi alterado sem precisar revisar o arquivo inteiro.

Marcando como "Ready for dev"

O sistema de status do Dev Mode resolve um problema antigo: "esse design está finalizado ou ainda vai mudar?" Para marcar um frame ou seção como pronto para implementação:

  1. Selecione o frame no Dev Mode. Pode ser um frame de tela inteira ou um componente específico.
  2. Clique em "Mark as ready for dev". No painel direito, há um botão/toggle de status. Clique em Ready for dev. O frame recebe um indicador visual (ícone verde) visível para todos.
  3. Desenvolvedores filtram por status. No Dev Mode, os devs podem filtrar a visualização para ver apenas frames marcados como "Ready for dev" — evitando trabalhar em telas que ainda estão em rascunho.
  4. Atualize conforme o progresso. O status pode ser alterado para "In progress" quando o dev começa a implementar, e "Completed" quando terminar — criando um kanban nativo dentro do Figma.
Status como processo de qualidade

Defina uma regra no time: apenas o designer responsável pode marcar como "Ready for dev", e somente após a aprovação do design lead. Isso cria um gate de qualidade que evita que devs implementem designs em progresso — um dos maiores geradores de retrabalho em times de produto.

Focus view: navegando de frame em frame

O Focus view é um modo de navegação no Dev Mode onde você vê apenas um frame por vez, com setas para navegar entre eles sequencialmente. É ideal para um desenvolvedor que precisa implementar um fluxo completo:

  • Clique em Focus no painel do Dev Mode para entrar nesse modo;
  • O frame selecionado ocupa toda a área do canvas (sem os outros frames ao redor);
  • Botões de navegação permitem ir para o próximo ou anterior frame do fluxo;
  • O painel de specs na direita permanece atualizado para o frame focado.

Isso é especialmente útil quando o arquivo tem dezenas de frames e o desenvolvedor precisa focar apenas no fluxo que está implementando naquela sprint.

Navegação otimizada para desenvolvedores

O Dev Mode tem vários recursos pensados para o fluxo de trabalho de desenvolvimento:

  • Busca por componentes: campo de busca no painel esquerdo para encontrar componentes específicos rapidamente;
  • Filtro por status: mostrar apenas frames "Ready for dev", "In progress" ou todos;
  • Anotações (Annotations): designers podem deixar notas técnicas visíveis apenas no Dev Mode (veremos detalhes na lição 5);
  • Links para Jira/Storybook: plugins permitem vincular frames a tickets e componentes de código;
  • Exportar assets: selecionar e exportar ícones, imagens e ilustrações diretamente do Dev Mode sem precisar pedir ao designer.

Exemplo de uso real

Uma desenvolvedora front-end recebe um link para o Figma com o design da tela de checkout. Usando o Dev Mode:

  1. Ela filtra por Ready for dev — vê apenas os 3 frames aprovados;
  2. Usa o Focus view para trabalhar frame a frame sem distração;
  3. Clica no campo de e-mail e copia o snippet CSS da tipografia;
  4. Passa o mouse sobre os espaçamentos internos para ver os valores de gap e padding;
  5. Clica em "Compare changes" para ver o que o designer alterou desde ontem — apenas o botão mudou de cor;
  6. Exporta os ícones SVG diretamente do painel de exportação.

Todo esse processo sem precisar falar com o designer, sem screenshots, sem planilhas de spec.

Resumo

  • O Dev Mode é uma interface separada do Figma projetada para desenvolvedores — specs limpas, valores copiáveis, sem ruído de ferramentas de criação.
  • Alterne com Shift + D; o painel direito mostra medidas, cores, tipografia e code snippets.
  • Compare changes mostra exatamente o que mudou entre duas versões do design.
  • Ready for dev cria um sistema de status formal: o dev só implementa o que está aprovado.
  • Focus view permite navegar frame a frame sem distração — ideal para implementação sequencial de fluxos.
✍️ Exercício

Inspecionando um design completo

Abra qualquer arquivo de design no Figma e entre no Dev Mode (Shift + D):

  1. Selecione um botão e copie todos os valores: cor de preenchimento (HEX), border radius, padding (valores individuais), e o snippet CSS completo.
  2. Selecione um texto e copie a tipografia completa (family, size, weight, line-height).
  3. Com um elemento selecionado, passe o mouse sobre outros elementos vizinhos e anote as distâncias exibidas.
  4. Marque um frame como "Ready for dev" e verifique que o indicador visual aparece.
  5. Ative o Focus view e navegue entre 3 frames sequencialmente.
Critério de sucesso: você consegue listar todos os valores de spec de um componente sem consultar o designer, e o status "Ready for dev" é visível tanto no modo de edição quanto no Dev Mode.
🏆 Desafio

Implementar a partir do Dev Mode

Escolha um componente do seu design (botão, card, formulário) e implemente-o em HTML/CSS usando apenas o Dev Mode como fonte de verdade — sem perguntar ao designer nem adivinhar valores. Todos os valores de cor, tipografia, espaçamento e border radius devem vir diretamente do painel de inspeção. Compare o resultado no navegador com o design original; a diferença visual deve ser imperceptível.

  • Ver visualmente o que mudou no design entre duas versões do histórico, com indicadores de adicionado, removido e modificado
  • Comparar o design do Figma com o componente implementado no código
  • Comparar dois arquivos Figma diferentes lado a lado
  • Ver as diferenças entre branches antes de fazer o merge
O Compare changes compara a versão atual do arquivo com uma versão anterior do Version History, destacando em verde (novo), vermelho (removido) e amarelo (modificado) — perfeito para devs que precisam saber o que mudou desde ontem.

3. Qual é o propósito do status "Ready for dev" no Dev Mode?

  • Travar o frame para edição até que o dev termine a implementação
  • Exportar automaticamente os assets do frame para um repositório Git
  • Notificar o designer que o desenvolvimento foi concluído
  • Sinalizar ao desenvolvedor que aquele frame foi aprovado pelo designer e está pronto para implementação
O status "Ready for dev" é um sinal do designer para o desenvolvedor: "este design está finalizado e aprovado, pode implementar". Ele resolve o problema clássico de devs implementando designs que ainda estavam em rascunho.
