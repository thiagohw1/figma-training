Tokens → código

Design tokens são a linguagem que design e código compartilham. Design tokens: a cola entre design e código

Design tokens são pares nome–valor que representam decisões de design — cores, tipografia, espaçamento, elevação — numa forma que tanto designers quanto desenvolvedores podem usar como fonte única de verdade.

Em vez de o designer dizer "use aquele roxo" e o dev tentar achar a cor certa, o token color.primary.600 tem um valor exato (#6C4CF1) que é idêntico no Figma, no CSS, no iOS e no Android. A mudança desse valor num único lugar propaga automaticamente para todos os destinos.

Variables do Figma = Design Tokens

As Variables do Figma (lançadas em 2023 e expandidas continuamente) são a implementação nativa de design tokens dentro do Figma. Uma Variable de cor chamada color/primary/600 com valor #6C4CF1 é, na prática, um design token. O que muda é como você exporta essas Variables para uso no código.

Hierarquia de tokens: primitivos, semânticos e de componente

Tokens bem arquitetados têm três camadas:

  • Primitivos (Global): todos os valores brutos possíveis. color.blue.500 = #3B82F6. Esses tokens raramente são usados diretamente em componentes.
  • Semânticos (Alias): tokens com significado contextual que referenciam primitivos. color.action.primary = {color.blue.500}. Esses são usados em componentes. Troque o tema escuro apenas aqui.
  • De componente: tokens específicos de um componente. button.background.default = {color.action.primary}. Permitem ajustes finos por componente sem quebrar a escala global.

Primitivos definem valores brutos; semânticos criam significado; componentes consomem semânticos. Para trocar o tema, você só precisa reescrever a camada semântica.

Exportando Variables via REST API do Figma

O Figma expõe as Variables de um arquivo pela sua REST API. Isso significa que você pode automatizar a exportação dos tokens sem precisar de plugin ou ferramenta extra:

GET https://api.figma.com/v1/files/:file_key/variables/local
Authorization: Bearer SEU_TOKEN_DE_API

A resposta é um JSON com todas as coleções de variables, seus modos e valores. Um token de cor, por exemplo, aparece assim:

{
  "id": "VariableID:123:456",
  "name": "color/primary/600",
  "resolvedType": "COLOR",
  "valuesByMode": {
    "light-mode-id": { "r": 0.424, "g": 0.298, "b": 0.945, "a": 1 },
    "dark-mode-id": { "r": 0.608, "g": 0.506, "b": 1.0, "a": 1 }
  }
}

Note que as cores vêm em formato RGBA normalizado (0–1). Você precisará converter para HEX ou RGB para uso no CSS. Essa conversão pode ser feita por um script Node.js simples ou pelo Style Dictionary.

Use um token de API de leitura

Para automação, crie um token de API pessoal no Figma com escopo de leitura apenas (não escrita). Isso garante que o script de exportação não pode modificar acidentalmente o arquivo. Guarde o token como variável de ambiente (FIGMA_TOKEN) e nunca o commit no repositório.

Tokens Studio: gerenciamento avançado de tokens

O Tokens Studio for Figma (anteriormente "Figma Tokens") é o plugin mais adotado para gerenciar design tokens no Figma. Ele oferece recursos que a interface nativa de Variables ainda não tem (em 2025/2026):

  • Formato de arquivo universal: exporta tokens como JSON em múltiplos formatos;
  • Sincronização com Git: conecta diretamente ao GitHub/GitLab/Bitbucket — o time de design faz "push" dos tokens direto para o repositório;
  • Tokens compostos: typography, shadow e outros tokens que agrupam múltiplas propriedades em um único token;
  • Math tokens: tokens que são cálculos — spacing.xl = {spacing.base} * 3;
  • Temas múltiplos: gerencia light, dark, e temas de marca (white-label) com facilidade.

Workflow básico com Tokens Studio

  1. Instale o plugin. No Figma, abra o painel de Plugins e instale "Tokens Studio for Figma".
  2. Importe ou crie seus tokens. No painel do plugin, você pode criar tokens manualmente ou importar um JSON existente. Se você já tem Variables no Figma, o plugin pode importá-las automaticamente.
  3. Configure a sincronização com Git (opcional, mas recomendado). No painel de configurações do plugin, conecte ao repositório Git onde os tokens devem viver. O plugin cria/atualiza um arquivo tokens.json no repositório.
  4. Exporte os tokens. Use o botão "Export" do plugin para gerar o JSON de tokens. Escolha o formato: W3C Design Tokens, Style Dictionary, ou o formato nativo do plugin.

O formato W3C Design Tokens

Em 2025, o W3C finalizou a especificação Design Tokens Format Module — um formato JSON padronizado para design tokens que pode ser lido por qualquer ferramenta que implemente o spec. Isso é importante porque significa que você pode trocar de ferramenta (Figma → Penpot, por exemplo) sem precisar reescrever o pipeline.

Um token de cor no formato W3C parece assim:

{
  "color": {
    "primary": {
      "600": {
        "$type": "color",
        "$value": "#6C4CF1",
        "$description": "Primary brand color, main action"
      }
    }
  }
}

Ferramentas como Tokens Studio e Style Dictionary já suportam esse formato. O $type indica o tipo do token, $value o valor e $description a documentação.

Por que o formato W3C importa

Antes da padronização, cada ferramenta usava seu próprio JSON. Migrar de ferramenta significava reescrever o pipeline inteiro. Com o W3C Format, o JSON de tokens é portável — qualquer ferramenta compatível pode ler e processar sem transformação. É o mesmo princípio das variáveis CSS Custom Properties vs. variáveis Sass proprietárias.

Style Dictionary: transformando tokens em código

O Style Dictionary (criado pela Amazon, open source) é a ferramenta mais usada para transformar um arquivo JSON de tokens em outputs de código para múltiplas plataformas simultaneamente:

  • CSS Custom Properties (--color-primary-600: #6C4CF1;);
  • Sass/LESS variables ($color-primary-600: #6C4CF1;);
  • JavaScript/TypeScript objects (colorPrimary600: "#6C4CF1");
  • Swift constants para iOS;
  • Kotlin/XML para Android;
  • JSON para React Native.

A configuração básica do Style Dictionary define quais transformações aplicar e quais outputs gerar:

// style-dictionary.config.js
module.exports = {
  source: ["tokens/**/*.json"],
  platforms: {
    css: {
      transformGroup: "css",
      prefix: "ds",
      buildPath: "build/css/",
      files: [{ destination: "variables.css", format: "css/variables" }]
    },
    ios: {
      transformGroup: "ios-swift",
      buildPath: "build/ios/",
      files: [{ destination: "StyleDictionary.swift", format: "ios-swift/class.swift" }]
    }
  }
};
Um JSON → cinco plataformas

A beleza do Style Dictionary é que você mantém um arquivo de tokens (o JSON do Figma) e ele gera automaticamente CSS, SCSS, iOS Swift, Android XML e qualquer outro formato que seu time precise. Uma mudança de cor no Figma, exportada pelo Tokens Studio e processada pelo Style Dictionary, atualiza simultaneamente o web, o iOS e o Android — sem trabalho manual em nenhuma plataforma.

Mantendo design e código sincronizados

A sincronização contínua é o objetivo final. Para isso, automatize o máximo possível:

  • GitHub Action / CI: configure uma action que, quando o arquivo de tokens é atualizado no repositório (via Tokens Studio push), executa o Style Dictionary e abre um PR com as mudanças no código;
  • Changelog de tokens: o diff do arquivo JSON no Git mostra exatamente quais tokens mudaram — é o changelog automático do seu design system;
  • Semver nos tokens: trate o arquivo de tokens como um pacote com versionamento semântico. Adicionar um token = patch. Renomear um token existente = major (breaking change).

Exemplo de uso real

Um design system de um banco digital tem tokens para light mode e dark mode. O pipeline funciona assim:

  1. O designer atualiza a cor color.primary.600 de #6C4CF1 para #5A3CE0 no Figma (feedback da equipe de acessibilidade: contraste maior);
  2. Usando o Tokens Studio, faz push do tokens.json atualizado para o repositório GitHub;
  3. Uma GitHub Action detecta a mudança, executa o Style Dictionary e abre um PR com --color-primary-600: #5A3CE0 no CSS, colorPrimary600 = UIColor(red:0.35...) no Swift, e o valor equivalente no Kotlin;
  4. O tech lead revisa o PR em 5 minutos — é apenas uma mudança de valor de cor — e faz o merge;
  5. O pipeline de deploy atualiza automaticamente o web, o app iOS e o app Android;
  6. Total de tempo do designer ao prod: ~15 minutos. Sem e-mails, sem planilha de "cores para atualizar".
Comece simples, escale conforme necessário

Você não precisa implantar o pipeline completo no dia 1. Comece com: Variables no Figma + exportação manual via REST API + CSS Custom Properties no projeto. Conforme o time crescer e a frequência de mudanças aumentar, adicione Tokens Studio, Style Dictionary e a automação CI/CD progressivamente.

Resumo

  • Design tokens são pares nome–valor que unificam decisões de design entre Figma e código. Variables do Figma são tokens nativas.
  • A hierarquia recomendada é primitivos → semânticos → componente — troque temas apenas nos semânticos.
  • A REST API do Figma expõe Variables em JSON; o Tokens Studio oferece exportação e sincronização com Git mais amigáveis.
  • O formato W3C Design Tokens é a especificação portável que todas as ferramentas modernas estão adotando.
  • O Style Dictionary transforma um JSON de tokens em CSS, Swift, Kotlin e outros formatos simultaneamente.
  • O pipeline completo é: Figma → JSON (Git) → Style Dictionary (CI/CD) → pacotes de plataforma → uso no código.
✍️ Exercício

Pipeline básico de tokens

Monte um pipeline simplificado de design tokens:

  1. No Figma, crie uma coleção de Variables chamada "Colors" com pelo menos 5 tokens de cor (primitivos) e 3 tokens semânticos que referenciam os primitivos.
  2. Use a REST API (com seu token pessoal do Figma) para fazer um GET no endpoint de variables e salve o JSON de resposta.
  3. Instale o Tokens Studio no Figma e importe as suas Variables. Exporte como JSON no formato W3C Design Tokens.
  4. Instale o Style Dictionary (npm install -g style-dictionary) e configure-o para transformar o JSON em CSS Custom Properties e um arquivo JavaScript.
  5. Abra o CSS gerado e verifique que os tokens aparecem como --color-* variables.
Critério de sucesso: você tem um arquivo variables.css gerado automaticamente pelo Style Dictionary com as cores que você criou no Figma — mudando o valor no Figma, exportando pelo Tokens Studio e executando o Style Dictionary novamente, o CSS atualiza com os novos valores.
🏆 Desafio

Pipeline automatizado com GitHub Actions

Implemente o pipeline completo com automação: configure o Tokens Studio para sincronizar com um repositório GitHub (branch tokens). Configure uma GitHub Action que, ao detectar mudança no tokens.json, executa o Style Dictionary e abre um PR automático com as atualizações de CSS e JavaScript para a branch main. O PR deve incluir no título qual token foi alterado (extraído do diff do JSON). Documente o processo num arquivo README do repositório. Ao final, teste o pipeline completo: mude uma cor no Figma, faça push pelo Tokens Studio e verifique que o PR aparece no GitHub em menos de 2 minutos.

QuizTeste seu conhecimento

1. Qual é a diferença entre tokens primitivos e tokens semânticos?

  • Primitivos são usados diretamente em componentes; semânticos são apenas para documentação
  • Primitivos definem todos os valores brutos possíveis; semânticos criam significado contextual referenciando primitivos — e são usados em componentes
  • Primitivos só existem no Figma; semânticos só existem no código
  • Não há diferença prática — são apenas duas formas de nomear a mesma coisa
Primitivos são a paleta completa — todos os valores existentes. Semânticos atribuem significado: color.action = {color.blue.500}. Os componentes consomem semânticos, não primitivos. Para trocar o tema dark, você só modifica os semânticos — os primitivos ficam intactos.

2. O que o Style Dictionary faz no pipeline de design tokens?

  • Cria e gerencia tokens diretamente no Figma via plugin
  • Sincroniza automaticamente o Figma com repositórios Git
  • Transforma um arquivo JSON de tokens em código para múltiplas plataformas (CSS, Swift, Kotlin, JS) simultaneamente
  • Valida os tokens do Figma contra o formato W3C Design Tokens
O Style Dictionary pega um JSON de tokens como input e gera CSS Custom Properties, variáveis Swift, recursos Android XML, objetos JavaScript e outros formatos de saída — todos a partir de uma única fonte de verdade.

3. Por que o formato W3C Design Tokens é importante?

  • É uma especificação padronizada e portável — tokens em W3C Format podem ser lidos por qualquer ferramenta que implemente o spec, sem lock-in de fornecedor
  • É o único formato que o Figma exporta nativamente via REST API
  • Garante que os tokens funcionem automaticamente em todos os browsers sem build step
  • É obrigatório para publicar componentes na npm
O W3C Design Tokens Format resolve o problema de portabilidade: antes, cada ferramenta usava seu JSON proprietário. Com a especificação W3C, um arquivo de tokens é portável entre ferramentas (Figma, Penpot, Tokens Studio, Style Dictionary) sem reescrita — eliminando o lock-in de fornecedor.
